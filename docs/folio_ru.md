# FOLIO — заметки о коллекции

Рабочие заметки по написанному экспертами бенчмарку логики первого порядка,
планируется как **гейт L2** `docs/reasoning_roadmap_ru.md`. Английский оригинал:
`docs/folio.md`. Смежное: `docs/reasoning_roadmap_ru.md`, `docs/prontoqa_ru.md`,
`docs/task_ru.md` §3.8.

Источник: Han et al., *FOLIO: Natural Language Reasoning with First-Order Logic*
(arXiv:2209.00840, v3 2024). Данные: `github.com/Yale-LILY/FOLIO` (MIT);
текущий релиз — HF `yale-nlp/FOLIO`; `data/v0.0` в репозитории. Закоммиченной
выборки пока нет.

## 1. Что это за бенчмарк

Написанный экспертами open-domain корпус задач рассуждения на естественном языке
с аннотациями логики первого порядка (FOL). Каждая задача — **история**: набор
NL-посылок и набор NL-заключений, каждому заключению присвоена метка `True`,
`False` или `Unknown`. Каждая посылка и заключение несут параллельную
FOL-формулу, а метки проверяются машинно — FOL-инференс-движок удостоверяет, что
заключение `True`/`False` следует из посылок (или противоречит им).

- 1 430 заключений (аннотация) / 1 435 (Таблица 3) при **487 наборах посылок**;
- сплит 70/15/15 = 1 001 / 203 / 226 по **истории**;
- словарь 4 351 слово; глубина рассуждения 0–7 (мода 4); 28.7% требуют ≥5 шагов;
- трёхзначная метка с **открытым миром** `Unknown` (мажоритарный класс 38.5%).

Всё нужное для метки лежит **внутри посылок**: на этапе выравнивания аннотаторы
добавляют недостающее общее знание и «внутренние свойства» предикатов (например,
`LocatedIn` транзитивен, `BeFamily` симметричен) как явные дополнительные
посылки. Корпус, таким образом, самодостаточен, что совпадает с допущением
Ankyra о единичной задаче (`docs/task_ru.md` §1).

Два метода построения, отражаются в поле `source`:

- **WikiLogic** — с нуля, по случайным страницам Wikipedia; 304 истории,
  1 353 посылки, 753 заключения; глубина 1–5; 51 различное AST; более
  разнообразные структуры на уровне предложений и логики.
- **HybLogic** — гибрид: шаблоны, собранные сцеплением валидных силлогизмов
  (заключение одного становится посылкой следующего), затем инстанциированные в
  NL аннотаторами; 183 истории, 1 054 посылки, 682 заключения; глубина 5–8;
  25 AST; проще логика предложений, но длиннее цепочки.

Базовые результаты (test): мажоритарный 38.5%, GPT-4 few-shot 64.2%,
Logic-LM 78.1%.

## 2. Поля записи

| Поле | Значение |
|---|---|
| `premises` | NL-посылки (список) |
| `premises-FOL` | параллельные FOL-формулы посылок |
| `conclusion` | NL-заключение |
| `conclusion-FOL` | параллельная FOL-формула заключения |
| `label` | `True` / `False` / `Unknown` |
| `story-id` | id истории (посылки общие для заключений) |
| `example-id` | id на заключение |
| `source` | `WikiLogic` или `HybLogic` |

## 3. Оси

- **source** — WikiLogic (разнообразнее, короче) vs HybLogic (шаблоннее, длиннее);
- **глубина рассуждения** — 0–7 дедуктивных шагов (мода 4; ≥5 у 28.7%);
- **метка** — True / False / Unknown (открытый мир);
- **логический инвентарь** — см. §4.

## 4. Логический инвентарь → этап движка

Корпус — **не** единый фрагмент. Стратифицируй каждый пример по конструкциям,
которые реально использует его FOL-аннотация:

| Конструкция FOL | Пример | Этап Ankyra |
|---|---|---|
| атомарный ground-факт | `WildTurkey(tom)` | L0 |
| универсальная импликация | `∀x(WildTurkey(x) → …)` | L0 |
| конъюнкция в теле правила | `… ∧ …` | L0 |
| явное отрицание | `¬EasternWildTurkey(tom)` | **L1** |
| дизъюнкция | `A(x) ∨ B(x) ∨ …` | **L2** |
| квантор существования | `∃x(…)` | **L2** |
| функция / вложенный терм | `f(x, y)` | решение о фрагменте (за пределами заявленного L2) |
| равенство | `x = y` | решение о фрагменте (за пределами заявленного L2) |
| схема аксиом | транзитивность `LocatedIn`, симметрия `BeFamily` | решение о фрагменте (явные аксиомы) |

Замечания:

- Большинству меток `True`/`False` нужны **отрицание и/или дизъюнкция**, поэтому
  чисто definite-Horn (L0) подмножество мало. FOLIO — гейт и L1, **и** L2, а не
  только L2; L0-срез — лёгкая базовая линия.
- **Сколемизация — не фича извлечения.** Устранение существования — сколем-
  функция/константа для посылки, witness-константа для цели — это шаг
  клаузальной нормализации внутри решающей процедуры, а не то, что выдаёт Фаза 0.
  Фазе 0 нужно лишь *зафиксировать* структуру кванторов (какая переменная, какая
  область действия); сколемизирует прувер.
- Ground truth меток сам получен FOL-инференс-движком (Приложение G статьи,
  прувер класса Prover9). L2 может переиспользовать резолюционный прувер как свою
  решающую процедуру, а не писать свой; референсная процедура уже существует.
- Выводимость в FOL лишь **полуразрешима**: `proven` распознаётся, опровержение —
  нет. L2 должен вести **ограниченный** клаузальный поиск и честно сообщать
  `insufficient` / исчерпание бюджета (риск L2 в `docs/reasoning_roadmap_ru.md`).

## 5. Отношение к Ankyra

- **In-fragment подмножество.** Примеры, чей FOL использует только атомы,
  универсальные импликации, конъюнкцию, отрицание и дизъюнкцию (без функций,
  равенства и схем), — цель L1+L2. `HybLogic` шаблонный и проще на уровне
  предложения, поэтому это более предсказуемый in-fragment срез; `WikiLogic`
  разнообразнее и нагружает извлечение.
- **Out-of-fragment подмножество.** Функции, равенство и схемы аксиом выходят за
  «positive FOL», который обязуется покрыть roadmap; такие примеры помечаются
  `out_of_fragment` и не являются провалом гейта. Их закрытие — решение о
  фрагменте, а не исправление бага.
- **`Unknown` — дефолт открытого мира.** Корректный `Unknown` нельзя
  производить закрытием мира: `ANKYRA_NEGATION_MODE` (L1) задаётся бенчмарком, а
  не угадывается (то же правило, что у ProntoQA, `docs/prontoqa_ru.md` §6).
- **Схемы аксиом.** Транзитивность/симметрия в общем случае не присутствуют в
  сыром тексте как предложения; для NL-задачи их должен предложить LLM. Это
  гипотезы, если бенчмарк не подаёт FOL-аннотацию — конкретный случай границы
  propose/decide, фиксируется в реестре гипотез.

## 6. Как харнесс будет это использовать

- `problem_text` = `premises` + `conclusion` как целевое утверждение, как у
  ProofWriter/ProntoQA.
- Цель polarity-aware: `True` → выводимо, `False` → опровергнуто, `Unknown` →
  ни то, ни другое (честный `unsupported`/`insufficient`).
- Стратификация по FOL-аннотации (§4) для разделения `in_fragment` и
  `out_of_fragment`; против гейта оценивается только in-fragment подмножество.
- Бенчмарк можно также прогонять в **FOL-fed** режиме (подать `premises-FOL` /
  `conclusion-FOL` напрямую), чтобы отделить ошибку извлечения от ошибки движка;
  это диагностика, а не продуктовый путь.
- Гейты и гигиена стоимости — по `docs/proofwriter_ru.md` §6–7: маленькая
  закоммиченная выборка, `ANKYRA_EXTRACT_SAMPLES=1`, один прогон, повтор только
  при расхождении.

## 7. Риски

- **Расползание фрагмента.** Полная FOL неразрешима; обещание «решать FOLIO»
  сломало бы гарантию `proven`. Фрагмент должен быть явным, а бюджет — честным.
- **Извлечение — самое трудное.** Неверный FOL-перевод даёт уверенно неверную
  метку; адаптер должен сообщать об ошибках кодирования, а не угадывать.
- **Соблазн хардкода.** Транзитивность/симметрия и фиксированные шаблоны
  силлогизмов провоцируют вшитую онтологию, запрещено `docs/task_ru.md` §3.8.
- **Стоимость.** 226 тестовых примеров с длинными наборами посылок;
  `ANKYRA_EXTRACT_SAMPLES=1` и маленькая закоммиченная выборка обязательны.

## 8. Тест-план

0. **Recon (без LLM).** Разобрать закоммиченные FOL-аннотации и посчитать
   распределение конструкций (§4), чтобы точно оценить размеры in-fragment /
   out-of-fragment подмножеств.
1. **Builder** `evals/build_folio_sample.py` — детерминированный, стратифицирован
   по source × глубина × конструкция, закоммичен как `evals/data/folio_tier_*.jsonl`
   (зеркало `evals.build_proofwriter_sample`).
2. **Adapter** `evals/folio.py` — `load_sample` / `problem_text` /
   `score_record` / `_to_problem`, `--tier/--ids/--limit`, трассы в
   `evals/out/folio/`, тот же отчёт гейта.
3. **Гейт:** 0 grounded false proofs, каждый детерминированный in-fragment ответ
   `proven`, точность по kind ≥ 95% (порог L2 roadmap); `out_of_fragment`
   считается, но не проваливается; каждый оставшийся провал категоризован.

## 9. Статус

**Подмножество отрицаний реализовано (offline).** Рекон по validation v0.0
(единственный сплит на GitHub с `conclusion-FOL`): 204 примера, из них **13 остаются
во фрагменте L1-отрицания** (явное отрицание, универсальная импликация, конъюнкция,
атомарные факты и **ground**-заключение; без дизъюнкции/∃/равенства/XOR/↔/
многопеременной квантификации). `evals.build_folio_sample` коммитит их как
`evals/data/folio_negation_tier_a.jsonl`, а `evals.folio` — полярно-осознанный
адаптер (метка `True/False/Uncertain` → yes/no/unknown, открытый мир).

**Живые прогоны.** Сэмпл из 23 до фильтра: 9/23. Отфильтрованный из 13: **7/13**
(все 4 `Uncertain` верны; `grounded_mismatch` больше нет). Два дефекта, найденных
здесь, исправлены:

- `grounded_mismatch` оказался не извлечением, а **дырой классификации**: LLM
  сослался на целое условие (`"If 1984 is a streaming service, then …"`), чтобы
  утвердить `is_a(1984, streaming_service)`, а guard условной цитаты пропустил это
  из-за завершающей точки (находка B13 в `docs/quality_findings_ru.md`). Исправлено;
  пример теперь `unknown`.
- `Plungers suck.` формализовалось как факт-константа `suck(plunger)` вместо правила
  `is_a(?x,plunger) → suck(?x)`; промпт извлечения теперь квантифицирует bare plural,
  и пример верен.

Остальные расхождения — `undecided_mismatch` (gold-формализация тоже не проходит в
открытом мире — сводится к L2), а не извлечение.

Все метки `Uncertain` корректно остались unknown. Дыр звуковости движка больше не
наблюдалось.

**Gold-fed диагностика (решающая).** `evals.analyze_folio` парсит аннотированный FOL
напрямую (`evals.folio_fol`, FOL-fed режим из §6) и разделяет **фрагмент** и
**извлечение**: если gold-формализация уже не решается, пробел в логике, а не в
извлечении. На сэмпле из 13:

| источник вердикта | верно |
|---|---|
| text-fed (LLM-извлечение) | 7/13 |
| gold-fed, открытый мир | 7/13 |
| gold-fed, закрытый мир | 8/13 |

Категории: **ok 6** (4 `Uncertain` + 2 ground-факта), **semantics/reductio 5**
(gold-fed проходит только в закрытом мире), **fragment 1**, **extraction 1**
(дрейф предиката на стадии вопроса, вариативность провайдера). То есть низкий
результат определяется границей фрагмента, а не извлечением: большинство метк `False`
и отрицаемые `True` требуют **reductio/контрапозиции** (L2) или шага закрытого мира,
а `Uncertain` требует **открытого** мира — ни одно допущение о мире не подходит сразу.
text-fed теперь совпадает с gold-fed (оба 7/13), т.е. оставшийся разрыв — в логике, а
не в извлекателе.

Вывод: L1-срез FOLIO реально крошечный и всё равно требует L2; FOLIO — корректно
**гейт L2**, а не L1. Больший выход требует L2 (reductio) и/или gated HF v2 (полный FOL
для train). Функциональные термы в v0.0 отдельно не детектируются (нет чистого поля);
документированное ограничение фрагмента. См. `docs/reasoning_roadmap_ru.md` L2 и
`docs/l1_plan_ru.md`.

\begin{abstract}
We present Ankyra, a domain-general neuro-symbolic reasoning system built on a strict
separation of roles: the language model \emph{proposes} a formalization, and a deterministic
symbolic engine \emph{decides} it. The system spans a family of decidable formalisms ---
from definite Horn clauses and stratified negation to positive first-order logic with
disjunction and quantifiers, finite-domain constraints, exact arithmetic, and defeasible
defaults with specificity. Each formalism comes with a sound decision procedure and a
declared fragment. Every answer carries a machine-checkable proof trace, and no statement
enters the theory without either a verbatim quotation or an explicit hypothesis tag. We
report a demonstration-scale evaluation on standard collections: on covered slices the
system achieves high accuracy while producing no confidently wrong conclusions, and it
abstains honestly (\texttt{out\_of\_fragment}) where the implemented logic cannot express
the problem. We also compare against two open-source neuro-symbolic systems --- Logic-LM and
LINC --- on identical inputs and the same model, and show that under a small, inexpensive
model the binding constraint is the translation interface rather than the reasoning. We make
no claim to state-of-the-art performance: the evaluation uses fixed subsamples rather than
full test sets, and we state the statistical and methodological limitations explicitly.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Large language models read text well and translate it into a precise formal language. They
do poorly what symbolic procedures do well: they derive consequences \emph{soundly}, track
exactly which premises were used, and refuse to guess. A free chain of thought sounds
plausible, but it does not distinguish a correct step from a merely convincing one: it
carries neither a certificate of soundness nor a history from which one could reconstruct
what the answer rests on. Verifiability is therefore the central problem of reasoning with
language models.

Ankyra~\cite{ankyra} gives each side the work it is good at. The language model reads the
text and does two things: it decomposes the problem into \emph{structure} (objects, facts,
rules, quotations), and, while the answer is still open, it proposes individual steps. The
symbolic engine handles the \emph{formal} side: it turns the structure into a theory, closes
it under inference rules, matches it against the question, and certifies what actually
follows.

The central design principle is short: \emph{the language model proposes, the engine
decides}. The model never owns truth. Every statement it produces is deterministically
classified as \texttt{derivable}, \texttt{cited} (supported by a verbatim quotation),
\texttt{hypothesis} (knowledge absent from the text, tagged), or \texttt{rejected}. The
strength of an answer never exceeds the strength of its premises: a derivation from
quotations is \texttt{proven}; a derivation resting on assumptions is
\texttt{proven\_under(H)}.

This separation is not an engineering compromise. It reflects the distinction between an
\emph{unformalizable source} (doxa) and formal \emph{logos}: the language model here is the
bearer of doxa, which logos consults for proposals but never for truth, and the proposal
protocol, deterministic classification, journal, and text-grounding checks form the
interface between them~\cite{doxa}. A full account of the operator family is the subject of
a separate paper; here we focus on the system that implements it and on its empirical
evaluation.

\paragraph{Contributions.}
\begin{itemize}
\item A propose/decide architecture with two separated participants and a machine-checkable
proof trace.
\item A proposal protocol in which every statement is classified deterministically, and the
strength of an answer (\texttt{proven}, \texttt{proven\_under(H)}, \texttt{not\_proven})
never exceeds the strength of its premises.
\item A family of decidable formalisms under a \emph{declared-fragment protocol}, with
honest abstention \texttt{out\_of\_fragment} instead of a silent downgrade to a weaker
logic.
\item A staged-evaluation methodology for \emph{composite} benchmarks that separates the
coverage ceiling (formalism) from the extraction ceiling (model) via a gold-fed mode.
\item A common-input comparison with two open-source translator-plus-solver systems on the
same rows and the same model, which separates the translation interface from the symbolic
reasoning and quantifies the model-regime effect.
\item A demonstration prototype on standard collections with a measurable soundness
invariant: no confidently wrong conclusions.
\end{itemize}

\paragraph{Scope (explicit).} This is a report on a demonstration prototype, not a claim to
state-of-the-art performance. We evaluate \emph{fixed subsamples} of standard collections,
explain the budget that prevents full test-set runs, and report confidence intervals. Full
coverage of a collection is unattainable by construction for sets with mixed constructions,
such as FOLIO (Section~\ref{sec:results}).

\paragraph{Structure.} Section~\ref{sec:system} describes the architecture and the proposal
protocol; Section~\ref{sec:example} gives worked examples per stage;
Section~\ref{sec:formalisms} lists the formalisms and decision procedures;
Section~\ref{sec:method} presents the evaluation methodology; Section~\ref{sec:results}
reports results; Section~\ref{sec:comparison} compares against Logic-LM and LINC on identical
inputs; Section~\ref{sec:limitations} discusses limitations;
Section~\ref{sec:related} covers related work.

\section{System overview}
\label{sec:system}

Ankyra is not a monolithic solver but a system that coordinates formalizations and decision
procedures. For each problem the model produces a formalization in some logic, and a sound
procedure for that logic decides it. Different classes of problems require different
procedures, each with its own internal representation; the implemented logics are described
in Section~\ref{sec:formalisms}.

\subsection{Four phases}

A problem passes through four phases. Only one of them --- inference --- belongs to the
engine; the other two consult the model.

\begin{itemize}
\item \textbf{Phase 0 --- decomposition.} The text is split into a descriptive part and a
question, and from that point they are treated as separate objects. Two calls to the
language model follow in a fixed order: first, a structural decomposition of the descriptive
part (objects, facts, conditional statements, alternatives and groupings, negations and
modalities, a short verbatim quotation per element); then an expression of the question over
the canonical vocabulary already established by the theory. Between and after these calls, a
deterministic builder unrolls and enriches the structure into a \emph{theory} and a
\emph{query}. A strict rule applies: \emph{the question is never asserted as a fact}.
\item \textbf{Phase 1 --- decide.} The symbolic engine derives all consequences of the
theory to a fixed point and checks whether the goal follows. Every derived fact carries a
history: which facts and which rule produced it. The engine adds no knowledge of its own: it
is sound and complete \emph{relative to} the formalization it receives.
\item \textbf{Phase 2 --- guided cycle.} If the constructed theory does not yet settle the
question, the system does not stop at a bare ``unknown'': it reports exactly where the
difficulty lies, and the model gets a bounded opportunity to help by proposing one step per
iteration (Section~\ref{sec:cycle}).
\item \textbf{Phase 3 --- explanation.} The finished proof trace is assembled
\emph{automatically} from the proof history, not by the model. The model may later
paraphrase the finished trace in prose, but it may not introduce new facts.
\end{itemize}

The key boundary runs between Phases 0 and 1: everything the model formulates must either
rest on a verbatim quotation or be explicitly tagged as an assumption. Nothing enters the
theory without such grounding.

\subsection{The proposal protocol}

Every statement the model wishes to add is classified deterministically. The classification
is not a subjective judgment: it depends only on whether the statement already follows, is
grounded in the text, or is an assumption.

\begin{center}
\begin{tabular}{p{2.4cm}p{6.2cm}p{4.6cm}}
\toprule
\textbf{Category} & \textbf{Condition} & \textbf{Engine action} \\
\midrule
\texttt{derivable} & already follows from the current theory & accepted as narration only \\
\texttt{cited} & new statement with a verbatim quotation from the text & added to the axioms \\
\texttt{hypothesis} & knowledge absent from the text & recorded in the journal, tagged $H$ \\
\texttt{rejected} & fails a schema, safety, or quotation check & dropped with a reason code \\
\bottomrule
\end{tabular}
\end{center}

It is the distinction between \texttt{cited} and \texttt{hypothesis} that makes answers
honest. A derivation using only quoted facts is \texttt{proven}. A derivation resting on
assumptions is \texttt{proven\_under(H)}, and the answer names those assumptions. If nothing
is established, the answer is \texttt{not\_proven}. The strength of an answer therefore
never exceeds the strength of its premises, and an assumption cannot pass itself off as a
fact.

\subsection{The guided cycle and the journal}
\label{sec:cycle}

The inner cycle (Phase 2) is fully deterministic; the only call to the model is a
\emph{proposal}. The cycle alternates a hint, a free proposal, and a deterministic
classification, and accepts at most one proposal per iteration --- so each iteration leaves
a checkable trace. An iteration proceeds as follows:

\begin{enumerate}
\item \textbf{Verify.} The engine closes the current theory and checks the goal, producing a
verdict and structured gaps (for example \texttt{target\_unmatched:} when the goal predicate
appears nowhere).
\item \textbf{Termination check.} If the verdict is already decisive --- \texttt{supported},
\texttt{refuted}, \texttt{contradiction}, or \texttt{insufficient} --- the cycle stops.
\item \textbf{Hint.} The model receives the problem structure, the admissible predicates and
objects of the theory, a summary of what has been derived, the current gaps, the goal, and
the kinds of proposals allowed.
\item \textbf{Proposal.} The model returns a short narrative and exactly one typed proposal:
reformulate the question in the theory's vocabulary, add a rule, assert a quoted fact, or
select the next subgoal.
\item \textbf{Classification and application.} The engine checks the proposal against the
schema, safety rules, and the text, assigns it to one of the four categories above, and
either applies or drops it. Application is monotone: the theory only grows.
\item \textbf{Record.} The iteration is written to the journal, and the inner cycle
restarts.
\end{enumerate}

The cycle stops on a decisive verdict, on \texttt{no\_progress} (two consecutive iterations
without change), on exhausting the iteration budget, or when assumptions are disallowed.
None of these outcomes is a correctness violation: each is an honest stopping point.

\emph{Monotone base, moving answer.} The \emph{base} --- axioms, rules, hypotheses --- only
grows: premises are never deleted, the goal is never weakened. The \emph{answer}, however,
may change as new information arrives. Such changes are not hidden: each is recorded as a
\texttt{Revision} with the source iteration and the assumptions involved, and the revisions
are kept alongside the explanation. The system thus remains checkable under non-monotonic
reasoning without ever changing its base.

\subsection{Data model}

Everything the system reasons about is assembled from a few simple elements. An
\emph{object} (\texttt{Object}) is a canonical named entity. A \emph{relation}
(\texttt{Morphism}) is a single predicate applied to a subject and an object, with a
modality and a negation flag; negation is the same predicate marked false, not a separate
name. A \emph{rule} (\texttt{Rule}) is a conditional statement: a conjunction of conditions
entails a consequence, marked as an implication or an exception and carrying a source (a
quotation or a hypothesis identifier). A \emph{theory} (\texttt{Theory}) collects objects,
asserted relations, and rules, while a \emph{query} (\texttt{Query}) stores the conditions
the question asserts ($\Gamma$), the goal ($\phi$), and the answer type. Inside the engine,
a \emph{fact} (\texttt{Fact}) is the ground atom together with its proof history.

\subsection{A principled limitation: deterministic code does not parse language}

Deterministic code never interprets natural language. Normalizing identifiers and closed
enumerations that the model has \emph{already} extracted (predicate and object identifiers,
modality, \texttt{relation\_kind}, field keys) is permitted: it operates on the structured
result, not on the source text. Heuristics over the source text that rely on words,
morphology, characteristic phrases, or hand-made term lists are not permitted: they do not
generalize across domains, and semantics are set by the extraction instruction. The only
operations over the source text are structural checks: exact quotation occurrence, coverage,
and length.

\section{Worked examples per stage}
\label{sec:example}

We give examples for each stage --- from pure deduction and abduction through defaults,
negation, disjunction, a composite FOLIO case, finite-domain constraints, and exact
arithmetic. They show how the proposal protocol, answer strength, and choice of decision
procedure work on concrete inputs.

\subsection{Pure deduction}

Text: \emph{``It is raining. If it is raining, the ground is wet. Is the ground wet?''}

Phase 0 splits the text into a descriptive part and a question. The descriptive part yields
one fact and one rule; the question becomes the goal:

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Element} & \textbf{Content} & \textbf{Source} \\
\midrule
Fact & \texttt{raining()} & \texttt{cited} (``It is raining.'') \\
Rule $R_1$ & \texttt{raining()} $\Rightarrow$ \texttt{is\_wet(ground)} & \texttt{cited} (``If it is raining, the ground is wet.'') \\
Goal $\phi$ & \texttt{is\_wet(ground)}, type \texttt{yes\_no} & question (not a fact) \\
\bottomrule
\end{tabular}
\end{center}

Phase 1 closes the theory: rule $R_1$ fires on the fact and derives
\texttt{is\_wet(ground)}, carrying the premise and the firing rule in its history.
Verification gives the verdict \texttt{supported}, the answer \texttt{yes}, and strength
\texttt{proven}; the cycle makes no call to the model. Phase 3 assembles the trace
automatically:

\begin{enumerate}
\item \texttt{raining()} --- axiom, \texttt{cited};
\item \texttt{is\_wet(ground)} --- rule $R_1$, from step 1.
\end{enumerate}

\subsection{Abduction and answer strength}

Text: \emph{``The vehicle has an engine, four wheels, 150 horsepower and four doors. What
kind of vehicle is it?''}

Phase 0 extracts only the observed facts --- \texttt{has\_engine}, \texttt{wheel\_count},
\texttt{power}, \texttt{door\_count}. The text contains no classification rules, so the
theory has none either. The goal is open: \texttt{is\_a($X$, ?c)}. Phase 1 derives nothing
for this predicate and reports the gap \texttt{target\_unmatched: is\_a}, after which the
guided cycle starts.

In the first iteration the model proposes classification rules, for example: ``engine
$\Rightarrow$ motor vehicle'', ``motor vehicle and four wheels $\Rightarrow$ car''. There
are no quotations under them, so the classification tags them as \texttt{hypothesis}, and
the rules are entered in the journal with tags $H_1, H_2, \dots$ (Section~\ref{sec:cycle}).
The theory grows monotonically, closure derives \texttt{is\_a($X$, car)} and
\texttt{is\_a($X$, sedan)}, and the goal variable is bound along the \texttt{is\_a} chain
rather than guessed. Verification gives \texttt{supported}, but the derivation rests on
assumptions, so the answer strength is \texttt{proven\_under($H_1,H_2,\dots$)}, and the
answer names those assumptions.

Running the same problem with \texttt{ANKYRA\_ALLOW\_HYPOTHESES=false} rejects the same
rules, and the system answers honestly \texttt{not\_proven}. The difference between
\texttt{proven} and \texttt{proven\_under} in these two examples is not cosmetic: it
reflects exactly what the answer rests on.

\subsection{Defaults and specificity}

Text: \emph{``Birds can fly. Penguins are birds, but penguins cannot fly. Tweety is a
penguin. Can Tweety fly?''}

Phase 0 gives the facts \texttt{is\_a(tweety, penguin)} and \texttt{is\_a(penguin, bird)},
together with two default rules: \texttt{is\_a(?x, bird)} $\Rightarrow$ \texttt{fly(?x)} and
\texttt{is\_a(?x, penguin)} $\Rightarrow$ \texttt{$\neg$fly(?x)}. Under plain monotone
closure both rules would fire and produce a contradiction. With the defaults layer enabled,
the penguin rule is strictly more specific --- it rests on the edge \texttt{is\_a(penguin,
bird)} --- and wins: the verdict is \texttt{refuted}, the answer is ``no'', and the flag
\texttt{defeasible=true}.

The symmetric example --- ``birds do not fly, penguins fly'' --- gives \texttt{supported}
and the answer ``yes'': specificity does not depend on polarity. In the classic example
``Nixon is a Quaker and a Republican'' with rules \texttt{quaker} $\Rightarrow$
\texttt{pacifist} and \texttt{republican} $\Rightarrow$ \texttt{$\neg$pacifist}, specificity
is undefined --- both rules are equally specific --- and the system honestly answers
\texttt{unsupported} with the gap \texttt{undecided\_conflict}, rather than guessing a
winner. Source: \texttt{evals/defeasible\_synthetic}, 8/8.

\subsection{Negation and disjointness (L1)}

Text: \emph{``No real number is imaginary. $a$ is a real number. Is $a$ imaginary?''}

The statement ``no real number is imaginary'' is formalized not as a general rule but as a
disjointness constraint \texttt{disjoint(real\_number, imaginary)}. Together with the fact
\texttt{is\_a(a, real\_number)}, it yields \texttt{$\neg$is\_a(a, imaginary)} and hence
refutes the goal: verdict \texttt{refuted}, answer ``no''. It is essential that the
refutation rests on an explicit disjointness rather than on a silent closed-world
assumption: under the open world, the system does not declare the goal false merely because
it failed to derive it. Source: \texttt{evals/l1\_synthetic}, identifier
\texttt{disjoint-refute-01}; gate 40/40.

\subsection{Disjunction and case split (L2)}

Theory: fact \texttt{is\_a(rex, prim)}; rule \texttt{is\_a(?x, prim)} $\Rightarrow$
\texttt{is\_a(?x, a)} $\lor$ \texttt{is\_a(?x, b)}; rules \texttt{is\_a(?x, a)}
$\Rightarrow$ \texttt{is\_a(?x, c)} and \texttt{is\_a(?x, b)} $\Rightarrow$
\texttt{is\_a(?x, c)}; goal \texttt{is\_a(rex, c)}. The Horn procedure cannot handle a
disjunctive head, so the clausal L2 procedure is enabled: it splits into cases over the two
disjuncts and derives \texttt{c} in each, after which the verdict is \texttt{supported}.
With L2 disabled, the same input yields an honest \texttt{out\_of\_fragment}, not a silent
downgrade to a weaker logic. Source: \texttt{evals/l2\_synthetic}, identifier
\texttt{head-case-split-01}; gate 65/65.

\subsection{A composite FOLIO case}

The FOLIO gold formalization mixes constructions from several stages, so the collection is
evaluated by intra-fragment slices. In row \texttt{folio-validation-0010} (``wild turkey''),
the premises contain a disjunction of six subspecies and the fact \texttt{WildTurkey(tom)}.
Conditional negations together with this fact yield \texttt{$\neg$Eastern(tom)},
\texttt{$\neg$Osceola(tom)}, and the negation of the Goulds/Merriams/Riogrande disjunction;
the goal \texttt{Eastern(tom)}, labeled \texttt{False}, is therefore refuted. The clausal
procedure gives \texttt{refuted} (``no''), matching the label.

Row \texttt{folio-validation-0027} (``Marvin'') is different: the goal is labeled
\texttt{False}, but the annotated premises entail neither the goal nor its negation, and the
system honestly abstains (\texttt{unknown}) rather than issuing an unconfirmed ``no''. On
the negation slice (13 rows) the gold-fed mode gives 12/13 with zero confidently wrong
conclusions; on the L2 tier-a slice (45 rows) coverage is 44/45 and gold-fed is 42/44.
Sources: \texttt{evals/data/folio\_l2\_tier\_a.jsonl},
\texttt{folio\_negation\_tier\_a.jsonl}.

\subsection{Finite-domain constraints (L3)}

An AR-LSAT problem: five instrumental pieces run on a compact disc in some order; conditions
of order, adjacency, and grouping are given, and the question asks which of the proposed
sequences is admissible. The formalization is finite-domain: a domain of positions $0..4$,
five variables with an \texttt{all\_different} constraint, ordering and composite
constraints. A \texttt{not\_violate} question is checked by enumeration, and ``must be'' and
``could be'' questions are decided as truth in all or at least one admissible placement. On
hand-encoded real games the gold-fed mode gives 27/27, including 5/5 for
\texttt{not\_violate} questions; the live run on the eval split gives 23/30. Sources:
\texttt{evals/data/ar\_lsat\_dev.jsonl}, \texttt{evals/data/ar\_lsat\_gold.jsonl}.

\subsection{Exact arithmetic (L4)}

A GSM8K problem: ``Henry made two stops during a 60-mile trip; the first was after 20 miles,
the second was 15 miles before the end. How many miles did he drive between the stops?''
Phase 0 builds a directed graph of quantities: \texttt{total=60}, \texttt{first=20},
\texttt{before\_end=15}, and the target quantity \texttt{between} is given by an equation.
The linear system is solved in exact rational arithmetic: $60-20-15=25$. An arithmetic error
is impossible here by construction: a wrong number can only be a \emph{modeling} error,
never a counting one. Source: \texttt{evals/data/gsm8k\_gold.jsonl}, identifier
\texttt{gsm8k-gold-0028}; gold-fed 8/8.

\section{Formalisms and decision procedures}
\label{sec:formalisms}

Ankyra is not a ``Horn-clause solver'' but a system that coordinates formalizations. The end
goal is to cover the largest practically important class of reasoning for which a decidable
decision procedure exists: the model produces a formalization in a logic $L$, and a sound
procedure for $L$ decides it. Coverage is therefore measured in named formalisms, not in an
undefined notion of ``reasoning''.

\subsection{The stage protocol}

Each stage is described by the same six items: the \emph{formalism} $L$ and the answer
semantics; the \emph{decision procedure}, sound for $L$ (and, where claimed, complete); the
\emph{engine change}; the \emph{extraction change} --- what Phases 0 and 2 must be able to
express for the model to propose in $L$; the \emph{staged gate on a reference collection}
with a small fixed subsample and hard invariants (no confidently wrong conclusions, every
determinate answer \texttt{proven}, accuracy above threshold, every remainder categorized);
and a \emph{switch}, off by default, so that the semantics of the reference collection does
not leak into the engine.

\begin{center}
\begin{tabular}{p{0.8cm}p{5.6cm}p{5.4cm}}
\toprule
\textbf{Stage} & \textbf{Formalism} & \textbf{Procedure} \\
\midrule
L0 & definite Horn clauses, \texttt{is\_a}, negation as complementary pairs (open world) & semi-naive forward chaining to a fixed point \\
L1 & stratified negation / negation as failure (NAF), declared closed world & stratified closure, disjointness constraints \\
L2 & positive first-order logic: disjunction, $\exists/\forall$, proof by cases & bounded resolution (grounding over a finite domain) \\
L3 & finite-domain constraints (CSP/SAT) & search over finite value domains \\
L4 & arithmetic terms and equations & exact rational evaluation / linear elimination \\
D  & defaults with specificity via \texttt{is\_a} & defeasible layer (specificity over the strict core) \\
\bottomrule
\end{tabular}
\end{center}

L3 and L4 are separate engines within the same system, each with its own internal
representation: finite-domain constraints are not logical derivability but constraint
satisfaction, and an arithmetic problem yields a number, not a consequence.

\subsection{The declared fragment}

Since the procedures differ, the system must decide which one runs --- and do so without
ever guessing. The \emph{declared-fragment protocol} provides the answer. The system
analyzes the \emph{constructed} theory and query and derives the set of required features:
is there a disjunctive head, an existential quantifier, a composite goal, a negation, a
built-in comparison, an equality? This is the \emph{fragment} --- an objective property of
the formalization, not an intention. Separately, a run \emph{declares} its semantics: which
procedures are enabled (\texttt{ANKYRA\_*} switches) and whether the query is read under an
open or closed world. The routing decision combines the two and checks them against each
other.

If the fragment fits within the enabled capabilities, the corresponding procedure is chosen.
If not --- the structure needs a logic that the run did not enable, or a combination the
chosen procedure cannot honor --- the result is the named gap \texttt{out\_of\_fragment},
not a silent downgrade to a weaker procedure.

The extension point is the \texttt{Inference} protocol: the semantics (derivability, verdict
shape, closure against which a proposal is classified) become swappable, while procedure
selection and mechanisms stay in place. There are currently two implementations --- Horn and
clausal; L3 and L4 are plugged in as separate engines.

\subsection{What the engines share}

Every engine is sound \emph{relative to} the formalization it receives, and every engine
abstains honestly instead of guessing. The symbolic components are complete relative to the
formalization (forward chaining reaches a fixed point), but completeness of the
\emph{translation} is not claimed: the model can always miss a premise in the text. The
distinction between a wrong answer and a missing one is therefore preserved throughout.

\section{Evaluation methodology}
\label{sec:method}

\paragraph{Metrics.} For each collection we report \emph{class accuracy} (three-class or
multiple-choice) with Wilson 95\% confidence intervals. The staged gate also requires a
\emph{soundness invariant}: every determinate answer \texttt{proven} and no confidently
wrong conclusions.

\paragraph{Two ceilings.} For a composite reference collection we separate \emph{coverage}
(the share of gold formulas the implemented logic can express and decide; the remainder is
an honest \texttt{out\_of\_fragment}) and \emph{extraction} (the share of covered rows the
language model translates correctly). The \emph{gold-fed mode} feeds the engine annotated
formalizations instead of model-extracted ones, separating the accuracy of the method from
the accuracy of translation.

\paragraph{Budget and reproducibility.} There is no free access to the language model; runs
that call it are paid. Each collection therefore enters as a small fixed subsample, runs
once, and is repeated only on a discrepancy. All checks without a language model (synthetic
sets, gold-fed diagnostics) are reproducible from a single repository.

\paragraph{The evaluation ladder.} Results are obtained on a three-rung ladder. The first
rung is synthetic sets without a language model, directly exercising the semantics of each
formalism, with no extraction and no provider variance: this is the clean engine signal. The
second rung is a surface-simple real collection (for example ProntoQA-OOD for L2), adding
real text on top of clean notation. The third rung is a deliberately extraction-heavy slice
of a real collection (FOLIO). Across the ladder, the gold-fed mode --- feeding the engine
hand-written formulas instead of extracted ones --- separates two distinct ceilings:
\emph{coverage} (how many problems the implemented logic can express at all; going beyond it
is an honest \texttt{out\_of\_fragment}, costing completeness but not soundness) and
\emph{extraction} (how many covered problems the model translates correctly). The separation
shows where improvement must come from --- the engine or the interface.

\section{Results}
\label{sec:results}

We report two results: class accuracy on covered slices and the soundness invariant.
Deterministic checks without a language model come first, followed by live runs on external
collections. On no reported slice is there a single confidently wrong conclusion, and every
determinate answer is tagged \texttt{proven}.

\paragraph{ProofWriter (L0).} This is the base gate for the definite Horn layer. On the

hours) was not run for budget reasons.

\paragraph{ProntoQA (L1) and ProntoQA-OOD (L2).} These are gates on real text over clean
notation. ProntoQA checks explicit negation: tier a is 48/48 and tier b is 160/160, all
answers \texttt{proven}; the one-sided 95\% Clopper--Pearson lower bound on per-problem
accuracy for tier b is 98.1\%. ProntoQA-OOD checks compositional reasoning (disjunction,
case split, quantifiers): tier a is 41/42 (97.6\%), with no confidently wrong conclusion.
After these runs, ProntoQA is considered closed.

\paragraph{FOLIO (L1/L2, composite case).} The FOLIO first-order annotation spans several
formalisms at once, so it is evaluated by intra-fragment slices rather than by a single
score:
\begin{itemize}
\item The negation slice (13 rows) turned out to be \emph{fragment-bound}: on the Horn path,
gold-fed and text-fed modes coincide (7/13), and the remainder is reductio and
contraposition; the slice is therefore scored by the clausal L2 procedure: gold-fed 12/13,
text-fed 11/13, with no confidently wrong conclusion. The four \texttt{Uncertain} answers
remain honest \texttt{unknown}; a global closed world is not applied, since it would wrongly
refute them.
\item The L2 tier-a slice (45 rows): coverage is 44/45 (one broken annotation), i.e.\ the
implemented logic expresses almost the whole slice; on the covered rows, gold-fed gives
42/44 against 29/44 under text-fed.
\end{itemize}
The gap between gold-fed (method) and text-fed (extraction) localizes the remaining cost in
extraction, not in the engine: the coverage ceiling on the fixed 45-row slice is in effect
reached. Across the whole 204-row validation split, the two fixed gates cover 13 + 93 = 106
rows (a lower bound on the expressible share); of the 93 rows of the L2 fragment, only 45
are fixed and run, while 48 are left unrun for budget reasons. The remaining rows --- at
most 98 --- contain constructions outside any implemented stage (exclusive or, equivalence,
multi-variable quantifiers, equality, function terms, axiom schemas) and are reported as
\texttt{out\_of\_fragment}.

\paragraph{AR-LSAT (L3).} Finite-domain constraints are checked by a separate engine. On
hand-encoded real games the gold-fed mode gives 27/27; the live run on the eval split is
23/30 (76.7\%) with no \texttt{grounded\_mismatch}. The seven misses are honest abstentions,
not confidently wrong answers.

\paragraph{GSM8K (L4).} Exact rational arithmetic makes arithmetic errors impossible by
construction; a wrong number here is always a \emph{modeling} error, never a counting one.
Synthetic checks are 37/37, the hand-encoded gold is 8/8, and the live run gives dev 12/12
and eval 38/40. The two wrong rows in the eval split are annotated gold errors: one dataset
error, one ambiguity.

\section{Comparison with Logic-LM and LINC}
\label{sec:comparison}

The formalisms and gates above are this paper's contribution. A natural question is how the
same problems are handled by the two closest open-source neuro-symbolic systems,
Logic-LM~\cite{logiclm} and LINC~\cite{linc}. Both are translator-plus-solver pipelines: a
language model writes a formalization and a symbolic prover decides it. Rather than contrast
them qualitatively (as in Section~\ref{sec:related}), we report a \emph{common-input}
comparison --- the same problem rows and the same language model for all three systems ---
and then analyse what separates them.

\subsection{Protocol}
\label{sec:comparison-protocol}

\paragraph{Inputs and model.} Every system receives the exact Ankyra sample rows and the
same model the engine uses at run time: a small, inexpensive instruction model (DeepSeek V4
Flash) behind an OpenAI-compatible endpoint. The external systems were not reimplemented.
Their own prompt, symbolic back-end and scoring are driven unchanged by a thin adapter;
because both were written against the legacy \texttt{openai<1} client, that client is
redirected to the engine's provider, forced to the engine's model, and configured to
disable the model's explicit thinking trace exactly as the engine does. Temperature-0 calls
are cached, so the runs are reproducible at no further cost.

\paragraph{Decoding.} Each system runs its own protocol, because that is the protocol its
published accuracy refers to. Sampling here means running the language model several times
on the same input to obtain $N$ candidate outputs. It is used to estimate the stability of
the generation and to raise the chance that at least one candidate passes parsing.

\begin{center}
\small
\begin{tabular}{p{1.7cm}p{6.3cm}p{6.5cm}}
\toprule
\textbf{System} & \textbf{Decoding} & \textbf{Why} \\
\midrule
Ankyra & temperature $0.1$, one sample, structured (tool/JSON) extraction & the engine's design; it never samples \\
Logic-LM & temperature $0$, one sample, plus self-refinement & its published pipeline \\
LINC & 8-shot, $10$ samples, temperature $0.8$, majority vote & its published pipeline \\
\bottomrule
\end{tabular}
\end{center}

A matched-decoding ablation (all three greedy, one sample) is given in
Section~\ref{sec:comparison-ablations}, so that the protocol itself is not silently doing
the work.

\paragraph{Metrics.} \emph{Solver accuracy} is the share of rows with a correct answer.
Both a failed program execution and an abstention count as wrong; this is the strictest of
our metrics, and we use it throughout. \emph{Coverage} is the share of rows whose program
executed. \emph{Executable accuracy} is accuracy over the rows where the program actually
ran. \emph{Confidently wrong answers} are executed programs with an incorrect answer: the
external systems commit to such an answer, whereas Ankyra is sound relative to its
formalization and produces no such answers.

\paragraph{Scope.} This is not a reproduction of the two papers. They used GPT-3.5/GPT-4
and their own splits; fixing the rows and the model makes the systems comparable but
changes every absolute number. The object of interest is the \emph{relative} behaviour of
the three pipelines under identical input.

\subsection{The interface is the difference}
\label{sec:comparison-interface}

The three systems require different output from the model. Ankyra extracts into a JSON
schema through tool/function calling, and a deterministic builder turns that structure into
the theory; format compliance is enforced by the API contract, not by the prompt, so the
model only has to get the \emph{content} right. Logic-LM requires a program in a hand-written
grammar (\texttt{Predicates:/Facts:/Rules:/Query:}, \texttt{:::}, \texttt{\$x}) read by a
parser sensitive to syntax. LINC requires a \texttt{TEXT:/FOL:} scaffold and executes the
extracted formulas; the scaffold is simple enough that a few of ten samples usually fit,
which is why its sampling matters so much (Section~\ref{sec:comparison-ablations}). The
central finding is that with a small, inexpensive model the binding constraint is the
\emph{translation interface}, not the reasoning: Ankyra is nearly invariant to the model's
formatting habits, while the free-text pipelines can break easily.

\subsection{Decoding ablations}
\label{sec:comparison-ablations}

\paragraph{LINC: greedy versus native.} On the same rows and tasks, moving LINC to its
native protocol raises FOLIO from $34.5\%$ to $74.1\%$ and ProofWriter tier A from $22.2\%$
to $86.7\%$. LINC's robustness lives substantially in its sampling/majority step; reporting
only the greedy value would be misleading.

\paragraph{Logic-LM: best-of-$N$.} Logic-LM does not sample. As a control, five samples per
row at temperature $0.8$ on ProofWriter tier A yielded \emph{zero} executable programs out
of $225$ (the greedy run produced $6$ of $45$). Higher temperature worsens its grammar
compliance rather than rescuing it, so sampling does not explain the two systems' different
behaviour.

\paragraph{Logic-LM: self-refinement.} Its own refinement, implemented only for
Prover9/FOLIO and z3/AR-LSAT, roughly triples FOLIO coverage ($6.9\%\to55.2\%$), raises
FOLIO solver accuracy from $6.9\%$ to $39.7\%$ and AR-LSAT from $53.3\%$ to $63.3\%$, and
introduces confidently wrong answers on FOLIO ($0\to9$).

\subsection{What is not run, and why}
\label{sec:comparison-notrun}

The comparison is bounded by the code of the systems under evaluation, not by arbitrary
choice. LINC's task registry contains only FOLIO and ProofWriter, so it cannot be run on
ProntoQA, AR-LSAT or GSM8K; Logic-LM has no GSM8K path. Logic-LM's self-refinement exists
only for Prover9 and z3 --- its prompt directory contains
\texttt{self-correct-AR-LSAT.txt} and \texttt{self-correct-FOLIO.txt} and nothing else, and
its executor map lists only those two back-ends --- so there is no self-refinement to run
for its PyKE datasets (ProofWriter, ProntoQA). Per-prover capability was still measured,
deliberately and without the model, by the gold-fed runs above. Stage L4 (arithmetic) and
ProntoQA-OOD have no counterpart in either system and remain out of scope.

\subsection{Caveats}
\label{sec:comparison-caveats}

Ankyra's figures are taken from the committed gates and live traces, but were not re-run on
the same day as the external systems; one ProofWriter tier-A trace is an empty-question
extraction failure (provider variance), so the saved traces show $44/45$ against the
accepted gate $45/45$. LINC tier D is greedy rather than native, so it is a lower bound.
Provider non-determinism is real even at temperature $0$; single runs are reported, as
everywhere in this paper. Finally, the comparison is end-to-end --- prompt, decoding, parser
and solver together --- which is exactly what is needed to see how well a method turns a
small model into a sound answer.

\section{Limitations}
\label{sec:limitations}

\paragraph{Sample size and statistics.} Every number on a real collection rests on a small
sample (N = 13, 30, 40, 42, 44, 300), so the confidence intervals are wide
(Table~\ref{tab:results}); on the small slices they overlap with plausible baselines and do
not support a state-of-the-art claim. Detecting a difference of about five percentage points
at $p\approx0.95$ with power $0.8$ would require on the order of 400 examples per group.

\paragraph{Single runs and non-determinism.} The live path calls a language model whose
provider is non-deterministic even at zero temperature. Runs are performed once (for budget
reasons) and repeated only on a discrepancy, so we do not report a variance estimate and do
not perform significance tests.

\paragraph{Subsamples, not full test sets.} We evaluate fixed subsamples: ProntoQA-OOD tier
a (42 of 5{,}800), AR-LSAT eval (30 of $\sim$230), GSM8K eval (40 of $\sim$1{,}319),
ProofWriter tier D (300 of 6{,}368 theories). Full collections were not run because there is
no free access to the language model and the runs are paid for by the author out of pocket;
this is a deliberate boundary of the study, not a hidden failure.

\paragraph{Soundness is relative to the formalization.} The engine is sound \emph{relative
to} the theory it is handed; the translation from natural language into that theory is done
by the language model. An extraction error can therefore produce an \emph{abstention} or, in
principle, a \texttt{proven} answer about a wrong formalization. We measure the absence of
confidently wrong conclusions (zero on every reported slice) and reduce extraction risks
through verbatim quotation checks, guards against citing conditional statements, guards
against refuting on the basis of hypotheses, and domain-declaration control. This is not an
end-to-end soundness proof relative to the real world.

\paragraph{No single aggregate for a composite collection.} For FOLIO, full coverage of the
collection is unattainable by construction: equality, function terms, exclusive or,
equivalence, multi-variable quantifiers, and axiom schemas lie outside any implemented
stage, and full first-order derivability is only semi-decidable. We therefore report
stratified slices and an explicit \texttt{out\_of\_fragment} counter rather than a
whole-collection score.

\paragraph{Comparison with published results.} Section~\ref{sec:comparison} does run a
common-input comparison, but not against the \emph{published} numbers: published values are
obtained on different collections, splits, protocols, and models, so the reported accuracies
remain not directly comparable across papers. The comparison is with the released systems
re-run on identical inputs and one model; the contribution remains an argument about
soundness, checkability and robustness to the translation model, with accuracy as supporting
evidence.

\paragraph{Model and provider variability.} The numbers are tied to the extraction provider
at run time; a different or updated model will change the text-fed columns. The gold-fed
columns and the synthetic checks do not depend on the model.

\paragraph{Defaults.} Only the synthetic gate is reported; a real
defeasible/natural-language-inference (NLI) collection remains future work.

\section{Related work}
\label{sec:related}

\paragraph{Map of the field.} A 2026 systematic survey~\cite{survey2026} (178 works,
2020--2025) identifies four stable patterns of neuro-symbolic integration: sequential
cascade, symbolic validator, symbolic planner with a neural executor, and differentiable
integration. Ankyra is closest to the sequential cascade with a bounded cycle, but it
differs in two respects: a proposal protocol under which every statement enters the theory
only with a quotation or an assumption tag, and a declared fragment under which a mismatch
between the required and available logic yields an honest \texttt{out\_of\_fragment} rather
than a silent downgrade to a weaker procedure. The same survey notes that meta-cognitive
abilities --- monitoring one's own conclusions, recognizing a lack of knowledge, switching
modes --- appear in only $5\%$ of the works; \texttt{out\_of\_fragment} and
\texttt{proven\_under(H)} can be seen as a contribution to exactly this niche.

The closest system in spirit is \emph{Autonomous Trustworthy Agents} (ATA)~\cite{ata}: it
also pursues determinism and checkability, but achieves them by \emph{removing} the LLM from
the runtime entirely (the LLM builds a knowledge base offline; only the symbolic solver runs
online). Ankyra keeps the LLM in the loop, constraining it through the protocol; the two are
different points on the same spectrum. The same approach to verifying regulatory documents
with an SMT solver is described in~\cite{nsc}.

\paragraph{Language-model reasoning without a certificate.} Chain-of-thought~\cite{cot} and
self-consistency~\cite{selfconsistency} show that step-by-step text generation improves
language-model answers. Such chains, however, are not certified: a step that looks plausible
may be wrong, and the answer carries neither a proof history nor a distinction between
``proven'' and ``plausible''. Ankyra addresses exactly this gap: the model produces the
reasoning, but a symbolic engine checks and certifies derivability.

\paragraph{Language model and symbolic engine.} Translator-plus-solver pipelines
(Logic-LM~\cite{logiclm}, LINC~\cite{linc}) also hand reasoning over to a symbolic solver,
but trust the translation entirely: if the formalization is wrong, so is the conclusion.
Here the boundary is stricter: every statement enters the theory only with a verbatim
quotation or an explicit assumption tag, answer strength is derived from the premises
(\texttt{proven} versus \texttt{proven\_under}), and a mismatch between the required and
available logic yields an honest \texttt{out\_of\_fragment} rather than a hidden downgrade
to a weaker procedure. Section~\ref{sec:comparison} re-runs both systems on identical inputs
and the same model: their provers are sound and capable (gold-fed $81$--$93\%$ on FOLIO),
but as free-text pipelines they are sensitive to a small model's formatting, while the
structured interface of Ankyra is not.

\paragraph{Collections as staged gates.} We use standard collections ---
ProofWriter~\cite{proofwriter}, ProntoQA~\cite{prontoqa} and
ProntoQA-OOD~\cite{prontoqaood}, FOLIO~\cite{folio}, AR-LSAT~\cite{arlsat},
GSM8K~\cite{gsm8k} --- not as a single aggregate score but as staged gates for individual
stages, each with its own semantics. For composite collections (FOLIO) we isolate
intra-fragment slices and separately report \texttt{out\_of\_fragment}; a single score
across a collection with mixed constructions is unattainable by construction.

\paragraph{Non-monotonic reasoning and defaults.} Default logic~\cite{reiter} and
circumscription~\cite{mccarthy} formalize the defeasibility of conclusions; Ankyra
implements a defaults layer with specificity via \texttt{is\_a} and honestly reports an
undecided conflict rather than guessing a winner. The philosophical framing (doxa/logos) and
the operator family of interaction are described in a companion paper~\cite{doxa}; here we
focus on the system that implements this interface.

\paragraph{Proof history and checkability.} The reliance on an automatically assembled proof
history aligns Ankyra with work on checkable proof. The explanation here is a presentation
of the derivation, not a second opinion about it: the model may not add facts to it, and
every step names the rule that fired, the bindings used, and the supporting quotation or
hypothesis.

\section{Conclusion}

We have presented a neuro-symbolic system in which a language model proposes and a
deterministic engine decides, spanning a family of decidable formalisms under a
declared-fragment protocol. The contribution is not an individual solver but an architecture
and a discipline: a proposal protocol in which no statement enters the theory without a
quotation or an assumption tag; answer strength that never exceeds the strength of its
premises; a declared fragment and honest \texttt{out\_of\_fragment} instead of a silent
downgrade to a weaker logic; and a staged-evaluation methodology for composite collections
that separates the method's coverage from the extraction ceiling.

On fixed slices of standard collections the system achieves high accuracy without a single
confidently wrong conclusion, and honestly abstains where its logic cannot express the
problem. A common-input comparison with Logic-LM and LINC shows that their symbolic reasoning
is sound but their free-text translation interface is the wall under a small model, whereas
Ankyra's structured extraction is robust to it; with a stronger model and its native
sampling, LINC is competitive. The evaluation is a demonstration prototype, not state of the
art; the limitations above define the boundary of what these results support. Natural
directions for further work are a real defeasible/NLI collection, finite function terms and
multi-variable quantifiers (currently outside the fragment), and runs on full collections as
budget becomes available.

\section{Reproduction}
\label{app:repro}

Checks without a language model (synthetic sets and gold-fed diagnostics) are reproducible
from the repository without access to the language model and without API payment:

\begin{verbatim}
uv run python -m evals.routing_synthetic
uv run python -m evals.l1_synthetic
uv run python -m evals.l2_synthetic
uv run python -m evals.l3_synthetic
uv run python -m evals.l4_synthetic
uv run python -m evals.defeasible_synthetic
uv run python -m evals.ar_lsat --gold evals/data/ar_lsat_gold.jsonl
uv run python -m evals.gsm8k --gold evals/data/gsm8k_gold.jsonl
uv run python -m evals.analyze_folio
\end{verbatim}

Runs that call the language model (to the paid extraction provider) are performed once and
repeated only on a discrepancy:

\begin{verbatim}
uv run python -m evals.proofwriter --tier d
uv run python -m evals.prontoqa --tier b
uv run python -m evals.prontoqa_ood --tier a
uv run python -m evals.ar_lsat --sample eval --live
uv run python -m evals.gsm8k --sample eval --live
\end{verbatim}

The common-input comparison of Section~\ref{sec:comparison} is reproducible from the
repository: adapters and drivers live in \texttt{comparison/} and the per-row outputs in
\texttt{comparison/results/}. The offline parts (adapters, gold-fed back-end checks) need no
API; the live parts are the paid runs recorded there.

\begin{verbatim}
PYTHONPATH=$PWD /tmp/opencode/cmp/llm-venv/bin/python -m comparison.run_logicllm \
    --repo /tmp/opencode/cmp/logicllm --action prepare
PYTHONPATH=$PWD /tmp/opencode/cmp/llm-venv/bin/python -m comparison.run_logicllm \
    --repo /tmp/opencode/cmp/logicllm --action all --collection folio_tier_a
PYTHONPATH=$PWD /tmp/opencode/cmp/linc-venv/bin/python -m comparison.run_linc \
    --repo /tmp/opencode/cmp/linc --collection folio_tier_a --nshot 8 \
    --n-samples 10 --temperature 0.8 --jobs 6
\end{verbatim}

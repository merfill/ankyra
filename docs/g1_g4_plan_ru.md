# План G1–G4 — обобщение извлечения на FOLIO L2 (Фаза 1)

Статус: **завершён.** Фаза 1 из `docs/folio_extension_plan.md` (обобщение извлечения,
G1–G4), идущая после завершённого понижения Tier-1 (`docs/coverage_ceiling.md`
§6–§7). Итог: text-fed **29–31/45** по трём живым гейтам (лучший 31; сохранённый
базис 25/45, исходный живой 26/45), **0 grounded false proofs**, охват gold-fed без
изменений — 42/45. Что легло: измерительная обвязка Шага 0 + триаж (§13); формулировка
извлечения G1–G3 (§14–§15); ground-CNF форма цели T4 и guard `ask_universal` (`G-D6`,

(§22) показывает, что более сильная модель не сдвигает стену. Решения `G-D1`…`G-D6`
зафиксированы в §5 и §19.

Канонический язык: английский; русское зеркало: `docs/g1_g4_plan_ru.md`,

## 1. Цель

Сдвинуть **потолок извлечения** на FOLIO L2: заставить LLM предлагать формулы,
которые коммутируемый клаузальный фрагмент (`ANKYRA_LOGIC`) уже умеет решать, чтобы
точность text-fed приблизилась к границе gold-fed. Конкретно: сохранять все посылки
(G2), выражать универсальные/условные/`¬∃` выводы как цели, а не ground-атомы (G3),
выдавать генерические дизъюнкции в head-only форме, которую движок поддерживает (G1),
и перестать терять строки на масштабе сатурации (G4).

Согласно `D-FE-2` извлечение идёт после метода: gold-fed диагностика показала, что
более глубокий предел — охват, Tier-1 его закрыл, и теперь доминирующая потеря —
извлечение.

## 3. Объём и не-цели

**В объёме.**
- Изменения извлечения (промпт + схема + детерминированный builder) для G1–G4.
- Измерительная обвязка, позволяющая eval-харнессу повторно запускать текущий движок
  на сохранённом извлечении (LLM-free) и записывать извлечённую структуру вопроса.
- LLM-free гейты (`evals.l2_synthetic`, `evals.routing_synthetic`, `pytest`) и
  единственный бюджетируемый живой повторный прогон FOLIO L2.

**Вне объёма (без изменений).**
- Любая новая процедура решения или семантика: G3 переиспользует формы цели
  `forall`/`cnf` из T3/T4; G1 переиспользует head-only заземление из T5; G4 уже
  починен T6. Без нового флага; capability остаётся `clausal` (`ANKYRA_LOGIC`).
- Любая NL-эвристика над сырым текстом — детекторы cue-фраз, морфология, списки
  терминов (`docs/task.md` §3.8). Семантика живёт в промпте извлечения;
  детерминированный код работает только со структурированным выводом.
- Конструкты Tier-2 (равенство, функции, `↔`/`⊕`, многовеременная квантификация) —
  отдельные решения по фрагментам (`docs/folio_extension_plan.md` §6).
- Подгонка под id (`docs/coverage_ceiling.md` §8); понижение семантики ради
  прохождения строки (напр. свёртка `∀x(Pet→¬Cat)` в ground `¬is_a(pet,cat)`).
- Любой живой прогон, кроме единственного бюджетируемого гейта в §10
  (`docs/reasoning_roadmap.md` §4).

## 4. Четыре пункта

Раскладка по строкам ниже — **гипотеза триажа** по устаревшим трейсам; Шаг 0 (§6)
подтверждает или исправляет её до любого исправления.

### 4.1 G4 — масштаб ground-сатурации

- **Состояние:** движковая сторона **сделана** (T6, ground unit propagation,
  `docs/t6_plan.md`): он решает gold-строки `0009`/`0010` и поднял gold-fed до 42/45.
  Строки G4 из устаревших text-fed трейсов (`0009`, `0039`, `0127`), как ожидается,
  уже исправлены T5/T6.
- **Работа:** нет, если только Шаг 0 не покажет сохраняющийся промах масштаба. Если
  так — допустимо только *явное* движение бюджета (`D-FE-7`); исчерпание обязано
  оставаться честным `insufficient`. Никакого неограниченного поиска, никакой новой
  машинерии.

### 4.2 G1 — универсальная дизъюнкция только по голове («Either X or Y …»)

- **Состояние:** форма — это *генерическая дизъюнкция по универсуму*
  (`∀x(A(x) ∨ B(x))`, напр. «There are six types of wild turkeys: …», «an animal is
  either a rabbit or a squirrel»). Движок её поддерживает через T5
  (`head_only_rule`; head-only переменные заземляются по индивидуальной области
  `D_ind`), а экстрактор уже выдаёт дизъюнктивную голову в `consequents` с пустым
  антецедентом (наблюдалось на `0009`, `0149`, `0127`). Прежний
  `out_of_fragment:unsafe_rule` был артефактом до-T5.
- **Работа:** сделать общую форму явной в промпте и закрепить тестами — без изменения
  движка. Генерическая дизъюнкция идёт в правило с пустым антецедентом и
  дизъюнктивной головой (`consequents`), никогда — в ground-факт и никогда — в
  правило с выдуманным телом; head-переменная пробегает универсум.
- **Риск:** если детерминированный тест вскроет реальный пробел заземления —
  остановиться и обсудить, не добавлять ad-hoc ветку.

### 4.3 G3 — универсальный / условный / `¬∃` вывод (главный пункт)

- **Состояние:** движок умеет решать `Query.goal_mode="forall"` / `"cnf"` (T3/T4), но
  **извлечение не может это выразить**: у `QuestionStructure` есть только
  `ask` / `ask_all` / `ask_any`, а `unroll_query_structure` никогда не выдаёт
  `forall`. Поэтому экстрактор сворачивает `∀x(Pet→¬Cat)` / `¬∃x FinancialAid(x)` в
  один ground-атом (строки `0045`, `0007`, `0107`), что либо неверно, либо
  неотвечаемо.
- **Работа (`G-D1` = `ask_universal`):**
  - `core/schemas.py` `QuestionStructure`: добавить
    `ask_universal: list[StructAtom]` — универсально-квантифицированная клаузальная
    цель `∀x(l₁ ∨ … ∨ lₙ)`: литералы над одной и той же переменной, литерал может быть
    отрицательным (импликация `A(x) → B(x)` есть `¬A(x) ∨ B(x)`; `¬∃x φ` есть
    `∀x ¬φ`). Когда поле непусто, оно заменяет `ask` / `ask_all` / `ask_any`.
  - `build/unroll.py` `unroll_query_structure`: `ask_universal` →
    `goals = <литералы>`, `goal_mode="forall"`, `target = goals[0]`. Отрицание
    сохраняется; никакого принуждения к позитивности.
  - `build/extract.py` `QUESTION_SYSTEM`: вывод вида «all/every X …», «no X …»
    (`¬∃`) или условный вывод — это клаузальная цель `ask_universal`, **не**
    ground-атом; явно прописать различие — `ask_all` остаётся shared-witness
    экзистенциалом `∃x(g₁ ∧ … ∧ gₙ)` (T1), `ask_universal` — это `∀`.
- **Фрагмент:** уже назван — `universal_goal` (`engine/inference.py`) маршрутизируется
  в существующий capability `clausal`; нового флага нет.

### 4.4 G2 — потерянные посылки / несвязанные факты

- **Состояние:** экстрактор отбрасывает атомарные посылки про именованных индивидов,
  оставляя теорию почти без морфизмов (строки `0072`, `0058`, `0139`, `0149`), поэтому
  разрешимая строка становится `insufficient`.
- **Работа:** упрочнение промпта в `build/extract.py` `PROBLEM_SYSTEM` — сохранять
  **каждую** атомарную посылку; посылка про именованного индивида остаётся фактом
  (конъюнкция ground-утверждений — по факту на конъюнкт); никогда не отбрасывать
  посылку как «очевидную».
- **Отложено (`G-D2`):** детерминированный repair-триггер по покрытию (repairable-gap
  `structural:`, когда описательный текст во многом не покрыт) сейчас **не**
  добавляется. Он рискует переоткрывать легитимные open-world неизвестные; его
  пересмотрят только если живой гейт покажет, что одного промпта недостаточно.

## 5. Решения по устройству

- **G-D1 — форма цели G3.** (a) Выделенное клаузальное поле `ask_universal` в
  `QuestionStructure`, отображаемое в `goal_mode="forall"` (зеркалит T3;
  минимально, форма движка уже есть). (b) Общая схема `ask_formula`/`goal_clauses`
  для произвольной ground CNF (T4) — крупнее, а все строки G3 на FOLIO суть
  универсальные клаузы. (c) Без поля схемы; кодировать как `ask_all` и позволить
  движку угадывать — отклонено (`all`-цель — другая логика). **DECIDED (a).**
- **G-D2 — repair-триггер G2.** (a) Пока только упрочнение промпта; добавить
  repairable-gap по покрытию позже, и только если измерение покажет необходимость.
  (b) Добавить триггер сейчас — отклонено как спекулятивное и рискованное для
  легитимных open-world строк. **DECIDED (a), отложено.**
- **G-D3 — G4.** Без кода: T6 закрыл движковую сторону; только явное движение
  бюджета, если Шаг 0 покажет сохраняющийся промах (`D-FE-7`). **DECIDED.**
- **G-D4 — G1.** Уточнение промпта плюс детерминированный тест builder/движка; без
  изменения движка (T5 уже заземляет head-only переменную). **DECIDED.**
- **G-D5 — измерительная обвязка.** Сохранять извлечённый `QuestionStructure` и
  добавить LLM-free режим engine-replay в `evals/analyze_folio.py`, чтобы движковые
  изменения можно было перемерять на сохранённом извлечении; изменение
  промпта/схемы всё ещё требует живого повторного прогона. **DECIDED** (нужно, чтобы
  держать G-трек дешёвым).

## 6. Шаг 0 — measure-first (LLM-free)

До любого исправления:

1. **Триаж.** Пересобрать список провалов text-fed из сохранённых трейсов и
   классифицировать **первый блокер** каждой строки как G1/G2/G3/G4/other (Шаг 0
   подтверждает гипотезы §4 и отделяет устаревшие строки от настоящих).
2. **Engine replay.** Добавить в `evals/analyze_folio.py` режим, который повторно
   запускает `verify(trace.theory, trace.query)` (и перескоривает через
   `folio.score_record`) на сохранённом извлечении под логикой среза. Это даёт
   **текущий** счёт движка для старого извлечения при нулевой стоимости LLM, отделяя
   устаревшее от настоящего промаха извлечения.
3. **Записать** триаж в раздел результатов этого документа.

## 8. Синтетический гейт (`evals.l2_synthetic`, `evals.routing_synthetic`)

LLM-free, по одному кейсу на конструкт, с негативным контролем. Кейсы строятся на
уровне **структуры** (детерминированный путь builder), так как сам промпт
юнит-тестами не проверяется.

| кейс | структура / цель | ожидание |
|---|---|---|
| `g3-universal-01` | клауза `ask_universal` `[¬Pet(?x), ¬Cat(?x)]`; правила её вынуждают | `supported`, `yes`, признак `universal_goal` |
| `g3-universal-02` | свидетель, фальсифицирующий клаузу | `refuted`, `no` |
| `g3-universal-03` | та же цель, закодированная ground-атомом (неверная форма G3) | **не** должна доказываться (soundness-контроль) |
| `g3-neg-exists-01` | `ask_universal` `[¬FinancialAid(?x)]` (`¬∃`) | совпадает с gold-семантикой |
| `g1-head-only-01` | генерическое правило `∀x(A(x) ∨ B(x))` только по голове | решается по `D_ind` (T5), не по именам классов |
| `g1-head-only-02` | то же, но в области нет индивида | честный `unsupported` (без фабрикации) |
| `g3-off-01` | цель `ask_universal` при `logic="off"` | `out_of_fragment:compound_goal` |

Кейс в `routing_synthetic` утверждает, что `ask_universal` маршрутизируется в
`clausal`, когда `ANKYRA_LOGIC` включён.

**Замечание о реализации (G3).** Кейсы `evals.l2_synthetic` строят `Theory`/`Query`
напрямую, минуя `QuestionStructure`; механизм движка `universal_goal` там уже
покрыт (T3, `evals/build_l2_synthetic.py:_universal_goal_cases`). Новая работа G3 —
**отображение в builder** `ask_universal` → `goal_mode="forall"` — поэтому гейтится
детерминированными тестами builder (`tests/test_build_unroll.py`,
`tests/test_build_query.py`) вместо дублирующего синтетического механизма, включая
soundness-контроль `g3-universal-03`.

## 10. Живой гейт (бюджет)

Один повторный прогон FOLIO L2 тир a после того, как все пункты лягут:

```
uv run python -m evals.folio --subset l2 --jobs N
uv run python -m evals.analyze_folio --subset l2
```

Критерий приёмки: text-fed correct строго выше, **0 grounded false proofs**, каждый
оставшийся провал категоризирован как G1–G4 или `other`. Записать число и триаж в §13
и в `docs/quality_findings.md` §G. Это единственный живой прогон; повторять только при
расхождении (`docs/reasoning_roadmap.md` §4).

## 11. Риски

- **Регрессии промпта в других доменах.** Формулировки G1–G3 обязаны оставаться
  общими (без доменных терминов). Гейты ProofWriter/ProntoQA по пунктам не
  перепрогоняются; проверка — offline-набор и единственный FOLIO-гейт.
- **Неверное кодирование G3.** Универсальный вывод нельзя сворачивать в ground-атом
  (ловушка T3); контроль `g3-universal-03` это утверждает.
- **Передоминирование G2.** Откладывание триггера по покрытию (`G-D2`) избегает
  изготовления посылок; если триггер позже добавят, он не должен срабатывать на
  легитимном open-world неизвестном.
- **Путаница с устаревшими трейсами.** Guard — engine replay из Шага 0; без него
  text-числа читались бы по до-Tier-1 трейсам.

## 18. Диагностика `G-D2` — coverage-триггер не селективен

Coverage-триггер (исходный замысел `G-D2`: repairable-gap `structural:`, когда
описательный текст во многом не покрыт) был измерен до реализации, на трейсах
прогона 2 (`source_coverage` цитат собранной теории / длина источника):

| фактический вердикт | диапазон доли покрытия |
|---|---|
| верные строки | 0.24 – 0.91 |
| провальные строки | 0.19 – 0.88 |

Распределения почти полностью перекрываются. Конкретно, провальные строки G2 **не**
недопокрыты: `0042` — 0.88, `0077` — 0.84 при **0** ground-морфизмов: экстрактор
цитирует предложения внутри правил, но отбрасывает ground-факты, поэтому текст
«покрыт», а посылки потеряны. Обратно, проходные чисто-правиловые строки (напр.
`0043` 0.91, `0076` 0.90) и проходные низкопокрытые (`0006` 0.41, `0065` 0.42) лежат
по обе стороны. Порог по покрытию поэтому срабатывал бы широко на верных извлечениях
(стоимость, churn, риск регрессий), почти не ловя провалы G2.

**Вывод.** Coverage-триггер **не является общим решением** и не строится; измерение
противоречит посылке `G-D2`. Принципиальная альтернатива — **query-driven unlink
repair**: после `build_query`, когда `verify` сообщает о несвязанном атоме вопроса,
чей константа/предикат отсутствует в теории, запустить одно ограниченное
переизвлечение задачи, сфокусированное на этом атоме (структурно — по собранной
теории/запросу, без NL-эвристик). Это изменение на уровне графа, крупнее `G-D2`; ему
нужно отдельное решение.

Альтернатива — **B** (формулировка извлечения для оставшихся строк G3) или принять
31/45.

## 19. Решение — B сейчас, `A′` отложить (с причинами)

**DECIDED.** Делаем **B** (формулировка извлечения для оставшихся строк G3);
**откладываем `A′`** (query-driven unlink repair). Причины откладывания `A′`, по
трейсам прогона 2:

1. **Низкая селективность gap-driven.** `A′` срабатывает на
   `target_unmatched:`/`condition_unmatched:` из `verify`. Среди 11 провалов
   извлечения этот сигнал есть только у `0042` и `0033` (yield 2):
   - `0058` — `supported` **без gap**: это мисформализованная цель, которую
     gap-driven repair не видит;
   - `0073`, `0077`, `0149` — `insufficient` **без gap**;
   - `0018`, `0020`, `0040`, `0044`, `0127` — `logic_budget:exhausted`, не unlink.
2. **Расширение до сырого отсутствия токенов неселективно.** По константам/предикатам
   вопроса, отсутствующим в теории: проходные строки доходят до 3
   (`0083`, `0076`, `0043`), а провальные бывают с 2 (`0018`, `0040`, `0042`). Порога,
   который их разделяет, нет — ровно как с coverage (§18).
3. **Это не минимально.** `A′` — механизм уровня графа (новый шаг после query, хук
   repair, лишние LLM-вызовы на исправление, новые тесты). Строить его на
   неподтверждённой посылке селективности — спекулятивная машинерия, что правила
   проекта отвергают (`AGENTS.md`; `docs/coverage_ceiling.md` §8).
4. **Условие возврата (бэклог).** Пересмотреть `A′` только если после B оставшийся
   провал даёт **чистый** unlink-сигнал: gap `target_unmatched:`/`condition_unmatched:`,
   чей атом отсутствует в теории *и* чьё исходное предложение не покрыто. Тогда
   строить как именованный ограниченный шаг со свежим измерением — никогда как
   пороговую эвристику.

**Объём B** (только промпт, `QUESTION_SYSTEM`):
- `0044`: ground-дизъюнкция литералов (в т.ч. отрицательных) — это `ask_clauses` с
  одной клаузой, **не** `ask_all` (который есть конъюнкция).
- `0033`, `0058`: неопределённый участник («leads a Y», «in the same state») — это
  shared-witness `ask_all` с одной переменной-свидетелем.
- `0040`: конъюнкция про конкретный **именованный** объект использует константу,
  а не `?x`.
- Валидация: один полный живой прогон (не только четыре id), так как правки промпта
  давали кросс-доменные регрессии (прогон 1 → прогон 2).

**Решение зафиксировано; реализация и живой результат — в §20.**

  Pierre are in the same state» → `[state(butte, ?x), state(pierre, ?x)]`);
  конъюнкция про **именованный** объект сохраняет константу в каждом конъюнкте (не
  `?x`). Это адресует `0033`, `0058`, `0040`.
- `ask_clauses` теперь документирует ground-**дизъюнкцию с отрицательными/смешанными
  литералами** («neither A nor B» = `¬A ∨ ¬B`) как одну клаузу, никогда `ask_all`. Это
  адресует `0044`.

## 22. Ablation модели — более сильная модель не сдвигает стену

Гипотеза: остаточные промахи — instruction-following извлечения, поэтому более

  бюджет.

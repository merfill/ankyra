\begin{abstract}
Мы представляем Ankyra — нейросимволическую систему рассуждений, не зависящую от предметной области. В её основе лежит принцип разделения ролей: языковая
модель \emph{предлагает} формализацию, а детерминированный символический решатель её \emph{решает}. Система охватывает несколько разрешимых формализмов
 — от определённых хорновских клауз и стратифицированного отрицания до позитивной логики первого порядка с дизъюнкцией и кванторами, конечно-доменных
ограничений, точной арифметики и умолчаний со специфичностью. Для каждого формализма определена корректная решающая процедура и объявлен фрагмент.
Любой ответ сопровождается автоматически проверяемой историей вывода; ни одно утверждение не попадает в теорию без дословной цитаты или явной пометки
гипотезы. Мы приводим демонстрационную оценку на стандартных коллекциях: на охваченных срезах система показывает высокую точность, не допуская ни
одного уверенно неверного вывода, и честно воздерживается (\texttt{out\_of\_fragment}) там, где реализованная логика не может выразить задачу.
Мы также сравниваем систему с двумя открытыми нейросимволическими системами — Logic-LM и LINC — на одинаковых входах и одной и той же модели и показываем,
что при малой и недорогой модели связывающим ограничением оказывается интерфейс перевода, а не рассуждение.
Мы не претендуем на передовой уровень: оценка опирается на зафиксированные подвыборки, а не на полные тестовые наборы, и все возникающие статистические
и методические ограничения мы проговариваем явно.
\end{abstract}

\section{Введение}
\label{sec:intro}

Большие языковые модели хорошо читают текст и переводят его на точный формальный язык. Плохо они делают то, что удаётся символическим процедурам: выводят
следствия \emph{корректно}, точно отслеживают, какие посылки были использованы, и отказываются угадывать. Свободная цепочка рассуждений (chain-of-thought)
звучит правдоподобно, но не отличает правильный шаг от просто убедительного: у неё нет ни свидетельства корректности, ни истории, по которой можно было
бы восстановить, на чём держится ответ. Именно поэтому проверяемость оказывается центральной проблемой рассуждений языковых моделей.

Ankyra~\cite{ankyra} даёт каждой стороне ту работу, в которой она сильна. Языковая модель читает текст и выполняет две вещи: разбирает задачу на \emph{структуру}
(объекты, факты, правила, цитаты) и, пока ответ ещё открыт, предлагает отдельные шаги. Символический решатель отвечает за \emph{формальную} сторону:
превращает структуру в теорию, замыкает её по правилам вывода, сопоставляет с вопросом и удостоверяет то, что действительно следует.

Центральный принцип построения формулируется коротко: \emph{языковая модель предлагает, решатель решает}. Модель никогда не владеет истиной. Каждое её
утверждение детерминированно классифицируется как \texttt{derivable}, \texttt{cited} (подкреплено дословной цитатой), \texttt{hypothesis}
(знание, отсутствующее в тексте, с пометкой) или \texttt{rejected}. Обоснованность ответа никогда не превышает обоснованности его посылок:
вывод из цитат — это \texttt{proven}, вывод, опирающийся на допущения, — \texttt{proven\_under(H)}.

Это разделение не является инженерным компромиссом. Оно отражает различение \emph{неформализуемого источника} (doxa) и формального \emph{logos}:
языковая модель здесь — носитель doxa, к которому logos обращается за предложениями, но не за истиной, а протокол предложений, детерминированная
классификация, журнал и проверки привязки к тексту образуют интерфейс между ними~\cite{doxa}. Полное изложение операторного семейства — предмет
отдельной работы; здесь мы сосредоточены на реализующей его системе и её эмпирической проверке.

\paragraph{Вклад.}
\begin{itemize}
	\item Архитектура «предлагает / решает» с двумя раздельными участниками и автоматически проверяемой историей вывода.
	\item Протокол предложений: каждое утверждение классифицируется детерминированно, а обоснованность ответа (\texttt{proven}, \texttt{proven\_under(H)}, \texttt{not\_proven}) никогда не превышает обоснованности его посылок.
	\item Семейство разрешимых формализмов в рамках \emph{протокола объявленного фрагмента} с честным воздержанием \texttt{out\_of\_fragment} вместо молчаливого перехода к более слабой логике.
	\item Методика поэтапных проверок \emph{составных} эталонных коллекций, разделяющая потолок охвата (формализм) и потолок извлечения (модель) с помощью режима эталонного входа.
	\item Сравнение на общем входе с двумя открытыми системами вида «переводчик + решатель» на тех же строках и той же модели, разделяющее интерфейс перевода и символическое рассуждение и оценивающее эффект режима модели.
	\item Демонстрационный прототип на стандартных коллекциях с измеримым инвариантом корректности — отсутствием уверенно неверных выводов.
\end{itemize}

\paragraph{Область (явно).} Это отчёт о демонстрационном прототипе, а не заявка на передовой уровень. Мы оцениваем \emph{зафиксированные подвыборки}
стандартных коллекций, объясняем бюджет, не позволяющий проходить полные тестовые наборы, и приводим доверительные интервалы. Полный охват коллекции
недостижим по построению для наборов со смешанными конструкциями, таких как FOLIO (раздел~\ref{sec:results}).

\paragraph{Структура.} Раздел~\ref{sec:system} описывает архитектуру и протокол предложений; раздел~\ref{sec:example} приводит примеры по стадиям;

приводит результаты; раздел~\ref{sec:comparison} сравнивает систему с Logic-LM и LINC на одинаковых входах; раздел~\ref{sec:limitations} — ограничения; раздел~\ref{sec:related} — связанные работы.

\section{Обзор системы}
\label{sec:system}

Ankyra — не монолитный решатель, а система, которая координирует формализации и решающие процедуры. Для каждой задачи модель порождает формализацию в
некоторой логике, а корректная процедура для этой логики её решает. Разные классы задач требуют разных процедур, каждая со своим внутренним представлением;
какие именно логики реализованы, описано в разделе~\ref{sec:formalisms}.

\subsection{Четыре фазы}

Задача проходит четыре фазы. Только одна из них — вывод — принадлежит решателю; две другие обращаются к модели.

\begin{itemize}
	\item \textbf{Фаза 0 — декомпозиция.} Текст разделяется на описательную и вопросительную части, и с этого момента они трактуются как разные объекты. Далее следуют два обращения к языковой модели в фиксированном порядке: сначала структурная декомпозиция описательной части (объекты, факты, условные утверждения, альтернативы и группировки, отрицания и модальности, короткая дословная цитата на каждый элемент), затем выражение вопроса над уже установленным каноническим словарём теории. Между обращениями и после них детерминированный построитель разворачивает и дополняет структуру до \emph{теории} и \emph{запроса}. Действует строгое правило: \emph{вопрос никогда не утверждается как факт}.
	\item \textbf{Фаза 1 — решение.} Символический решатель выводит все следствия теории до неподвижной точки и проверяет, следует ли цель. Каждый выведенный факт несёт историю: какие факты и какое правило его породили. Решатель не добавляет знания от себя — он корректен и полон \emph{относительно} полученной формализации.
	\item \textbf{Фаза 2 — управляемый цикл.} Если построенная теория ещё не решает вопрос, система не останавливается на голом «неизвестно»: она сообщает, где именно возникла трудность, и модель получает ограниченную возможность помочь, предлагая по одному шагу за итерацию (раздел~\ref{sec:cycle}).
	\item \textbf{Фаза 3 — объяснение.} Готовая трасса вывода собирается \emph{автоматически} из истории вывода, а не моделью. Модель может позже пересказать готовую трассу связным текстом, но не вправе вводить новые факты.
\end{itemize}

Ключевая граница проходит между фазами 0 и 1: всё, что формулирует модель, обязано либо опираться на дословную цитату, либо быть явно помеченным допущением.
Ничто не входит в теорию без такого основания.

\subsection{Протокол предложений}

Каждое утверждение, которое модель хочет добавить, классифицируется детерминированно. Классификация не является субъективным суждением: она зависит
только от того, выводится ли утверждение уже сейчас, подкреплено ли оно текстом или является допущением.

\begin{center}
\begin{tabular}{p{2.4cm}p{6.2cm}p{4.6cm}}
\toprule
\textbf{Категория} & \textbf{Условие} & \textbf{Действие решателя} \\
\midrule
\texttt{derivable} & уже выводится из текущей теории & принимает только как изложение \\
\texttt{cited} & новое утверждение с дословной цитатой из текста & добавляет в аксиомы \\
\texttt{hypothesis} & знание, отсутствующее в тексте & заносит в журнал с пометкой $H$ \\
\texttt{rejected} & не проходит проверку схемы, безопасности или цитаты & отклоняет с кодом причины \\
\bottomrule
\end{tabular}
\end{center}

Именно различение \texttt{cited} и \texttt{hypothesis} делает ответы честными. Вывод, использующий только процитированные факты, — это
\texttt{proven}. Вывод, опирающийся на допущения, — \texttt{proven\_under(H)}, и ответ называет эти допущения. Если ничего не установлено,
ответ — \texttt{not\_proven}. Поэтому обоснованность ответа никогда не превышает обоснованности его посылок, а допущение не может выдавать себя за факт.

\subsection{Управляемый цикл и журнал}
\label{sec:cycle}

Внутренний цикл (фаза 2) полностью детерминирован; обращением к модели является только \emph{предложение}. Цикл чередует подсказку, свободное предложение
и детерминированную классификацию и принимает не более одного предложения за итерацию — так каждая итерация оставляет проверяемый след.
Итерация устроена следующим образом:

\begin{enumerate}
	\item \textbf{Проверка.} Решатель замыкает текущую теорию и проверяет цель, порождая вердикт и структурированные пробелы (например, \texttt{target\_unmatched:}, когда предикат цели нигде не встречается).
	\item \textbf{Проверка завершения.} Если вердикт уже решающий — \texttt{supported}, \texttt{refuted}, \texttt{contradiction} или \texttt{insufficient} — цикл останавливается.
	\item \textbf{Подсказка.} Модель получает структуру задачи, допустимые предикаты и объекты теории, сводку выведенного, текущие пробелы, цель и виды допустимого предложения.
	\item \textbf{Предложение.} Модель возвращает краткое изложение и ровно одно типизированное предложение: переформулировать вопрос в словаре теории, добавить правило, утвердить цитируемый факт или выбрать следующую подцель.
	\item \textbf{Классификация и применение.} Решатель проверяет предложение на схему, правила безопасности и текст, относит его к одной из четырёх категорий выше и применяет либо отклоняет. Применение монотонно: теория только растёт.
	\item \textbf{Запись.} Итерация заносится в журнал, внутренний цикл перезапускается.
\end{enumerate}

Цикл останавливается на решающем вердикте, на \texttt{no\_progress} (две подряд итерации без изменений), на исчерпании бюджета итераций или
когда допущения запрещены. Ни один из этих исходов не является нарушением корректности: каждый — честная точка остановки.

\emph{Монотонная база, меняющийся ответ.} \emph{База} — аксиомы, правила, гипотезы — только растёт: посылки не удаляются, цель не ослабляется.
\emph{Ответ} тем не менее может меняться по мере поступления новой информации. Такие изменения не скрываются: каждое записывается как
\texttt{Revision} с указанием итерации-источника и причастных допущений, и ревизии сохраняются вместе с объяснением. Так система остаётся
проверяемой при немонотонном рассуждении, не изменяя при этом базу.

\subsection{Модель данных}

Всё, о чём рассуждает система, собирается из нескольких простых элементов. \emph{Объект} (\texttt{Object}) — каноническая именованная сущность.
\emph{Отношение} (\texttt{Morphism}) — один предикат, применённый к субъекту и объекту, с модальностью и признаком отрицания; отрицание — тот
же предикат, помеченный ложным, а не отдельное имя. \emph{Правило} (\texttt{Rule}) — условное утверждение: конъюнкция условий влечёт следствие,
оно помечено как импликация или исключение и несёт источник (цитату или идентификатор гипотезы). \emph{Теория} (\texttt{Theory}) собирает объекты,
утверждённые отношения и правила, а \emph{запрос} (\texttt{Query}) хранит условия, которые утверждает сам вопрос ($\Gamma$), цель ($\phi$) и
тип ответа. Внутри решателя \emph{факт} (\texttt{Fact}) — это заземлённый атом вместе с историей вывода.

\subsection{Принципиальное ограничение: детерминированный код не разбирает язык}

Детерминированный код никогда не интерпретирует естественный язык. Нормализация идентификаторов и закрытых перечислений, которые модель \emph{уже}
извлекла (идентификаторы предикатов и объектов, модальность, \texttt{relation\_kind}, ключи полей), допустима: она действует на структурированный
результат, а не на исходный текст. Эвристики по исходному тексту, опирающиеся на слова, морфологию, характерные обороты или составленные вручную
списки терминов, недопустимы: они не обобщаются между предметными областями, а семантика задаётся инструкцией извлечения. Единственные операции
над исходным текстом — структурные проверки: точное вхождение цитаты, покрытие и длина.

\section{Примеры по стадиям}
\label{sec:example}

Ниже приведены примеры для каждой стадии — от чистой дедукции и абдукции до умолчаний, отрицания, дизъюнкции,
составного случая FOLIO, конечно-доменных ограничений и точной арифметики. Они показывают, как работают
протокол предложений, обоснованность ответа и выбор решающей процедуры на конкретных входах.

\subsection{Чистая дедукция}

Текст: \emph{«It is raining. If it is raining, the ground is wet. Is the ground wet?»}

Фаза 0 разделяет текст на описательную и вопросительную части. Описательная часть даёт один факт и одно правило, вопрос становится целью:

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Элемент} & \textbf{Содержимое} & \textbf{Источник} \\
\midrule
Факт & \texttt{raining()} & \texttt{cited} («It is raining.») \\
Правило $R_1$ & \texttt{raining()} $\Rightarrow$ \texttt{is\_wet(ground)} & \texttt{cited} («If it is raining, the ground is wet.») \\
Цель $\phi$ & \texttt{is\_wet(ground)}, тип \texttt{yes\_no} & вопрос (не факт) \\
\bottomrule
\end{tabular}
\end{center}

Фаза 1 замыкает теорию: правило $R_1$ срабатывает на факте и выводит \texttt{is\_wet(ground)}, сохраняя в истории посылку
и сработавшее правило. Проверка даёт вердикт \texttt{supported}, ответ \texttt{yes} и обоснованность \texttt{proven};
цикл не выполняет ни одного обращения к модели. Фаза 3 собирает трассу автоматически:

\begin{enumerate}
	\item \texttt{raining()} — аксиома, \texttt{cited};
	\item \texttt{is\_wet(ground)} — правило $R_1$, из шага 1.
\end{enumerate}

\subsection{Абдукция и обоснованность ответа}

Текст: \emph{«The vehicle has an engine, four wheels, 150 horsepower and four doors. What kind of vehicle is it?»}

Фаза 0 извлекает только наблюдаемые факты — \texttt{has\_engine}, \texttt{wheel\_count}, \texttt{power},
\texttt{door\_count}. Правил классификации в тексте нет, поэтому их нет и в теории. Цель открыта:
\texttt{is\_a($X$, ?c)}. Фаза 1 не выводит для этого предиката ничего и сообщает пробел
\texttt{target\_unmatched: is\_a}, после чего запускается управляемый цикл.

На первой итерации модель предлагает правила классификации, например: «двигатель $\Rightarrow$ моторное средство»,
«моторное средство и четыре колеса $\Rightarrow$ автомобиль». Цитат под ними нет, поэтому классификация относит
их к \texttt{hypothesis}, и правила заносятся в журнал с пометками $H_1, H_2, \dots$ (раздел~\ref{sec:cycle}).
Теория монотонно растёт, замыкание выводит \texttt{is\_a($X$, car)} и \texttt{is\_a($X$, sedan)}, а переменная
цели связывается по цепочке \texttt{is\_a}, а не угадыванием. Проверка даёт \texttt{supported}, но вывод
опирается на допущения, поэтому обоснованность ответа — \texttt{proven\_under($H_1,H_2,\dots$)}, и ответ
называет эти допущения поимённо.

Если запустить ту же задачу с \texttt{ANKYRA\_ALLOW\_HYPOTHESES=false}, те же правила отклоняются, и система
честно отвечает \texttt{not\_proven}. Разница между \texttt{proven} и \texttt{proven\_under} в этих двух
примерах не косметическая: она в точности отражает, на чём держится ответ.

\subsection{Умолчания и специфичность}

Текст: \emph{«Birds can fly. Penguins are birds, but penguins cannot fly. Tweety is a penguin. Can Tweety fly?»}

Фаза 0 даёт факты \texttt{is\_a(tweety, penguin)} и \texttt{is\_a(penguin, bird)}, а также два правила-умолчания:
\texttt{is\_a(?x, bird)} $\Rightarrow$ \texttt{fly(?x)} и \texttt{is\_a(?x, penguin)} $\Rightarrow$ \texttt{$\neg$fly(?x)}.
При обычном монотонном замыкании сработали бы оба правила и получилось бы противоречие. При включённом слое умолчаний
правило про пингвинов оказывается строго специфичнее — оно опирается на ребро \texttt{is\_a(penguin, bird)}
 — и побеждает: вердикт \texttt{refuted}, ответ «нет», признак \texttt{defeasible=true}.

Симметричный пример — «птицы не летают, пингвины летают» — даёт \texttt{supported} и ответ «да»: специфичность не
зависит от полярности. Если же взять классический пример «Никсон — квакер и республиканец» с правилами \texttt{quaker}
$\Rightarrow$ \texttt{pacifist} и \texttt{republican} $\Rightarrow$ \texttt{$\neg$pacifist}, специфичность не
определена — оба правила одинаково конкретны, — и система честно отвечает \texttt{unsupported} с пробелом
\texttt{undecided\_conflict}, а не угадывает победителя. Источник: \texttt{evals/defeasible\_synthetic}, 8/8.

\subsection{Отрицание и несовместность (L1)}

Текст: \emph{«No real number is imaginary. $a$ is a real number. Is $a$ imaginary?»}

Утверждение «ни одно действительное число не мнимо» формализуется не общим правилом, а ограничением несовместности
\texttt{disjoint(real\_number, imaginary)}. Вместе с фактом \texttt{is\_a(a, real\_number)} оно даёт
\texttt{$\neg$is\_a(a, imaginary)} и, следовательно, опровергает цель: вердикт \texttt{refuted}, ответ «нет».
Существенно, что опровержение опирается на явную несовместность, а не на молчаливое закрытие мира: при открытом
мире система не объявляет цель ложной лишь потому, что её не удалось вывести. Источник: \texttt{evals/l1\_synthetic},
идентификатор \texttt{disjoint-refute-01}; проверка 40/40.

\subsection{Дизъюнкция и разбор случаев (L2)}

Теория: факт \texttt{is\_a(rex, prim)}; правило \texttt{is\_a(?x, prim)} $\Rightarrow$ \texttt{is\_a(?x, a)} $\lor$ \texttt{is\_a(?x, b)};
правила \texttt{is\_a(?x, a)} $\Rightarrow$ \texttt{is\_a(?x, c)} и \texttt{is\_a(?x, b)} $\Rightarrow$ \texttt{is\_a(?x, c)};
цель — \texttt{is\_a(rex, c)}. Хорновская процедура не может обработать дизъюнктивную голову, поэтому включается клаузальная
процедура L2: она разбирает случаи по двум дизъюнктам и в каждом выводит \texttt{c}, после чего вердикт — \texttt{supported}.
С выключенным L2 тот же вход даёт честный \texttt{out\_of\_fragment}, а не молчаливый переход к более слабой логике. Источник:
\texttt{evals/l2\_synthetic}, идентификатор \texttt{head-case-split-01}; проверка 65/65.

\subsection{Составной случай FOLIO}

Эталонная разметка FOLIO смешивает конструкции разных стадий, поэтому коллекция оценивается по внутрифрагментным срезам.
В строке \texttt{folio-validation-0010} («дикая индейка») посылки содержат дизъюнкцию шести подвидов и факт
\texttt{WildTurkey(tom)}. Условные отрицания вместе с этим фактом дают \texttt{$\neg$Eastern(tom)}, \texttt{$\neg$Osceola(tom)}
и отрицание дизъюнкции Goulds, Merriams и Riogrande; следовательно, цель \texttt{Eastern(tom)}, помеченная \texttt{False},
опровергается. Клаузальная процедура даёт \texttt{refuted} («нет»), что совпадает с меткой.

Строка \texttt{folio-validation-0027} («Марвин») устроена иначе: цель помечена \texttt{False}, но размеченные посылки
не влекут ни саму цель, ни её отрицание, и система честно воздерживается (\texttt{unknown}), а не выдаёт неподтверждённое
«нет». На срезе отрицания (13 строк) режим эталонного входа даёт 12/13 при нуле уверенно неверных выводов; на срезе
L2 уровня a (45 строк) охват составляет 44/45, а режим эталонного входа — 42/44. Источники:
\texttt{evals/data/folio\_l2\_tier\_a.jsonl}, \texttt{folio\_negation\_tier\_a.jsonl}.

\subsection{Конечно-доменные ограничения (L3)}

Задача AR-LSAT: пять инструментальных пьес идут на компакт-диске в некотором порядке; заданы условия порядка,
соседства и группировки, а вопрос спрашивает, какая из предложенных последовательностей допустима. Формализация
 — конечно-доменная: область позиций $0..4$, пять переменных с ограничением \texttt{all\_different}, порядковые
и составные ограничения. Вопрос вида \texttt{not\_violate} проверяется перебором, а вопросы «обязательно» и
«может быть» решаются как истинность во всех или хотя бы в одном допустимом размещении. На закодированных вручную
реальных играх режим эталонного входа даёт 27/27, в том числе 5/5 для вопросов \texttt{not\_violate}; реальный
запуск на разбиении eval — 23/30. Источники: \texttt{evals/data/\allowbreak ar\_lsat\_dev.jsonl}, \texttt{evals/data/\allowbreak ar\_lsat\_gold.jsonl}.

\subsection{Точная арифметика (L4)}

Задача GSM8K: «Генри сделал две остановки в поездке на 60 миль; первая — через 20 миль, вторая — за 15 миль до конца.
Сколько миль он проехал между остановками?» Фаза 0 строит ориентированный граф величин:
\texttt{total=60}, \texttt{first=20}, \texttt{before\_end=15}, а искомая величина \texttt{between}
задаётся уравнением. Линейная система решается в точных рациональных числах: $60-20-15=25$. Арифметическая ошибка
здесь невозможна по построению: неверное число может быть только ошибкой \emph{моделирования}, но не счёта.
Источник: \texttt{evals/data/gsm8k\_gold.jsonl}, идентификатор \texttt{gsm8k-gold-0028}; режим эталонного входа 8/8.

\section{Формализмы и решающие процедуры}
\label{sec:formalisms}

Ankyra — не «решатель хорновских клауз», а система, координирующая формализации. Конечная цель — охватить наибольший практически
важный класс рассуждений, для которых существует разрешимая процедура проверки: модель порождает формализацию в логике $L$,
а корректная процедура для $L$ её решает. Охват поэтому измеряется в именованных формализмах, а не в неопределённом «рассуждении».

\subsection{Протокол стадии}

Каждая стадия описывается одинаковым набором из шести пунктов: \emph{формализм} $L$ и семантика ответа; \emph{решающая процедура},
корректная для $L$ (и, где заявлено, полная); \emph{изменение решателя}; \emph{изменение извлечения} — то, что фазы 0 и 2 должны
уметь выразить, чтобы модель могла предлагать в $L$; \emph{этапная проверка на эталонной коллекции} с малой зафиксированной выборкой
и жёсткими инвариантами (отсутствие уверенно неверных выводов, каждый определённый ответ \texttt{proven}, точность выше порога,
каждый остаток отнесён к категории); и \emph{переключатель}, выключенный по умолчанию, чтобы семантика эталонной коллекции не
проникала в решатель.

\begin{center}
\begin{tabular}{p{0.8cm}p{5.6cm}p{5.4cm}}
\toprule
\textbf{Стадия} & \textbf{Формализм} & \textbf{Процедура} \\
\midrule
L0 & определённые хорновские клаузы, \texttt{is\_a}, отрицание как комплементарные пары (открытый мир) & полунаивный прямой вывод до неподвижной точки \\
L1 & стратифицированное отрицание / отрицание как неудача (NAF), объявленный закрытый мир & стратифицированное замыкание, ограничения несовместности \\
L2 & позитивная логика первого порядка: дизъюнкция, $\exists/\forall$, доказательство разбором случаев & ограниченная резолюция (заземление по конечной области) \\
L3 & конечно-доменные ограничения (CSP/SAT) & поиск по конечным областям значений \\
L4 & арифметические термы и уравнения & точное рациональное вычисление / линейное исключение \\
D  & умолчания со специфичностью через \texttt{is\_a} & слой умолчаний (специфичность над строгим ядром) \\
\bottomrule
\end{tabular}
\end{center}

L3 и L4 — отдельные решатели в рамках той же системы, со своим внутренним представлением: конечно-доменные ограничения — это не логическая
выводимость, а удовлетворение ограничений, а арифметическая задача даёт число, а не следствие.

\subsection{Объявленный фрагмент}

Поскольку процедуры разные, система должна решить, какая из них запускается, — и сделать это, никогда не угадывая. Ответ даёт
\emph{протокол объявленного фрагмента}. Система анализирует \emph{построенные} теорию и запрос и выводит набор требуемых
признаков: есть ли дизъюнктивная голова, квантор существования, составная цель, отрицание, встроенное сравнение, равенство.
Это и есть \emph{фрагмент} — объективное свойство формализации, а не намерение. Отдельно запуск \emph{объявляет} свою семантику:
какие процедуры включены (переключатели \texttt{ANKYRA\_*}) и читается ли запрос при открытом или закрытом мире. Решение о
выборе процедуры сводит эти два начала и проверяет их друг против друга.

Если фрагмент укладывается во включённые возможности, выбирается соответствующая процедура. Если нет — структуре нужна логика,
которую запуск не включил, или комбинация, которую выбранная процедура не может соблюсти, — результатом становится именованный
пробел \texttt{out\_of\_fragment}, а не молчаливый переход к более слабой процедуре.

Точкой расширения служит протокол \texttt{Inference}: семантика (выводимость, форма вердикта, замыкание, против которого
классифицируется предложение) становится сменной, а выбор процедуры и механизмы остаются на месте. Сегодня у него две
реализации — хорновская и клаузальная; L3 и L4 подключаются как отдельные решатели.

\subsection{Что общего у решателей}

Каждый решатель корректен \emph{относительно} переданной ему формализации и честно воздерживается вместо угадывания.
Символические компоненты полны относительно формализации (прямой вывод достигает неподвижной точки), но полнота \emph{перевода}
не заявляется: модель всегда может упустить посылку в тексте. Поэтому различие между неверным и недостающим ответом сохраняется всюду.

\section{Методика оценки}
\label{sec:method}

\paragraph{Метрики.} Для каждой коллекции мы приводим \emph{точность по классу} (трёхклассовую или с выбором варианта) с
доверительными интервалами Уилсона (95\%). Этапная проверка также требует \emph{инварианта корректности}: каждый определённый
ответ \texttt{proven} и отсутствие уверенно неверных выводов.

\paragraph{Два потолка.} Для составной эталонной коллекции мы разделяем \emph{охват} (долю эталонных формул, которые
реализованная логика может выразить и решить; остаток — честный \texttt{out\_of\_fragment}) и \emph{извлечение}
(долю охваченных строк, которые языковая модель переводит верно). Режим \emph{эталонного входа} подаёт решателю размеченную
формализацию вместо извлечённой моделью, отделяя точность метода от точности перевода.

\paragraph{Бюджет и воспроизводимость.} Бесплатного доступа к языковой модели нет; запуски с обращением к ней платные.
Поэтому каждая коллекция входит небольшой зафиксированной подвыборкой, проходит один раз и повторяется только при
расхождении. Все проверки без участия языковой модели (синтетические наборы, диагностика с эталонным входом)
воспроизводимы из одного репозитория.

\paragraph{Лестница проверок.} Результаты добываются на лестнице из трёх ступеней. Первая — синтетические наборы
без участия языковой модели, напрямую использующие семантику каждого формализма, без извлечения и без изменчивости
провайдера доступа к LLM: это чистый сигнал решателя. Вторая — простая по поверхности реальная коллекция (например, ProntoQA-OOD для L2),
добавляющая реальный текст поверх чистой нотации. Третья — намеренно тяжёлый по извлечению срез реальной коллекции
(FOLIO). Поперёк лестницы режим эталонного входа, то есть подача решателю написанных вручную формул вместо извлечённых,
разделяет два разных предела: \emph{охват} (сколько задач реализованная логика вообще может выразить; выход за него
 — честный \texttt{out\_of\_fragment}, снижающий полноту, но не корректность) и \emph{извлечение} (сколько охваченных
задач модель переводит верно). Разделение этих двух и показывает, откуда должно прийти улучшение — из решателя или
из интерфейса.

поэтому она оценивается по внутрифрагментным срезам, а не единым баллом:
\begin{itemize}
	\item срез отрицания (13 строк) оказался \emph{ограниченным фрагментом}: на хорновском пути режимы эталонного и текстового входа совпадают (7/13), а остаток составляют сведение к противоречию и контрапозиция; поэтому срез оценивается клаузальной процедурой L2: эталонный вход — 12/13, текстовый вход — 11/13, ни одного уверенно неверного вывода. Четыре ответа \texttt{Uncertain} остаются честными \texttt{unknown}; закрытый мир глобально не применяется, иначе он неверно опроверг бы их;
	\item уровень a формализма L2 (45 строк): охват — 44/45 (одна повреждённая разметка), то есть реализованная логика выражает почти весь срез; на охваченных строках режим эталонного входа даёт 42/44 против 29/44 при текстовом входе.
\end{itemize}
Разрыв между режимом эталонного входа (метод) и текстовым входом (извлечение) локализует оставшуюся стоимость в извлечении,
а не в решателе: потолок охвата на зафиксированном 45-строчном срезе фактически достигнут. По всему 204-строчному проверочному
разбиению два зафиксированных фрагмента проверок покрывают 13 + 93 = 106 строк (нижняя оценка выразимой доли); из 93
строк фрагмента L2 зафиксированы и прогнаны только 45, а 48 оставлены непрогнанными по бюджетным причинам. Оставшиеся
строки — не более 98 — содержат конструкции вне любой реализованной стадии (исключающее или, эквивалентность, кванторы
по нескольким переменным, равенство, функциональные термы, схемы аксиом) и отчитываются как \texttt{out\_of\_fragment}.

\paragraph{AR-LSAT (L3).} Конечно-доменные ограничения проверяются отдельным решателем. На закодированных вручную реальных
игровых задачах режим эталонного входа даёт 27/27; реальный запуск на разбиении eval — 23/30 (76{,}7\%) без единого
\texttt{grounded\_mismatch}. Семь промахов — честные воздержания, а не уверенно неверные ответы.

\paragraph{GSM8K (L4).} Точная рациональная арифметика делает арифметические ошибки невозможными по построению; неверное
число здесь всегда ошибка \emph{моделирования}, а не счёта. Синтетические проверки — 37/37, закодированный вручную
эталон — 8/8, реальный запуск: разбиение dev — 12/12, разбиение eval — 38/40. Две неверные строки разбиения eval
 — размеченные ошибки эталона: одна ошибка в наборе данных, одна неоднозначность.

\section{Сравнение с Logic-LM и LINC}
\label{sec:comparison}

Формализмы и проверки выше — вклад этой работы. Естественно спросить, как те же задачи решают две наиболее близкие
открытые нейросимволические системы — Logic-LM~\cite{logiclm} и LINC~\cite{linc}. Обе устроены по схеме «переводчик
 + решатель»: языковая модель строит формализацию, символический решатель её решает. Вместо качественного противопоставления
(как в разделе~\ref{sec:related}) мы приводим сравнение \emph{на общем входе} — одни и те же строки задач и одна и та же
языковая модель для всех трёх систем, — а затем разбираем, что именно их разделяет.

\subsection{Протокол}
\label{sec:comparison-protocol}

\paragraph{Входы и модель.} Каждая система получает ровно те же строки, что и в примерах для Ankyra выше, и ту же модель, которую
решатель использует во время запуска: малую и недорогую инструктивную модель (DeepSeek V4 Flash) за OpenAI-совместимой
конечной точкой. Внешние системы не переписывались: их собственные подсказки, символические решатели и процедуры подсчёта
оценок остаются неизменными, их лишь оборачивает тонкий адаптер. Адаптер необходим так как обе библиотеки рассчитаны на устаревший клиент \texttt{openai<1};
адаптер перенаправляет этот клиент на провайдера решателя, подменяет модель и отключает явную цепочку рассуждений — так же,
как это делает сам решатель. Вызовы при температуре~$0$ кэшируются, поэтому запуски воспроизводимы без дополнительных затрат.

\paragraph{Декодирование.} Каждая система запускается в собственном протоколе декодирования, потому что именно к нему относятся её опубликованные числа.
Под сэмплированием здесь понимается многократный запуск LLM на одном и том же входе с получением N вариантов ответа. Оно используется для оценки
устойчивости генерации и для повышения шанса, что хотя бы один вариант пройдёт разбор.

\begin{center}
\small
\begin{tabular}{p{1.7cm}p{6.3cm}p{6.5cm}}
\toprule
\textbf{Система} & \textbf{Декодирование} & \textbf{Почему} \\
\midrule
Ankyra & температура $0{,}1$, один сэмпл, структурированное (tool/JSON) извлечение & так устроен решатель; он не сэмплирует \\
Logic-LM & температура $0$, один сэмпл, плюс её self-refinement & её опубликованный конвейер \\
LINC & 8 примеров, $10$ сэмплов, температура $0{,}8$, голосование большинством & её опубликованный конвейер \\

\end{tabular}
\end{center}

Прогон с согласованным декодированием (все три системы жадные, один сэмпл) приведён в разделе~\ref{sec:comparison-ablations},
чтобы исключить влияние самого протокола на результат.

\paragraph{Метрики.} \emph{Точность решателя} — доля строк, на которые дан верный ответ. При этом и неудачный запуск программы,
и отказ от ответа считаются ошибкой. Это самая строгая из наших метрик, и всюду далее мы используем именно её. \emph{Охват}
 — доля строк, для которых программу удалось запустить. \emph{Точность среди запустившихся} — точность только по тем строкам,
где программа отработала. Уверенно неверные ответы — запустившиеся программы, давшие неверный ответ: внешние системы выдают
такой ответ как окончательный, тогда как Ankyra корректна относительно своей формализации и подобных ответов не порождает.

\paragraph{Область.} Это не воспроизведение и проверка результатов двух статей: в них использовались GPT-3.5/GPT-4 и собственные
разбиения; фиксация строк и модели делает системы сопоставимыми, но меняет все абсолютные числа. Интерес представляет \emph{относительное}
поведение трёх конвейеров на одинаковом входе.

\subsection{Разница — в интерфейсе}
\label{sec:comparison-interface}

Требования к ответу модели у трёх систем разные. Ankyra извлекает данные в JSON-схему через tool/function calling, а детерминированный
алгоритм превращает эту структуру в теорию; соблюдение формата обеспечивается контрактом API, а не подсказкой, поэтому модели нужно
правильно передать лишь \emph{содержание}. Logic-LM требует программу в написанной вручную грамматике
(\texttt{Predicates:/Facts:/Rules:/Query:}, \texttt{:::}, \texttt{\$x}), которую читает чувствительный к синтаксису парсер. LINC требует
каркас \texttt{TEXT:/FOL:} и исполняет извлечённые формулы; каркас достаточно прост, чтобы несколько из десяти сэмплов обычно оказались
валидными, — поэтому её сэмплирование так важно (раздел~\ref{sec:comparison-ablations}). Центральный вывод: при малой и недорогой модели
связывающим ограничением оказывается \emph{интерфейс перевода}, а не рассуждение: Ankyra почти не чувствительна к особенностям форматирования,
которые выбирает модель, конвейеры на свободном тексте — легко могут ломаться.

\subsection{Чувствительность к модели}
\label{sec:comparison-model}

Чтобы понять, сколько в результате даёт сама LLM, а сколько — устройство конвейера, мы сравнили собственный тестовый набор ProofWriter из
LINC на её же коде и протоколе на фиксированной подвыборке из 60 строк (каждая шестая строка). Наш запуск — только столбец DeepSeek.
Значения GPT-4 и GPT-3.5 \emph{не} являются запусками этой работы: они пересчитаны из генераций, закоммиченных авторами LINC в их
репозиторий, конфигурация которых (8 примеров, десять сэмплов, температура $0{,}8$) совпадает с использованным нами протоколом, а
эталонные метки совпадают построчно с нашими. Сравнение, таким образом, — это сравнение режимов моделей на одной задаче и конфигурации,
а не три запуска, выполненных здесь.

\subsection{Контрольные прогоны декодирования}
\label{sec:comparison-ablations}

\paragraph{LINC: один прогон против родного протокола.} На тех же строках и задачах переход LINC к её родному протоколу поднимает FOLIO с $34{,}5\%$ до $74{,}1\%$,
а ProofWriter уровня A — с $22{,}2\%$ до $86{,}7\%$. Устойчивость LINC в существенной мере обеспечивается её шагом сэмплирования и голосования;
приводить только жадное значение было бы введением в заблуждение.

\paragraph{Logic-LM: best-of-$N$.} Logic-LM не сэмплирует. Как контроль, пять сэмплов на строку при температуре $0{,}8$ на ProofWriter уровня A
дали \emph{ноль} исполнимых программ из $225$ (жадный запуск дал $6$ из $45$). Более высокая температура ухудшает соблюдение её грамматики,
а не улучшает его, поэтому сэмплирование не объясняет разного поведения двух систем.

\paragraph{Logic-LM: self-refinement.} Её собственный refinement, реализованный только для решателей Prover9 и z3, примерно утраивает охват FOLIO
(с $6{,}9\%$ до $55{,}2\%$), поднимает точность решателя на FOLIO с $6{,}9\%$ до $39{,}7\%$ и на AR-LSAT с $53{,}3\%$ до $63{,}3\%$, но и вводит
уверенно неверные ответы на FOLIO (с $0$ до $9$).

\subsection{Что не запускается и почему}
\label{sec:comparison-notrun}

Сравнение ограничено кодом оцениваемых систем, а не основано на произвольном выборе. Реестр задач LINC содержит только FOLIO и ProofWriter, поэтому её нельзя запустить
на ProntoQA, AR-LSAT или GSM8K; у Logic-LM нет возможности запуска на GSM8K. Self-refinement Logic-LM существует только для Prover9 и z3 — в каталоге её
подсказок лежат лишь \texttt{self-correct-AR-LSAT.txt} и \texttt{self-correct-FOLIO.txt}, а список исполнителей перечисляет только эти два
решателя, — поэтому для её наборов на PyKE (ProofWriter, ProntoQA) запускать нечего. Способность каждого конкретного решателя всё же
измерена — эталонными прогонами выше, намеренно и без модели. Стадия L4 (арифметика) и ProntoQA-OOD не имеют аналога ни в одной из систем
и остаются вне области.

\subsection{Оговорки}
\label{sec:comparison-caveats}

Числа Ankyra взяты из зафиксированных проверок и реальных трасс запусков, но не перезапускались в тот же день, что и внешние системы; одна трасса
уровня A ProofWriter — отказ извлечения с пустым вопросом (изменчивость поставщика), поэтому сохранённые трассы дают $44/45$ против
принятой проверки $45/45$. Уровень D у LINC — жадный, а не родной, то есть нижняя оценка. Недетерминизм поставщика сохраняется даже
при температуре~$0$; приводятся однократные запуски, как и везде в этой работе. Наконец, сравнение сквозное — подсказка, декодирование,
парсер и решатель вместе, — это все дает правильное представление о том, насколько хорошо метод превращает малую модель в корректный ответ.

\section{Ограничения}
\label{sec:limitations}

\paragraph{Размер выборки и статистика.} Каждое число на реальной коллекции опирается на малую выборку
(N = 13, 30, 40, 42, 44, 300), поэтому доверительные интервалы широки (таблица~\ref{tab:results});
на малых срезах они перекрываются с правдоподобными базовыми уровнями и не позволяют претендовать на
передовой уровень. Чтобы обнаружить разницу около пяти процентных пунктов при $p\approx0{,}95$
с мощностью $0{,}8$, нужно порядка $400$ примеров на группу.

\paragraph{Однократность запусков и недетерминизм.} Реальный путь обращается к языковой модели, поставщик
которой недетерминирован даже при нулевой температуре. Запуски выполняются один раз (по бюджетным соображениям)
и повторяются лишь при расхождении, поэтому мы не приводим оценку дисперсии и не выполняем проверку значимости.

\paragraph{Подвыборки, а не полные тестовые выборки.} Мы оцениваем зафиксированные подвыборки: ProntoQA-OOD,
уровень a (42 из 5\,800), AR-LSAT eval (30 из $\sim$230), GSM8K eval (40 из $\sim$1\,319), ProofWriter,
уровень D (300 из 6\,368 теорий). Полные коллекции не запускались, потому что бесплатного доступа к
языковой модели нет, а запуски оплачиваются автором из собственных средств; это осознанная граница
исследования, а не скрытый провал.

\paragraph{Корректность относительна формализации.} Решатель корректен \emph{относительно} теории, которую
ему передали; перевод естественного языка в эту теорию выполняет языковая модель. Поэтому ошибка извлечения
может дать \emph{воздержание} или, в принципе, ответ \texttt{proven} о неверной формализации. Мы измеряем
отсутствие уверенно неверных выводов (ноль на каждом отчитанном срезе) и снижаем риски извлечения проверкой
дословности цитат, защитой от цитирования условных утверждений, защитой от опровержения на основе гипотез и
контролем объявления предметной области. Это не доказательство истинности от начала до конца относительно
реального мира.

\paragraph{У составной коллекции нет единого итогового показателя.} Для FOLIO полный охват коллекции недостижим
по построению: равенство, функциональные термы, исключающее или, эквивалентность, кванторы по нескольким
переменным и схемы аксиом лежат вне любой реализованной стадии, а полная выводимость в логике первого порядка
лишь полуразрешима. Поэтому мы приводим стратифицированные срезы и явный счётчик \texttt{out\_of\_fragment},
а не оценку по всей коллекции.

\paragraph{Сравнение с опубликованными результатами.} Раздел~\ref{sec:comparison} действительно проводит сравнение
на общем входе, но не с \emph{опубликованными} числами: опубликованные значения получены на других коллекциях,
разбиениях, протоколах и моделях, поэтому точности из разных работ по-прежнему не сравнимы напрямую. Сравнение —
с выпущенными системами, перезапущенными на одинаковых входах и одной модели; вклад остаётся доводом о корректности,
проверяемости и устойчивости к модели перевода, а точность — поддерживающим свидетельством.

\paragraph{Изменчивость модели и поставщика.} Числа привязаны к поставщику извлечения на момент запуска; другая
или обновлённая модель изменит столбцы текстового входа. Столбцы эталонного входа и синтетические проверки не
зависят от модели.

\paragraph{Умолчания.} Отчитана только синтетическая проверка; реальная коллекция отменяемых рассуждений
(defeasible) и вывода на естественном языке (NLI) остаётся темой будущей работы.

\section{Связанные работы}
\label{sec:related}

\paragraph{Карта области.} Систематический обзор 2026 года~\cite{survey2026} (178 работ, 2020--2025) выделяет четыре
устойчивых паттерна нейросимволической интеграции: последовательный каскад, символический валидатор, символический
планировщик с нейронным исполнителем и дифференцируемое объединение. Ankyra ближе всего к последовательному каскаду
с ограниченным циклом, но отличается от него двумя вещами: протоколом предложений, при котором каждое утверждение
входит в теорию только с цитатой или пометкой допущения, и объявленным фрагментом, при котором несовпадение требуемой
и доступной логики даёт честный \texttt{out\_of\_fragment}, а не скрытый переход к более слабой процедуре. Тот же
обзор отмечает, что мета-когнитивные способности — мониторинг собственных выводов, распознавание нехватки знаний,
переключение режимов — встречаются лишь в $5\%$ работ; \texttt{out\_of\_fragment} и \texttt{proven\_under(H)}
можно рассматривать как вклад именно в эту нишу.

Ближайшая по духу система — \emph{Autonomous Trustworthy Agents} (ATA)~\cite{ata}: она также добивается детерминизма
и проверяемости, но достигает этого \emph{полным выносом} LLM за пределы runtime (LLM строит базу знаний офлайн,
онлайн работает только символический решатель). Ankyra сохраняет LLM в цикле, ограничивая его протоколом; это
принципиально разные точки на одном спектре. Тот же подход к верификации регуляторных документов через SMT-солвер
описан в~\cite{nsc}.

\paragraph{Рассуждения языковых моделей без сертификата.} Цепочка рассуждений (chain-of-thought)~\cite{cot} и
самосогласованность (self-consistency)~\cite{selfconsistency} показывают, что пошаговое порождение текста
улучшает ответы языковых моделей. Однако такие цепочки не сертифицированы: шаг, выглядящий правдоподобно,
может быть неверным, а у ответа нет ни истории вывода, ни различения «доказано» и «правдоподобно». Ankyra
устраняет именно этот пробел: рассуждение порождает модель, но выводимость проверяет и удостоверяет
символический решатель.

\paragraph{Языковая модель и символический решатель.} Конвейеры вида «переводчик + решатель» (Logic-LM~\cite{logiclm},
LINC~\cite{linc}) также передают рассуждение символическому решателю, но доверяют переводу целиком: если
формализация неверна, неверно и заключение. Здесь граница строже: каждое утверждение входит в теорию только
с дословной цитатой или явной пометкой допущения, обоснованность ответа выводится из его посылок
(\texttt{proven} против \texttt{proven\_under}), а несовпадение требуемой и доступной логики даёт
честный \texttt{out\_of\_fragment}, а не скрытый переход к более слабой процедуре. Раздел~\ref{sec:comparison}
перезапускает обе системы на одинаковых входах и одной модели: их решатели корректны и состоятельны (эталонный
вход даёт $81$--$93\%$ на FOLIO), но как конвейеры на свободном тексте они чувствительны к оформлению вывода малой
модели, тогда как структурированный интерфейс Ankyra — нет.

\paragraph{Коллекции как этапные проверки.} Мы используем стандартные коллекции — ProofWriter~\cite{proofwriter},
ProntoQA~\cite{prontoqa} и ProntoQA-OOD~\cite{prontoqaood}, FOLIO~\cite{folio}, AR-LSAT~\cite{arlsat},
GSM8K~\cite{gsm8k} — не как единый итоговый показатель,
а как этапные проверки отдельных стадий, каждая со своей семантикой. Для составных коллекций (FOLIO)
мы выделяем внутрифрагментные срезы и отдельно отчитываем \texttt{out\_of\_fragment}; единый балл
по коллекции со смешанными конструкциями недостижим по построению.

\paragraph{Немонотонные рассуждения и умолчания.} Логика умолчаний~\cite{reiter} и
циркумскрипция~\cite{mccarthy} формализуют отменяемость выводов; Ankyra реализует слой умолчаний со
специфичностью через \texttt{is\_a} и честно сообщает о неразрешённом конфликте, не угадывая победителя.
Философская рамка (doxa/logos) и семейство операторов взаимодействия изложены в сопутствующей работе~\cite{doxa};
здесь мы сосредоточены на системе, реализующей этот интерфейс.

\paragraph{История вывода и проверяемость.} Опора на автоматически собранную историю вывода сближает
Ankyra с работами о проверяемом выводе. Объяснение здесь — изложение доказательства, а не второе мнение
о нём: модель не вправе добавлять в него факты, а каждый шаг называет сработавшее правило, использованные
связывания и обосновывающую цитату или гипотезу.

\section{Заключение}

Мы представили нейросимволическую систему, в которой языковая модель предлагает, а детерминированный
решатель решает, охватывающую семейство разрешимых формализмов в рамках протокола объявленного фрагмента.
Вклад — не отдельный решатель, а архитектура и дисциплина: протокол предложений, при котором ни одно
утверждение не входит в теорию без цитаты или пометки допущения; обоснованность ответа, никогда не
превышающая обоснованности его посылок; объявленный фрагмент и честное \texttt{out\_of\_fragment}
вместо молчаливого перехода к более слабой логике; и методика этапных проверок составных коллекций,
разделяющая охват метода и потолок извлечения.

На зафиксированных срезах стандартных коллекций система показывает высокую точность, не допуская ни
одного уверенно неверного вывода, и честно воздерживается там, где её логика не может выразить задачу.
Сравнение на общем входе с Logic-LM и LINC показывает, что их символическое рассуждение корректно, но узким
местом при малой модели оказывается интерфейс перевода на свободном тексте, тогда как структурированное
извлечение Ankyra к нему устойчиво; при более сильной модели и родном сэмплировании LINC конкурентна.
Оценка — демонстрационный прототип, а не передовой уровень; ограничения выше определяют границу того,
что поддерживают эти результаты. Естественные направления дальнейшей работы — реальная коллекция
отменяемых рассуждений (defeasible) и NLI, конечные функциональные термы и кванторы по нескольким
переменным (сейчас за пределами фрагмента), а также запуски на полных коллекциях по мере
появления бюджета.

\section{Воспроизведение}
\label{app:repro}

Проверки без участия языковой модели (синтетические наборы и диагностика с эталонным входом) воспроизводимы из репозитория без доступа к языковой модели и без оплаты API:

\begin{verbatim}
uv run python -m evals.routing_synthetic
uv run python -m evals.l1_synthetic
uv run python -m evals.l2_synthetic
uv run python -m evals.l3_synthetic
uv run python -m evals.l4_synthetic
uv run python -m evals.defeasible_synthetic
uv run python -m evals.ar_lsat --gold evals/data/ar_lsat_gold.jsonl
uv run python -m evals.gsm8k --gold evals/data/gsm8k_gold.jsonl
uv run python -m evals.analyze_folio
\end{verbatim}

Запуски с обращением к языковой модели (к платному поставщику извлечения) выполняются один раз и повторяются только при расхождении:

\begin{verbatim}
uv run python -m evals.proofwriter --tier d
uv run python -m evals.prontoqa --tier b
uv run python -m evals.prontoqa_ood --tier a
uv run python -m evals.ar_lsat --sample eval --live
uv run python -m evals.gsm8k --sample eval --live
\end{verbatim}

лежат в \texttt{comparison/}, построчные выходы — в \texttt{comparison/results/}. Офлайн-части (адаптеры,
проверки бэкендов на эталонном входе) не требуют API; реальные части — это записанные там платные запуски.

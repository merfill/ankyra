# План T1 — экзистенциальная цель с общим свидетелем `∃x (A(x) ∧ B(x))`

Статус: **утверждён и реализован** (решения T1-D1a/T1-D2a/T1-D3a). Это первый пункт
бэклога понижения Tier-1 (`docs/coverage_ceiling.md` §6–§7). T1 повышает **охват**
(не извлечение) на FOLIO L2, делая решаемым конструкт, который коммутируемый
клаузальный фрагмент уже способен решить внутренне; согласно `D-FE-3` он
**переиспользует существующую ограниченную клаузальную процедуру** (`ANKYRA_LOGIC`) —
без новой процедуры решения и без новой семантики. Результаты — в §13.

Канонический язык: английский; русское зеркало: `docs/t1_plan_ru.md`, канонический
оригинал — `docs/t1_plan.md`.
Связанное: `docs/coverage_ceiling.md` (упорядоченный бэклог и открытые решения
T-D1…T-D3), `docs/folio_gold_fed.md` (измерение, за которым следует этот пункт),
`docs/l2_plan.md` (процедура, которую расширяет T1), `docs/folio.md` §9–§10,
`docs/fragment_routing.md` (контракт именованного фрагмента),
`docs/reasoning_roadmap.md`, `docs/implementation_plan.md` (§8 пункт 26).

## 1. Цель

Решать конъюнктивный экзистенциальный вывод с **единым общим свидетелем**,
`∃x (g₁(x) ∧ … ∧ gₙ(x))`, внутри коммутируемого клаузального фрагмента над конечной
областью, чтобы золотой (gold-fed) охват FOLIO L2 вырос на строки, чей первый
блокер — эта форма. Измеренный базис (2026-09-22,
`uv run python -m evals.analyze_folio --subset l2`):

|---|---|
| text-fed | 25/45 |
| gold-fed open | 17/45 |
| gold `out_of_fragment` | 24/45 |
| covered (метод) | 17/21 |
| covered (текст) | 15/21 |

Строки FOLIO L2 tier a, чей золотой вывод — конъюнкция с общим свидетелем (найдены

## 2. Текущий блокер

- **Парсер.** `evals/folio_fol.py:_conclusion` отказывает форме сразу, когда более
  одного конъюнкта упоминает квантифицированную переменную:
  `raise FolParseError("existential conclusion with a shared witness is out of
  fragment")` (`evals/folio_fol.py:346–347`), поэтому строка — `out_of_fragment`.
- **IR.** `Query.goals` + `goal_mode` не выражают «один свидетель для всех
  конъюнктов». `goal_mode="all"` решает каждую цель **независимо**
  (`verify._goal_outcome` вызывает `_l2_outcome` по цели, каждую со своим перебором
  свидетелей), т.е. реализует `(∃x g₁) ∧ … ∧ (∃x gₙ)` — слабее, чем
  `∃x (g₁ ∧ … ∧ gₙ)`. Поэтому форму отвергают, а не решают молча.
- **Билдер/извлечение уже способны её выразить.** `QuestionStructure.ask_all`
  компилируется в `Query.goals` + `goal_mode="all"` (`build/unroll.py:396–404`); атомы
  могут нести общий `?x`. Значит, для гейта метода изменение схемы не требуется.

## 3. Объём и не-цели

**В объёме.**
- `∃x (g₁(x) ∧ … ∧ gₙ(x))`: каждый `gᵢ` — литерал (заземлённый или над общей
  переменной/переменными), с **общим** свидетелем; конечная именованная область.
- Положительное направление (выводимость), отрицательное (опровержение), честные
  `unknown` и `budget`.
- Парсер gold-fed и LLM-free синтетический гейт.

**Вне объёма (без изменений, по-прежнему `out_of_fragment`).**
- Функциональные термы, вложенные кванторы, `∃` под `∀`.
- `¬∃`, универсальная/условная форма цели → **T3**.
- Экзистенциальная **посылка** с вложенной дизъюнкцией → **T2**.
- Заземление только по голове `∀x (A(x) ∨ B(x))` → **T5**.
- Формулировка **живого** извлечения для «есть ли x, который и … и …?» — это трек
  извлечения (G1–G4), не гейт метода T1.
- Никакого нового флага и новой настройки `.env`: capability — существующий `clausal`
  (`ANKYRA_LOGIC`, по умолчанию off).
- Никаких NL-эвристик и подгонки под id (`docs/task.md` §3.8;
  `docs/coverage_ceiling.md` §8).

## 4. Конструкт и его решение

### 4.1 Прочтение

`∃x (g₁(x) ∧ … ∧ gₙ(x))` читается **классически** над конечной областью `D`, которую
уже предполагает процедура заземления (пул объектов теории ∪ Skolem-константы ∪
константы вывода; та же позиция замыкания области, что и у перебора свидетелей,
`verify._witness_pool`). При открытом мире «не доказано» никогда не значит «ложно»:
`D` — это универсум **именованных** индивидов, к которым задача обязалась.

### 4.2 Процедура решения (переиспользует ограниченную резолюцию)

Собрать переменные целей `V`; пусть `D` — пул. Перебрать подстановки
`σ: V → D` (`|D|^|V|`). Для каждой `σ` заземлить каждую цель `gᵢσ`:

- **proved(σ)** — `T ∪ Γ ⊢ gᵢσ` для всех `i`, каждое — наземной резолюцией
  (`refute(clausification, literal_of(gᵢσ))`).
- **refuted(σ)** — `T ∪ Γ ⊨ ¬(g₁σ ∧ … ∧ gₙσ)`, проверяется допущением каждого
  конъюнкта отдельной единичной клаузой и выводом пустой клаузы (`refute_conjunction`
  в `engine/resolution.py`): допущенные единицы `{g₁σ},…,{gₙσ}` совместно
  невыполнимы. (Вариант «допустить остальные конъюнкты, опровергая первый» отброшен:
  базовая теория становится невыполнимой, что ломает полноту set-of-support.)
- иначе **open(σ)**.

Затем:

| исход группы | условие | статус вердикта |
|---|---|---|
| `supported` | некоторая σ доказана | `supported` (сообщить привязку) |
| `refuted` | все σ опровергнуты | `refuted` |
| `budget` | нет вердикта выше и какое-то решение исчерпало бюджет шагов | `insufficient` + `logic_budget:` |
| `unknown` | ни одна σ не доказана и какая-то σ открыта | `insufficient`/`unsupported` |

Частный случай `V = ∅` (заземлённая конъюнкция): одна пустая σ; **proved** тогда и
только тогда, когда все выводимы (существующая поддержка `all`), **refuted** — когда
конъюнкция невыполнима. Для одной цели процедура вырождается в сегодняшний путь
`single`.

### 4.3 Почему это корректно и общее

- **Общий, а не независимый.** Требование одной σ для всех конъюнктов — это ровно
  `∃x` (прочтение, которое сейчас отвергается); независимое прочтение — строго более
  слабая переаппроксимация и есть тот баг, от которого защищался парсер.
- **Обобщение безопасно.** Для целей с **разными** переменными совместный перебор есть
  `∏ (∃xᵢ gᵢ)` — логически равно текущей независимой обработке; для **заземлённых**
  целей пустая σ сводится к сегодняшнему поведению. Так `goal_mode="all"` становится
  единообразно «конъюнктивным запросом с экзистенциальными переменными» без
  регрессии в существующих случаях.
- **Опровержение достаточно полное для строк False.** `∀x (A(x) → ¬B(x))` (строка
  0058) опровергает `∃x (A∧B)` по каждому свидетелю, хотя ни `∀x ¬A`, ни `∀x ¬B` не
  выполняются — старое правило «опровергнут любой конъюнкт» воздержалось бы.
  Совместная проверка не добавляет несостоятельности: выводится пустая клауза.
- **Ограниченность.** Рост свидетелей — `|D|^|V|`; бюджет шагов явный, а исчерпание —
  честный `budget`.

## 5. Решения (все три DECIDED — вариант (a))

- **T1-D1 — Представление.** (a) Обобщить `goal_mode="all"` до совместного прочтения
  (рекомендуется): нового поля нет, переменная уже в целях, случаи с разными
  переменными и заземлённый не меняются. (b) Добавить новый режим/поле
  (`goal_mode="witness"` или `Query.witness`): явнее, но второе представление и более
  широкое изменение `Query`, диспетчеризации `builtin`/Horn и цикла предложений без
  прироста выразительности. **DECIDED (a).**
- **T1-D2 — Опровержение для заземлённых конъюнкций.** (a) Использовать совместную
  проверку невыполнимости для всех `all` (рекомендуется; нужно для 0058, корректно,
  полнее). (b) Оставить «опровергнут, если опровергнут какой-то конъюнкт» для
  заземлённых целей и применять совместную проверку лишь при наличии переменных
  (меньше поведенческое изменение, но две семантики у одного режима).
  **DECIDED (a)**; регрессионный повторный замер подтвердил это (§9).
- **T1-D3 — Именование фрагмента** (связано с `T-D3`). (a) Добавить производный
  `shared_witness` `FragmentFeature` (`goal_mode` `all` с переменной), отображённый в
  клаузальный фрагмент (рекомендуется): аудируемое имя, место для негативного
  контроля маршрутизации, новый capability/флаг не нужен. (b) Переиспользовать
  `compound_goal` без нового признака. **DECIDED (a).**

## 6. Изменения движка (`src/ankyra/engine/`)

- **`verify.py`.** Добавить совместное решение конъюнкции для `goal_mode="all"`:
  `_conjunctive_outcome(clausification, goals, pool)` → `(outcome, binding, target,
  complement)`, перебирающее σ и применяющее §4.2. Связать `l2_outcomes` так, чтобы
  запрос `all` давал один исход группы; пробросить привязку выигравшего свидетеля в
  `verdict.bindings`. Пути `single` и `any` не трогаются (`any` уже корректен:
  `∃x(A∨B) ≡ ∃xA ∨ ∃xB`).
- **`resolution.py`.** Обобщить процедуру: `refute_support(clausification, assumed)`
  заполняет set-of-support из **списка** допущенных клауз (одна единица для литеральной
  цели; по единице на конъюнкт для конъюнкции). `refute` — обёртка для одного литерала,
  `refute_conjunction` — отрицательная проверка T1; новой семантики нет.
  (`Clausification.with_units` рассматривался и отброшен — многоединичный support и есть
  чистая, полная форма.)
- **`explain.py`.** Для поддержанной группы рендерить объединение резолюционных
  доказательств по каждому конъюнкту для выигравшего свидетеля (`MergedProof`,
  разворачивается в `_l2_steps`); метка цели — конъюнктивная цель, привязка —
  свидетель. Refuted/unknown рендерятся пусто.
- **`inference.py`.** Добавить производный признак `shared_witness` (T1-D3) в
  `_fragment`; `compound_goal` уже отображается в клаузальную процедуру, поэтому
  `analyze_routing` даёт `clausal` через существующий capability. Нового кода отказа и
  нового флага нет.
- **`answer.py`.** Изменений не требуется: при `answer_type="open"` привязка берётся из
  `verdict.bindings` (`answer.py:136–139`). Замечание: `build_answer` считает силу с
  гипотезами через Horn `winning_proof`, который равен `None` для не-Horn L2
  доказательства; это существующее ограничение, вне объёма T1.

## 7. Парсер gold-fed (`evals/folio_fol.py`)

В `_conclusion` заменить отказ общего свидетеля (`folio_fol.py:346–347`) на плоскую
конструкцию `all`, уже используемую для заземлённой конъюнкции: `goals` — все
конъюнкты, `goal_mode="all"`, квантифицированная переменная остаётся в морфизмах.
Совместная семантика движка (T1-D1a) делает одно и то же представление корректным и
для общего свидетеля, и для заземлённого случая. Нового поля схемы нет. Вложенные
кванторы и нелитеральные тела по-прежнему бросают `FolParseError`.

Извлечение (`build/extract.py`, `build/unroll.py`) уже поддерживает `ask_all` с
переменными; изменение промпта не входит в гейт метода T1.

## 8. Синтетический гейт (`evals/l2_synthetic`)

Добавить механизм `shared_witness` в `evals/build_l2_synthetic.py` с обязательными
контролями:

| кейс | теория / цель | ожидание |
|---|---|---|
| `shared-witness-01` | один `x` — и `p`, и `q`; цель `∃x(p(x)∧q(x))` | `supported`, привязка |
| `shared-witness-02` | `p(a)`, `q(b)`, `a≠b`; цель `∃x(p(x)∧q(x))` | `insufficient` (ловушка: старое независимое прочтение сказало бы yes) |
| `shared-witness-03` | `p(a), p(b)`, правило `p(?x) → ¬q(?x)`; цель `∃x(p(x)∧q(x))` | `refuted` (совместная невыполнимость по свидетелю) |
| `shared-witness-04` | только `p(a)`; цель `∃x(p(x)∧q(x))` | `insufficient` |
| `shared-witness-05` | цепочка свидетеля в 2 шага, принудительный `LOGIC_BUDGET=1` | `insufficient`, никогда proven |
| `shared-witness-06` | та же цель при `logic="off"` | `out_of_fragment:compound_goal` |

Плюс кейс в `routing_synthetic`, утверждающий, что признак `shared_witness` маршрутизуется
в `clausal` при включённом `ANKYRA_LOGIC`.

## 10. Риски

- **Поведенческое изменение опровержения заземлённого `all`** (T1-D2a) затрагивает
  заземлённые составные цели FOLIO и существующие синтетические кейсы; проверка —
  регрессия и повторный gold-fed замер. Если это стоит корректной строки — откат к
  T1-D2b.
- **Стоимость.** `|D|^|V|` свидетелей × n конъюнктов × резолюция. Области FOLIO L2
  малы; бюджет ограничивает, исчерпание — `insufficient`, никогда не догадка.
- **Замыкание области.** Перебор по именованному пулу трактует его как универсум (уже
  позиция движка); индивид, названный только в выводе, попадает в пул через
  `_object_names`.
- **Достоверность объяснения.** У поддержки группы n поддоказательств; объединение всё
  равно должно отображать каждый шаг в реальное ребро резолюции (без выдуманных шагов).
- Никакого полного живого прогона FOLIO без отдельного бюджетированного решения
  (`docs/reasoning_roadmap.md` §4).

# План T3 — универсальная / условная / `¬∃` форма цели

Статус: **утверждён и реализован** (решения T3-D1a…T3-D4a). Это третий пункт
бэклога понижения Tier-1 (`docs/coverage_ceiling.md` §6–§7). T3 повышает **охват** (не
извлечение) на FOLIO L2, делая решаемой **универсально квантифицированную клаузальную
цель** — `∀x (l₁(x) ∨ … ∨ lₙ(x))`, которая покрывает `∀x (A(x) → B(x))`, `¬∃x φ(x)` и
`∀x (A(x) ∨ B(x))`. Согласно `D-FE-3` он **переиспользует существующую ограниченную
клаузальную процедуру** (`ANKYRA_LOGIC`) и конъюнктивное опровержение из T1: без новой
процедуры решения и без новой семантики. Результаты — в §13.

Канонический язык: английский; русское зеркало: `docs/t3_plan_ru.md`, канонический
оригинал — `docs/t3_plan.md`.
Связанное: `docs/coverage_ceiling.md` (упорядоченный бэклог и открытые решения
T-D1…T-D3), `docs/t1_plan.md` (цель с общим свидетелем, которую T3 зеркалит),
`docs/folio.md` (§9–§10), `docs/folio_gold_fed.md` (измерение, за которым следует
этот пункт), `docs/l2_plan.md` (процедура, которую расширяет T3),
`docs/fragment_routing.md` (контракт именованного фрагмента),
`docs/reasoning_roadmap.md`, `docs/implementation_plan.md` (§8 пункт 26).

## 1. Цель

Решать универсально квантифицированную клаузальную цель внутри коммутируемого
клаузального фрагмента над конечной областью, чтобы золотой (gold-fed) охват FOLIO L2
вырос на строки, чей первый блокер — эта форма. Измеренный базис (2026-09-22, после
T1, `uv run python -m evals.analyze_folio --subset l2`):

| источник вердикта | верно |
|---|---|
| text-fed | 25/45 |
| gold-fed open | 21/45 |
| gold `out_of_fragment` | 20/45 |
| covered (метод) | 21/25 |
| covered (текст) | 17/25 |

Строки FOLIO L2 tier a, чей первый блокер — универсальный/`¬∃` вывод (найдены
инспекцией `evals/data/folio_l2_tier_a.jsonl`):

| id | метка | вывод |
|---|---|---|
| folio-validation-0045 | Uncertain | `∀x (Pet(x) → ¬Cat(x))` («ни один питомец не кот») |
| folio-validation-0107 | False | `¬(∃x (FinancialAid(x)))` |

`docs/coverage_ceiling.md` считает **2** первых блокера для T3; повторный замер после
изменения даст точную дельту охвата и корректности.

**Не T3.** `folio-validation-0007` (`Uncertain`, `∀x (Human(x) → ¬Flu(x))`) — тоже
универсальная цель, но его первый блокер — **посылка**
`∃x (GetMonkeypox(x) ∧ (Fever(x) ∨ …))`, экзистенциал с вложенной дизъюнкцией →
**T2** (`docs/coverage_ceiling.md` §3b). Он остаётся `out_of_fragment` до T2.

## 2. Текущий блокер

- **Парсер.** `evals/folio_fol.py:_conclusion` отказывает `∀`-выводу сразу
  (`raise FolParseError("universal conclusion has no goal form (L2 target form
  pending)")`, `evals/folio_fol.py:331–332`). `¬(∃x …)` по NNF нормализуется в `∀` и
  затем попадает в
  `raise FolParseError("compound conclusion is not a flat conjunction/disjunction")`
  (`evals/folio_fol.py:356`). Обе строки — `out_of_fragment`.
- **IR.** `Query.goals` + `goal_mode` не выражают универсальную клаузу. `goal_mode` —
  это `single | all | any` (`core/models.py:25`): `all` решает каждый конъюнкт
  **независимо** со своим свидетелем (`verify._conjunctive_outcome`), `any` — это
  дизъюнкция независимо доказанных литералов. Ни то, ни другое не есть
  `∀x(l₁ ∨ … ∨ lₙ)`.
- **Положительное направление — не перебор конечного пула.** Доказывать `∀`, проверяя
  только именованных индивидов, **несостоятельно** (см. §4.3): маленький пул делает
  необщезначимый универсал «вакуумно истинным». T3 обязан ввести свежую константу для
  положительного направления.
- **Билдер для method-гейта не нужен.** T3 решается по структурному `Query`; живая
  формулировка извлечения «все … являются …» — это трек извлечения (G1–G4), а не
  method-гейт T3 (как и в T1).

## 3. Объём и не-цели

**В объёме.**
- Универсальная **клауза** `∀x (l₁(x) ∨ … ∨ lₙ(x))` над **одной** связанной
  переменной, каждый `lᵢ` — литерал (ground или над общей переменной): `∀x(A→B)`,
  `∀x(¬A)`, `∀x(A∨B)`, `∀x(A∧B → C)`.
- Положительное направление (следование) со **свежей константой**; отрицательное
  (опровержение) именованным свидетелем; честные `unknown` и `budget`.
- Парсер gold-fed и LLM-free синтетический гейт.

**Вне объёма (без изменений, по-прежнему `out_of_fragment`).**
- Вложенные кванторы (`∀x∀y`, `∃` под `∀`), свободная переменная помимо связанной,
  функциональные термы.
- Не-клаузальное тело: `∀x (A(x) ∧ B(x))` — не клауза и остаётся отвергнутым.
- Неплоская **условная/составная цель** (`A∨B → C∨D`, `Cute ∧ Still → Turtle ∧
  Skittish`) → **T4**. **Ground**-условная (`Cow(ted) → ¬Pet(ted)`) уже разбирается как
  плоская `any`-цель и не меняется.
- Экзистенциальная **посылка** с вложенной дизъюнкцией → **T2**.
- Grounding только по голове `∀x (A(x) ∨ B(x))` как **посылка** → **T5**.
- **Живая** формулировка извлечения для универсального вопроса — трек извлечения
  (G1–G4), а не method-гейт T3.
- Без нового флага и новой настройки `.env`: capability — существующий `clausal`
  (`ANKYRA_LOGIC`, по умолчанию off); новый `universal_goal` — производный
  `FragmentFeature`, а не процедура.
- Без NL-эвристик и подгонки под id (`docs/task.md` §3.8;
  `docs/coverage_ceiling.md` §8).

## 4. Конструкт и его решение

### 4.1 Прочтение

`∀x (l₁(x) ∨ … ∨ lₙ(x))` читается классически над коммутируемой конечной областью, но
**положительное** направление читается как настоящий универсал, а не по именованному
пулу: `D` — это универсум именованных индивидов **плюс произвольный свежий индивид**.
Это та же позиция замыкания области, которую процедура уже занимает для ground-инстансов
правил, расширенная константой обобщения (§4.3).

### 4.2 Процедура решения (переиспользование ограниченного резолюционного вывода)

Пусть `uf` — **свежая константа** (нет ни в одной клаузе теории), и `clausify` размножает
правила теории по именованному пулу **∪ {uf}**. Цель решается так:

- **supported** — `T ⊨ ∀x (l₁ ∨ … ∨ lₙ)`. Предполагаем отрицание клаузы на свежей
  константе, `{¬l₁(uf)}, …, {¬lₙ(uf)}`, и выводим пустую клаузу (`refute_conjunction`,
  `engine/resolution.py`). По обобщению над свежим `uf`, пустая клауза означает, что
  `T ∪ {⋀¬lᵢ(uf)}` невыполнимо, значит `T ⊨ ⋀lᵢ`-как-клауза для произвольного индивида,
  т.е. `T ⊨ ∀x(l₁ ∨ … ∨ lₙ)`.
- **refuted** — `T ⊨ ¬∀x(l₁ ∨ … ∨ lₙ) = ∃x (⋀¬lᵢ)`. По конечному именованному пулу
  находим свидетеля `d`, для которого `T ⊨ ¬lᵢ(d)` для **каждого** `i` (каждое через
  `refute(lᵢ(d))` → `entailed`); опровержения объединяются в одно доказательство
  отрицания цели.
- иначе **unknown**; решение, исчерпавшее бюджет шагов, — **budget** (`insufficient`,
  никогда не доказательство).

Особые случаи. Для одного литерала (`¬∃x φ` = `∀x ¬φ`) положительная проверка — это
`refute(φ(uf))`. Ground-клауза (`V = ∅`) сводится к существующему поведению
`single`/`any` и не является целью T3.

### 4.3 Почему это состоятельно и обще

- **Положительное направление состоятельно.** `uf` не встречается ни в одной клаузе
  теории, поэтому `T ⊨ cl(uf)` влечёт `T ⊨ ∀x cl(x)`; свежая константа — это ровно
  обобщение. Вывод пустой клаузы из предположенных `¬lᵢ(uf)` записывает только реальные
  резолюционные рёбра.
- **Наивная альтернатива несостоятельна и отвергнута.** Доказывать `∀`, требуя
  невыполнимость конъюнкции `⋀¬lᵢ` **только для каждого именованного индивида**, даёт
  ложное `supported` на маленьком пуле: `A(rex), B(rex) ⊢ ∀x(A→B)` было бы «доказано»,
  хотя безымянный индивид может его нарушить. Поэтому T3-D2(a) вводит `uf`.
- **Отрицательное направление состоятельно.** Именованный свидетель `d` со всеми
  выводимыми `¬lᵢ(d)` есть доказательство `∃x⋀¬lᵢ`, а значит `¬∀x(l₁∨…∨lₙ)`; для
  опровержения безымянный индивид не нужен.
- **Переиспользование T1.** `refute_conjunction` — это ровно отрицательная проверка
  T1; объединённое доказательство, обработка бюджета и рендеринг истории вывода общие.
- **Ограниченность.** Одна свежая константа, один резолюционный поиск на направление,
  явный бюджет шагов; исчерпание — честный `budget`.

## 5. Решения по устройству (все DECIDED — вариант (a))

- **T3-D1 — Представление.** (a) Новый `goal_mode="forall"`; `Query.goals` хранит
  литералы клаузы `l₁…lₙ`, а `Query.target = goals[0]` (чтобы `answer`/`explain` видели
  цель). Без дерева goal-формул (D-L2-7 сохраняется). (b) Переиспользовать `all` с
  негативными литералами и полем полярности: второе представление того же конструкта и
  более широкое изменение `Query`. **DECIDED (a).**
- **T3-D2 — Положительное направление.** (a) Свежая константа `uf` добавляется в
  ground-пул, затем `refute_conjunction` по негативным литералам клаузы (состоятельное
  обобщение; §4.3). (b) Перебирать только именованный пул и требовать, чтобы все
  свидетели удовлетворяли, — **несостоятельно**, вакуумно истинно на малой области.
  **DECIDED (a)**; (b) зафиксирован как отвергнутая альтернатива.
- **T3-D3 — Именование фрагмента.** (a) Добавить производный `FragmentFeature`
  `universal_goal` (`goal_mode == "forall"`), отображаемый в клаузальный фрагмент (он
  всегда сопутствует `compound_goal`, который уже выбирает `clausal`): аудируемое имя и
  место для routing-негатив-контроля, без нового capability/флага. (b) Переиспользовать
  `compound_goal` и не добавлять фичу. **DECIDED (a)** (зеркалит T1-D3).
- **T3-D4 — Объём тела.** (a) Ровно одна связанная переменная; тело — **плоская
  дизъюнкция литералов** (нормализуется через NNF). Вложенные кванторы, лишние
  свободные переменные и конъюнкции (`∀x(A∧B)`) остаются `out_of_fragment`.
  (b) Обобщить до произвольной кванторно-связочной структуры — это представление
  goal-*формулы* (`T-D2`/T4), отложено. **DECIDED (a).**
- **T-D3 (один фрагмент или три).** T1/T3 (и позже T4) добавляют каждый **производную
  фичу** и синтетический гейт, разделяя единственный capability `clausal` — шаблон, уже
  заданный T1 (`docs/t1_plan.md` T1-D3). Итого: одна процедура, именованные фрагменты,
  гейт на пункт. **Закрыто** T3-D3(a) + T3-D4(a).

## 7. Парсер gold-fed (`evals/folio_fol.py`)

В `_conclusion` сначала нормализовать через `_nnf`; когда результат — `forall` над одной
переменной, тело которой является **плоской дизъюнкцией литералов** (`_head_literals`),
вернуть `goals = [_morphism(l) …]`, `goal_mode="forall"`, `target = goals[0]`. Убрать
ранний отказ `formula[0] == "forall"` (`evals/folio_fol.py:331–332`). `¬(∃x …)`
обрабатывается автоматически через NNF (становится `forall`). `forall`, тело которого —
конъюнкция, вложенность или более одной/свободная переменная, по-прежнему возбуждает
`FolParseError`. Убрать/поправить устаревшую заметку об объёме в docstring модуля
(`evals/folio_fol.py` строки 14–15, 42–43).

Извлечение (`build/extract.py`, `build/unroll.py`) уже имеет `ask_all`/`ask_any` и для
method-гейта T3 изменений не требует.

## 10. Риски

- **Положительное направление — soundness-чувствительное.** Ошибка, теряющая свежую
  константу или помещающая её в теорию, допустила бы ложное `yes`. Синтетический
  контроль `universal-02` — специальный негативный тест; gold-fed повторный замер
  требует **0 grounded false proofs**.
- **Коллизия свежей константы.** Имя не должно встречаться в теории; `_fresh_constant`
  защитно пропускает существующие имена.
- **Grounding по `uf` — надмножество.** Он добавляет инстансы только универсальных
  правил (состоятельно). Его нельзя использовать, чтобы сузить отрицательное
  направление: refuted — это `∃`, поэтому лишний свидетель ему не мешает.
- **Поведенческое изменение парсера.** Ранний отказ на `∀` исчезает; все прочие формы
  вывода сохраняют существующий путь. Существующий набор тестов парсера — проверка.
- **Стоимость.** Одна лишняя константа умеренно увеличивает ground-набор клауз; бюджет
  ограничивает поиск, исчерпание — `insufficient`, никогда не догадка.
- **Точность объяснения.** Supported-универсал рендерит конъюнктивное опровержение,
  refuted — объединённые доказательства свидетелей. Каждый шаг должен отображаться в
  реальное резолюционное ребро.
- Никакого полного живого прогона FOLIO без отдельного бюджетного решения
  (`docs/reasoning_roadmap.md` §4).

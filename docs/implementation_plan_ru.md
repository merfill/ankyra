# План реализации — Ankyra

> Русская версия для чтения. Каноничный документ — `docs/implementation_plan.md`.

Статус: **черновик**. Архитектура согласована в обсуждении; открытые решения
помечены `OPEN`. Этот документ фиксирует согласованную архитектуру и все
альтернативы, которые нельзя забыть. Техническое задание (`docs/task.md`) будет
приведено в соответствие этому плану после закрытия открытых решений ниже.

## 1. Цель

Домен-независимый гибридный нейро-символический движок рассуждений. LLM
предлагает; детерминированный символический движок классифицирует, выводит и
верифицирует. LLM не владеет истиной: предлагать она может свободно, но каждое
предложение либо лицензировано теорией, либо заземлено цитатой, либо записано как
явная гипотеза.

## 2. Согласованная архитектура

### Фаза 0 — декомпозиция (специальная обработка текста)

Отдельная стадия, выдающая три самостоятельных артефакта и никогда их не смешивающая:

- `theory_structure` — факты и правила, извлечённые из описательной части;
- `question_structure` — цель `phi` (с переменными для «какой/кто/что»), константы
  вопроса и условия `Gamma`, которые вопрос утверждает;
- `answer_type ∈ {yes_no, open, instruction}` (для `instruction` ⇒ `phi = null`).

Жёсткое правило: вопрос никогда не утверждается как факт (эквивалент
`_drop_goal_echo` в OntoLegal). Вопрос выражается словарём теории, когда это
возможно; если выразить нельзя — сохраняется дословно, чтобы верификация честно
сообщила `target_unmatched`.

### Фаза 1 — детерминированное ядро (спина)

- Модель данных: `Object`, `Morphism` (`predicate, subject, object, quote, negated`),
  `Rule` (`conditions` AND → `consequence`), `Theory` (`objects`, `morphisms`
  = аксиомы, `rules`), `Query` (`conditions`, `target`, `variables`).
- `saturate`: прямой вывод до неподвижной точки (полу-наивно), завершается на
  конечном универсуме; каждый выведенный факт несёт историю вывода (`used`, `witness`,
  `rule_index`).
- `unify` / `match_goal`, `complementary` (P ∧ ¬P), транзитивное замыкание
  положительного `is_a`.
- `verify(Theory ∪ Gamma ⊢ phi)` → вердикт со статусом
  `supported | insufficient | unsupported | refuted` и структурированными gap'ами
  (`target_unmatched:`, `condition_unmatched:`, `unused_premise:`, `contradiction:`).
- Этот слой звуков и полон **относительно формализации**. Ему запрещено добавлять
  знание.

### Фаза 2 — направляемый цикл

Внутренняя петля (детерминированная, без LLM): `saturate` до неподвижной точки.
Внешняя волна (LLM), повторяется:

1. `verify(state)` → вердикт + структурированные gaps.
2. Сборка подсказки: структура задачи + словарь теории + достигнутый фронт + gaps +
   цель + правила заземления.
3. Свободное рассуждение LLM → одно типизированное предложение + нарратив.
4. Детерминированная классификация предложения:
   | категория | условие | действие движка |
   |---|---|---|
   | `derivable` | уже выводится | принять только как нарратив |
   | `cited` | новый факт с валидной дословной цитатой | добавить в аксиомы |
   | `hypothesis` | новое правило/факт вне текста | леджер гипотез, метка `H` |
   | `rejected` | схема / safety / цитата не проходят | отбросить с кодом причины |
5. Применить принятые добавления, снова прогнать внутреннюю петлю, перепроверить.
6. Стоп при `supported` / `refuted` / `no_progress` / бюджет / нет достижимой гипотезы.

Рампа свободы (политика, не архитектура): волна 0 разрешающая (свободное
именование предикатов, гипотезы разрешены и помечены); последующие волны
ограничивают — канонизируют имена, требуют переиспользования словаря, при желании
запрещают гипотезы (`ANKYRA_ALLOW_HYPOTHESES=false`).

### Фаза 3 — объяснение

Трассировка строится **механически** из истории вывода (`used`/`witness`). LLM может
только перефразировать готовое дерево вывода; вводить факты она не может. Сила
ответа явная: `proven`, `proven_under(H)` или `not_proven`.

## 3. Инварианты (зафиксированы сейчас, меняются политикой позже)

- **D2.** Ни один факт от LLM не входит в теорию без либо валидной цитаты
  (`cited`), либо явной метки гипотезы (`hypothesis`). Старый ReAct-механизм
  `new_predicates` отвергается полностью.
- **D3.** Монотонность *базы*: она только растёт; цель никогда не ослабляется;
  удаления посылок нет. Сам ответ при дефизбильной семантике может меняться; такие
  изменения фиксируются событиями `Revision` (пункт 11) и никогда — мутацией базы.
  (Оставляем сейчас; позже можно ослабить политикой.)
- **D4.** Сила ответа сообщается всегда (`proven` vs `proven_under(H)`).
- **D5.** Фаза 0 разделяет теорию и вопрос.
- **D6.** Свобода в предложении, детерминизм в классификации.
- **G1.** Одно действие предложения на волну; каждая волна оставляет проверяемый след.
- **Зафиксировано (решение):** леджер гипотез, сила ответа, классификация
  предложений и `Rule.source` — **ядро**, не опция. Режим гипотез по умолчанию —
  разрешающий-с-метками (`ANKYRA_ALLOW_HYPOTHESES=true`); строго-только-цитата —
  переключатель. В силу ответа идут только гипотезы, вошедшие в доказательство.
- **Зафиксировано (решение):** модальность — первоклассное поле
  `Morphism.modality`; имена предикатов по умолчанию без префикса; понижение в
  стиле OntoLegal — за `ANKYRA_DEONTIC_PREFIXES`.
- **Зафиксировано (решение):** оркестрация — LangGraph (`StateGraph`), линейный граф
  с ограниченным циклом рассуждения.

## 4. Примеры как приёмочные тесты

### Пример A — дождь (чистая дедукция, 1 волна, без гипотез)

- Фаза 0: теория = `{raining()}` + правило `R1: raining() => isWet(ground)`;
  вопрос `phi = isWet(ground)`, тип `yes_no`, `Gamma = {}`.
- Волна 0 (только детерминированно): `saturate` срабатывает по `R1`; `verify` →
  `supported`.
- Ожидание: ответ «да», объяснение из истории вывода. LLM в цикле не вызывается.

### Пример B — транспорт (абдукция, N волн, гипотезы)

- Фаза 0: теория = факты `hasEngine(X)`, `wheelCount(X,4)`, `power(X,150)`,
  `doorCount(X,4)`; **правил нет** (правила классов в тексте отсутствуют);
  вопрос `phi = is_a(X, ?c)`, тип `open`.
- Волна 0: замыкание ничего не даёт для `phi`; `verify` → gap `target_unmatched: is_a`.
- LLM предлагает правила классов + иерархию. Цитат из текста у них нет ⇒ категория
  `hypothesis` (`H1`, `H2`, `H3`, `Hh` для `is_a(car, motorVehicle)`,
  `is_a(sedan, car)`).
- Повторное замыкание: `is_a(X, motorVehicle)`, `is_a(X, car)`, `is_a(X, sedan)` +
  транзитивное `is_a`. `match_goal(is_a(X, ?c))` связывает `?c`; «самый специфичный»
  теперь **определён** цепочкой `is_a`, а не угадан.
- Ожидание: «X — седан, **при** H1, H2, H3, Hh». С запретом гипотез — честный
  отказ. Этот пример заодно показывает ключевой факт: правила классов никогда не
  были в исходном тексте.

### Пример C — бриллиант Никсона (неразрешённый дефолтный конфликт)

- Фаза 0: факты `is_a(nixon, quaker)`, `is_a(nixon, republican)`; правила
  `R1: is_a(?x, quaker) => pacifist(?x)` и
  `R2: is_a(?x, republican) => NOT pacifist(?x)`, оба — дефолты (все правила дефолты);
  вопрос `phi = pacifist(nixon)`, тип `yes_no`. `ANKYRA_DEFEASIBLE` включён.
- Строгое замыкание даёт два `is_a`-факта и ни одного `pacifist`. Оба дефолта
  дают кандидатов; между `quaker` и `republican` нет `is_a`, поэтому специфичность
  не определена.
- `verify` → `unsupported` с gap `undecided_conflict:pacifist`; ответ `not_proven`.
- Объяснение: `Explanation.conflict` (`kind = defeasible`, `status = undecided`,
  `defeated = none`) с обоими применениями правил.
- Это граница дефизбильности: равная или несравнимая специфичность никогда не
  угадывается.

### Пример D — пингвин в обе стороны (специфичность + маркер defeasible)

- (а) «Птицы летают. Пингвины — птицы, но пингвины не летают. Твити — пингвин.» →
  `is_a(penguin, bird)` делает правило про пингвинов строго конкретнее: `refuted` с
  `target_refuted:fly`, ответ «нет», `Answer.defeasible = true`.
- (б) «Птицы не летают. Пингвины летают. Твити — пингвин.» → та же специфичность
  выбирает обратную полярность: `supported`, ответ «да», `Answer.defeasible = true`.
- Показывает, что поражение не зависит от полярности, а ответ помечает применение
  дефолта.

### Пример E — строгое противоречие (несогласованная теория)

- «Все собаки — млекопитающие. Рекс — собака. Рекс не млекопитающее. Рекс —
  млекопитающее?» Строгое замыкание выводит `is_a(rex, mammal)` и содержит
  `NOT is_a(rex, mammal)`; пара входит в доказательство цели → `Status.contradiction`,
  ответ `not_proven`, `Explanation.conflict` (`kind = strict`, обе ветки).
- Противоречие, не связанное с целью (`q ∧ ¬q`, вопрос про `p`), — более слабый
  случай: ответ выдаётся штатно, а теория несёт gap `inconsistent_theory:` (решение D-G).

## 5. РЕШЕНО — сравнения / builtins (решение D1)

Статус: **РЕШЕНО** — v0 выходит без builtins; v0.1 добавляет вычислитель.
Кусается на примере B (`power > 50`, `wheelCount >= 4`).

### Вариант A — минимальный range-restricted builtin-вычислитель

- Закрытый набор: `=`, `neq`, `<`, `lte`, `>`, `gte` над числовыми литералами.
- Safety: каждая переменная в builtin-цели должна быть связана более ранним
  положительным реляционным атомом в том же теле правила; иначе правило отвергается.
- Семантика: builtin-атом не сопоставляется с фактами — он *вычисляется*,
  фильтруя подстановки во время унификации.
- Плюсы: пороги/свойства выражаются напрямую; не засоряем леджер гипотез тривиальной
  арифметикой; детерминирован и по-прежнему звуков (builtin вычислим, а не выучен);
  закрывает пример B без гипотез для числовой части.
- Минусы: нужен домен значений (числовые литералы), парсинг чисел, извлечённых из
  текста, и строгое соблюдение range-restriction для завершаемости.

### Вариант B — без builtins; пороги как явные предикаты/гипотезы

- LLM предлагает, например, `powerAbove50(X)` как факт-гипотезу или
  дискретизированный предикат. Всё остаётся Хорновым фактом; домена значений нет.
- Плюсы: движок остаётся тривиальным; никакой новой механики.
- Минусы: леджер заполняется тривиальными числовыми фактами; отображение
  «число → дискретный класс» становится свежей гипотезой каждый раз (плохое
  переиспользование); именно в дискретизации и прячутся ошибки.

### Решение

- **v0:** движок выходит **без** builtins; пример B выражает пороги как
  `hypothesis`. `unify`/`saturate` проектируются с единственной точкой расширения
  (хук `evaluate(builtin_atom, subst)`), чтобы вариант A подключился без переделок.
- **v0.1:** добавить вариант A как первое расширение, в рамках спецификации
  «закрытый набор + safety», за флагом.
- Вариант B держать как задокументированный fallback.

## 6. Прочие открытые вопросы

- **Режим гипотез (РЕШЕНО).** По умолчанию разрешающий-с-метками
  (`ANKYRA_ALLOW_HYPOTHESES=true`); строго-только-цитата — за переключателем.
- **Оркестрация (РЕШЕНО).** LangGraph `StateGraph`, линейный граф с ограниченным
  циклом (раздел 9 в `docs/task_ru.md`). `langgraph` остаётся зависимостью.
- **Поиск (РЕШЕНО — неприменимо).** Ankyra не поисковая система и фрагментов у неё
  нет. Вход — одна самодостаточная задача; движок рассуждает прямо по ней. Слоя
  recall/rerank/выравнивания к фрагменту нет.
- **Деонтическая модальность (РЕШЕНО).** Модальность — первоклассное поле
  `Morphism.modality`; имена предикатов по умолчанию без префикса. Понижение до
  `must_`/`must_not_`/`may_` в стиле OntoLegal живёт за `ANKYRA_DEONTIC_PREFIXES`
  (с polarity fold и фиксом двойного префикса). Вариант A (всегда префикс)
  остаётся задокументированным fallback.

## 7. Вехи (предварительно)

1. Модель данных + схемы извлечения Фазы 0.
2. Детерминированное ядро (saturate / unify / verify / история вывода) + тесты на примере A.
3. Направляемый цикл с леджером гипотез + тесты на примере B.
4. Механическое объяснение из истории вывода; опциональный пересказ LLM.
5. Точка расширения для builtins (вариант A) за флагом.
6. ~~**Связывание открытого запроса и честная недостаточность.**~~ **СДЕЛАНО.**
   `Query.variables` — только декларация неизвестных; связывание даёт унификация
   (`verify`/`explain` больше не подмешивают его в `build_context`); `settle_query`
   не удаляет посылки вопроса, поэтому неиспользованная доходит до `verify` как
   `insufficient`, а цикл считает её терминальной. Исправляет `vehicle`
   (`no_progress` → `supported`/`proven_under`) и `insufficient`
   (`supported` → `insufficient`). См. `quality_findings` A4/B7.
7. ~~**Харнесс публичного бенчмарка (ProofWriter).**~~ **СДЕЛАНО.** Закоммиченная
   выборка Tier A (45 задач синтетического ядра OWA, глубины 0/1/2/3/5), собирается
   детерминированно через `evals.build_proofwriter_sample`; `evals.proofwriter`
   маппит True/False/Unknown в `Answer.kind` с явной обработкой полярности и
   печатает строгий и абдуктивный режимы. Базовая линия: строгий **40/45**
   (детерминированные 25/30 все `proven`, Unknown 15/15, ложных доказательств нет);
   абдуктивный 30/30 детерминированных, но Unknown 5/15. Добавлены якорь против
   переформулировок под цитатой (`classify`, B8) и фидбэк последних волн в хинт (B9).
   См. `quality_findings` раздел E. Коллекция, её оси и харнесс описаны в
   `docs/proofwriter_ru.md`.
8. ~~**Формализация copula / домена (Фаза 0).**~~ **СДЕЛАНО.** Одноместная copula
   становится `is_a(subject, complement)` (никогда не голым унарным предикатом), а
   посылка правила, ограничивающая переменную объявленным `domain`-сортом,
   отбрасывается как домен квантора. Закрыло строгие пробелы ProofWriter `Att*` без
   спецкейсов в промпте.
   **Сброс домена — НА ДОИССЛЕДОВАНИЕ.** На синтетических структурах замечены два
   разных эффекта (на ProofWriter не воспроизводятся), поэтому это находка, которую
   надо воспроизвести и оценить до любой правки:
   - *(а) недо-вывод:* `enrich.strip_domain_conditions` безусловно удаляет
     `is_a(?x,D)` для глобального `domain`-сорта, даже когда это **единственная**
     связка переменной; правило остаётся без связки и не может сработать. По-правочный
     `unroll._normalize_domain` такую посылку намеренно сохраняет, то есть два пути
     расходятся. Проверено: `domain=["bird"]`, правило `is_a(?x,bird) => fly(?x)`
     становится без условий и ничего не выводит. Похоже на баг, не связанный с
     over-declaration.
   - *(б) сверх-вывод (незвуково):* если сорт переобъявлен и домен-посылка соседствует
     с другой связкой, её отброс снимает реальное ограничение, и правило срабатывает
     для не-D индивидов. Проверено: `domain=["bird"]`, правило
     `is_a(?x,bird) AND has_wings(?x) => fly(?x)`, факты `is_a(rex,dog)`,
     `has_wings(rex)` выводят `fly(rex)`.
   Открыто: сохранять ли посылку при переобъявлении сорта и не удалять ли единственную
   связку, плюс аудируемый пробел `over_declared_domain:`; сначала воспроизвести на
   живом извлечении (правило проекта: без спекулятивных механизмов).
9. **Поэтапное расширение ProofWriter (этапы B–D) — СДЕЛАНО; гейт D не зелёный,
   принято.** Закоммиченная выборка растёт по осям коллекции гейтованными шагами,
   каждый **прогоняется один раз** и перепрогоняется лишь при расхождении
   (экономно; `ANKYRA_EXTRACT_SAMPLES=1`): A 45 (сделано) → B 75 (A + 30 NatLang;
   **74/75**, гейт пройден) → C 150 (75 core + 75 NatLang; **148/150**, гейт пройден
   после фикса span-overlap в B8) → D 300 (C + 150 `depth-3ext`; **296/300**, гейт не
   зелёный — 2 grounded mismatch, один воспроизводимый, один вариативность; принято
   пока, находки 21–22); полная коллекция
   (6 368 теорий, ≈11 ч), этап E, **ОТМЕНЕНА** — нет бесплатного доступа к LLM, а
   API-токены оплачиваются из своего кармана; набор всех вопросов (54 848, ≈97 ч)
   остаётся вне объёма. **Этап D (300, 99%, 0 grounded false proofs) — принятый
   proof of concept.** Гейты этапа: 0 grounded false proofs,
   все детерминированные ответы `proven`, kind accuracy ≥ 90% (B) / 95% (C, D);
   каждое оставшееся падение категоризовано. Этапы служат и измерению, и отладке.
   Собирается `evals.build_proofwriter_sample --tier`, прогоняется
   `evals.proofwriter --tier`, отлаживается `evals.narrate --traces-dir`. См.
   `docs/proofwriter_ru.md` §6–7.

## 8. Беклог (из eval-харнесса)

Источник: `docs/quality_findings_ru.md`. По приоритету.

1. ~~**Верность объяснения (баг).**~~ **СДЕЛАНО.** `build_explanation` ветвится по
   статусу: `target_refuted` → отрицательный вывод; `contradiction` → обе ветки в
   `Explanation.conflict`; неразрешённый дефолтный конфликт → оба конкурирующих
   правила; `unsupported` / `insufficient` → пусто. Новый терминальный статус
   `contradiction` ставится, только если complementary pair входит в доказательство
   цели; несвязанное противоречие — gap `inconsistent_theory:`.
2. ~~**Провенанс правил в объяснении.**~~ **СДЕЛАНО.** `materialize_rule_morphisms` и
   `heal_contradictory_axioms` удалены: следствия правил не становятся аксиомами, а
   настоящее противоречие доходит до движка.
3. ~~**Захват презумпций.**~~ **ЗАКРЫТО (не воспроизводится / by design).** Явные
   маркеры («given that / assuming / suppose», рус. «при условии что») захватываются в
   live-прогонах 7/7, а контроль без маркера не перехватывается. Реализована явная
   декомпозиция `QuestionStructure.presuppositions` (идёт в `Query.conditions`, не в
   теорию), а шаги объяснения, заземлённые на Gamma, помечаются
   `source="presupposition"` (`docs/statement_sources_ru.md`). Comma-декларатив Фаза
   0.2 читает как описательный факт, поэтому ответ честно `supported`; тащить его в
   Gamma означало бы превратить данную информацию в гипотезу, поэтому оставлено как
   есть. Остаток — модельный (C1); сторож по cue-фразам запрещён `docs/task.md` §3.8,
   а поднимать `ANKYRA_EXTRACT_SAMPLES` доказанно бесполезно (C1). Live-кейсы
   пресуппозиций жёстко ассертятся в `tests/test_evals_live.py`.
4. **Митигации вариативности.** `ANKYRA_EXTRACT_SAMPLES` best-of-N,
   `ANKYRA_EXTRACT_REPAIRS` и `enforce_grounded` — сделаны. Провайдер измеренно
   стохастичен даже при `T=0` (`ANKYRA_SEED` не подтверждён, оставлен только
   opt-in). Отбор усилен: тай-брейк каноническим отпечатком структуры
   (`extract._rank_key`, без зависимости от порядка поступления), параллельные
   сэмплы сохраняют LLM-трас (`copy_context`), per-role
   `ANKYRA_EXTRACT_TEMPERATURE=0` применяется. Провайдерная детерминированность
   принята как внешняя и вне объёма; self-consistency кластеризация и стабильность
   промптов остаются опциональной устойчивостью.
5. ~~**Немонотонные исключения.**~~ **СДЕЛАНО** за `ANKYRA_DEFEASIBLE` (по умолчанию
   off): все правила — дефолты, строги только asserted-факты (ни извлечение, ни
   эвристика по предикату не задают силу), слой `engine/defeasible.py` (NFA +
   специфичность по `is_a`), `Answer.defeasible`, `Explanation.conflict` с
   причиной-свидетелем `is_a` для разрешённых поражений и обеими ветками для
   неразрешённых. См. `docs/defeasible_reasoning_ru.md`.
6. ~~**Кейс builtins.**~~ **СДЕЛАНО.** Детерминированное offline-покрытие через полный
   билдер (`tests/test_build_builtins.py`: `gte`/`gt`/`lte`/строковый `neq` по
   цепочке структура → Theory/Query → verify → Answer, плюс негативы «ниже порога» и
   «флаг выключен»); `check_naming` больше не помечает числа и переменные как имена
   объектов; live-харнесс жёстко ассертит ожидание задачи с `builtins: true`, а не
   только её инварианты.
7. ~~**LLM-судья.**~~ **ОТВЕРГНУТО (не делаем).** Детерминированные evaluator'ы
   (инварианты + ожидания) плюс бенчмарк с ground truth (ProofWriter, строгий 45/45)
   уже проверяют корректность, а звуковость символическая — не предмет суждения.
   LLM-судья (а) имел бы неясную цель (наррация косметична и выводится механически, а
   качество извлечения измеримо детерминированно — покрытие цитат, gaps, число волн),
   (б) был бы стохастическим судьёй того же стохастического провайдера — шум поверх
   шума, без воспроизводимости, (в) дал бы LLM решающую роль в оценке, против
   дизайн-принципа движка, и (г) стоил бы вызовов ради рубрики, которой нельзя
   доверять как метрике. Интерфейс `Evaluator` оставляем как точку расширения;
   вернуться только если появится конкретный качественный вопрос, на который
   детерминированные метрики и ground truth ответить не могут.
8. **`ARCHITECTURE.md`** — написан (слои, потоки, карта модулей).
9. **Подключаемая семантика вывода — ОТЛОЖЕНО.** См. `docs/logic_layer_ru.md`:
   это placeholder, а не задача. Вторая семантика (defeasible) уже есть и подключена
   флагом `DEFEASIBLE` в `engine/horn.py:derive_closure`, так что шов пока не
   вынуждается. Выделять узкий протокол `Inference` только когда появится
   действительно новая логика (ASP/probabilistic/…) или доказанная нужда; не
   абстрагировать спекулятивно.
10. ~~**Поле прямого ответа.**~~ **СДЕЛАНО.** `Answer.kind`
    (`yes|no|unknown|contradiction|binding|instruction`) вычисляется детерминированно,
    `engine.answer.render_answer` его локализует; `evals.narrate` печатает ответ, а
    LLM-наррация начинается с него. Скоринг на бенчмарках отображает кортеж
    `(kind, strength, defeasible)` и reason-бакеты под конкретный бенчмарк — семантика
    бенчмарка в движок не зашивается.
11. ~~**Ревизии ответа (аудит немонотонности).**~~ **СДЕЛАНО.** Монотонность
    заявлена для *базы*, а не ответа; `Revision` (`wave`, `trigger`, `previous`,
    `current`, `source_ids`) фиксируется при каждом изменении ответа между волнами
    и попадает в `Explanation.revisions`, а `Conflict.source_ids` называет гипотезы
    за конкурирующими ветками конфликта специфичности. Типизированные рёбра и слои
    онтологии не вводятся — фиксированный enum `physical/vital/...` обменял бы
    домен-независимость на жёсткую онтологию и отклонён.
12. ~~**Устойчивость полярности/отрицания (Phase 0).**~~ **СДЕЛАНО.** Две
    детерминированные правки по прогонам ProofWriter: `settle_query` отбрасывает
    посылку, комплементарную цели («есть ли phi?», извлечённый как положительная
    `phi` плюс посылка `¬phi`, самопротиворечив), а `classify` не принимает цитату
    из вопросительного спана (`_quote_in_question`), так что цель нельзя доказать
    ссылкой на вопрос. Оставшиеся строгие промахи — честные `unknown` и
    вариативность C1.
13. ~~**Заземлённое опровержение (guard абдукции).**~~ **СДЕЛАНО.** Допущение `P`
    не может опровергнуть `¬P`: опровержение с гипотезой понижается до
    `unsupported` (`hypothetical_refutation:`) и отвечает `unknown`/`not_proven`,
    что убирает 8 гипотетических опровержений в абдуктивном режиме ProofWriter.
    См. `docs/quality_findings_ru.md`, раздел F.
14. ~~**Плюмбинг воспроизводимости.**~~ **ОТБРОШЕНО (не делаем).** `ANKYRA_SEED`
    подмешивает seed в `ANKYRA_EXTRA_BODY`, а best-of-N сэмплы извлечения идут
    параллельно (`ANKYRA_EXTRACT_PARALLEL`, по умолчанию true). Поддержку seed
    провайдером в этом проекте не разбираем.
15. ~~**Question-begging guard.**~~ **СДЕЛАНО.** Нецитируемая факт-гипотеза, чей
    атом унифицируется с *замкнутой* целью, — `rejected/question_begging`;
    cited-факты из текста и привязки открытых целей освобождены, Example B
    безопасен. См. `docs/quality_findings_ru.md`, раздел F.
16. ~~**Структурный сорт квантора.**~~ **СДЕЛАНО.** Правила несут `forall`
    (переменная → сорт); `unroll` выбрасывает совпадающую посылку `is_a(?x,sort)`
    как домен квантора, оставляя её, если это единственная связка переменной.
    Снимает неоднозначность домен-vs-посылка (17–18 правил/прогон). См.
    `quality_findings_ru` B10.
17. ~~**Каноническое отношение признака + `relation_kind`.**~~ **СДЕЛАНО.**
    `StructAtom.relation_kind ∈ {ascription, possession, action}`; ascription
    канонизируется в `is_a(subject, property)` в любой позиции, possession — никогда,
    легаси `predication` отображается. Чинит расхождение кодировки факт-vs-правило
    (`quality_findings_ru` B11).
18. **Красный флаг потери конъюнкта — ЗАКРЫТО (не воспроизводится).** Измерено на
    11 сохранённых прогонах (~45 структур каждый): с корректным учётом `Slot.set`
    (AND) детектор срабатывает 0/249 правил; предполагаемая «потеря конъюнкта» была
    артефактом вывода (`object.id` при заполненном `object.set`). Вариант с покрытием
    токенов даёт ~37% ложных на морфологии глаголов (`need` vs «needs»), то есть
    требует лемматизации и не стоит того. Не реализовано.
19. ~~**Guard условной цитаты.**~~ **СДЕЛАНО.** Цитата, встречающаяся в источнике
    только внутри предложения-правила, не лицензирует аксиому
    (`quote_only_in_conditional`; отклонение `quote_conditional`, repairable-пробел
    `conditional_quote:`). Убрал два строгих ложных доказательства; строгий 45/45.
    См. `quality_findings_ru` B12.
20. **Источники утверждений — origin vs логическая роль (дизайн).** См.
    `docs/statement_sources_ru.md`. Origin (`cited` / `presupposition` / `hypothesis`
    / `external`) — только audit, в замыкание не попадает; логическая роль остаётся
    явной. Первый конкретный шаг: помечать шаги объяснения, заземлённые на Gamma, как
    `presupposition`, расширив `ExplanationStep.source`, чтобы `external` добавлялся
    потом без ломки. Дальше отложено — фреймворк источников не строим (ср. п.9).
21. ~~**Инъекция Gamma/цели через `reformalize_query`.**~~ **СДЕЛАНО.**
    `classify._reformalize` теперь считает запрос зафиксированным Фазой 0: условие,
    которого нет в запросе, — `rejected/fabricated_condition`; подменённая цель —
    `rejected/target_substituted`; меняются только `variables` (цель нельзя стереть).
    Этап D `RelNeg-OWA-D1-1025`. См. `quality_findings_ru` E.
22. ~~**Овер-обобщение именованного условного (извлечение).**~~ **СДЕЛАНО.**
    `PROBLEM_SYSTEM` теперь требует, чтобы условное про именованного индивида
    сохраняло константу (ground-импликация); над `?x` квантуется только
    generic-утверждение. Живой кейс `named_conditional`. Этап D
    `AttNoneg-OWA-D0-2873`. См. `quality_findings_ru` E.
23. **Провайдер принимает неполный tool-call — НЕ ЧИНИМ (принципиально).**
    Function-calling ответ с пустым `question` (и урезанными `facts`) валидируется
    молча (`ProblemStructure.question` по умолчанию `""`; `structured.py` принимает
    непустой `parsed`), поэтому стадия вопроса получает `""`, и запрос становится
    `instruction` (пост-фиксовый этап D: `no target extracted` 182/300). Не дыра
    звуковости (0 grounded false proofs). Неполный structured output — ответственность
    провайдера; защиту не добавляем. Если позже понадобится митигировать — bounded
    retry на пустой `question` в `extract_problem_structure`. См. `quality_findings_ru` E.
24. **Движок L1 + синтетические гейты — СДЕЛАНО.** Ограничения-дизъюнктности

    закрытого мира на запрос (`Query.world_assumption`, флаг `ANKYRA_NEGATION_MODE`)
    реализованы; `verify` репортит `out_of_fragment` для нестратифицируемых программ.
    LLM-free гейты: `evals.l1_synthetic` (32/32) и `evals.defeasible_synthetic` (8/8).
    Харнессы ProntoQA и FOLIO с закоммиченными сэмплами готовы; их живые прогоны
    вызывают платный извлекатель и ждут бюджета. План и решения: `docs/l1_plan_ru.md`.

## 9. Дорожная карта рассуждений (главная ось)

Главная ось развития — поэтапное расширение **разрешимых формализмов**: LLM
предлагает формализацию в логике `L`, а sound-процедура для `L` её решает.
Покрытие измеряется в именованных формализмах, а не в неограниченном
«рассуждении». Полное описание: `docs/reasoning_roadmap_ru.md`; заметки по
коллекциям: `docs/proofwriter_ru.md`, `docs/prontoqa_ru.md`, `docs/ar_lsat_ru.md`,
`docs/gsm8k_ru.md`, `docs/folio_ru.md`.

Этапы:

- **L0 — definite Horn** (текущий позвоночник: `is_a`, отрицание парами, OWA).
  Бенчмарк ProofWriter; этап D 296/300 — принятый proof of concept.
- **L1 — стратифицированное отрицание / negation-as-failure** с объявленным
  допущением о мире, для дизъюнктности и явного отрицательного знания. Бенчмарк
  ProntoQA; флаг `ANKYRA_NEGATION_MODE`. **Реализовано**: `Constraint` +
  `Query.world_assumption`, стратифицированный NAF в `engine/horn.py`, CWA в
  `engine/verify.py`; первичный гейт `evals.l1_synthetic` (32/32, без LLM), плюс
  харнессы ProntoQA и FOLIO (`docs/l1_plan_ru.md`; живые прогоны ждут бюджета).
- **L2 — дизъюнкция / positive FOL / proof by cases**, для compositional-цепочек.
  Бенчмарк ProntoQA-OOD (compositional); флаг `ANKYRA_LOGIC`. Второй гейт
  **FOLIO** (`docs/folio_ru.md`), стратифицирован по конструкции FOL (in-fragment
  оценивается, функции/равенство/схемы — `out_of_fragment`); полная FOL
  полуразрешима, поэтому поиск ограничен, а исчерпание — честный `insufficient`.
- **L3 — конечнодоменные CSP/SAT, отдельный движок.** Бенчмарк AR-LSAT.
- **L4 — арифметика, отдельный числовой движок или tool-use.** Бенчмарк GSM8K.
- **D — defeasible** (за `ANKYRA_DEFEASIBLE`); **реализовано + синтетический гейт**
  `evals.defeasible_synthetic` (8/8, без LLM); defeasible-NLI остаётся дешёвым
  дифференцирующим гейтом на реальных данных.

Решения: L3/L4 — отдельные движки и низкий приоритет; арифметика предпочтительно
через tool-use, а не ядро в репозитории. Архитектурный шов — `docs/logic_layer_ru.md`
(подключаемой становится только семантика). **Предусловие:** сначала закрыть
находки звуковости 21–22. **Бюджет:** каждый этап входит маленькой закоммиченной
выборкой (нет бесплатного доступа к LLM); полные коллекции бюджетируются отдельно.

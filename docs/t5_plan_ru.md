# План T5 — универсальная посылка только по голове (`∀x (l₁(x) ∨ … ∨ lₙ(x))`)

Статус: **утверждён и реализован**. Это пятый пункт бэклога понижения Tier-1
(`docs/coverage_ceiling.md` §6–§7) и самый крупный. T5 повышает **охват** (не
извлечение) на FOLIO L2, делая решаемой **универсальную посылку только по голове**:
клаузу, переменные которой не связаны телом, например `∀x (Rabbit(x) ∨ Squirrel(x))`.
Согласно `D-FE-3` он **переиспользует существующую ограниченную клаузальную процедуру**
(`ANKYRA_LOGIC`): работа — в области заземления, а не в новой семантике. Пункт
разрешает открытое решение **T-D1** из `docs/coverage_ceiling.md` §7. Результаты —
в §13.

Канонический язык: английский; русское зеркало: `docs/t5_plan_ru.md`, канонический
оригинал — `docs/t5_plan.md`.

Связанное: `docs/coverage_ceiling.md` (упорядоченный бэклог и открытое решение
T-D1), `docs/t1_plan.md`, `docs/t3_plan.md` (шаблон на пункт, которому следует T5),

## 2. Текущий блокер

- **Заземление.** `_groundings` (`engine/clause.py:116–124`) отвергает правило, как
  только переменная **головы** не является переменной тела
  (`if head_vars - body_vars: return None`), поэтому `clausify` записывает
  `unsafe_rule:<i>` (`engine/clause.py:263–266`), а `verify` возвращает
  `out_of_fragment`. Безусловный дизъюнктивный универсал кодируется парсером ровно как
  такое правило (`evals/folio_fol.py:_clause_rule`, 264–276: `conditions=[]`,
  `consequence=A(?x)`, `alternatives=[B(?x)]`).
- **Horn-движок его не видит.** `_fire_rules` пропускает любое правило без условий
  (`engine/horn.py:409–410`), поэтому универсал только по голове там ни срабатывает, ни
  безопасен; единственный кандидат — процедура L2.
- **Две разные области в одном пуле.** Пул клаузификации — это
  `build_context(theory).obj_pool ∪ skolems ∪ extra_pool` (`engine/clause.py:257`), а
  `obj_pool` (`engine/horn.py:49–60`) собирает **все** субъекты и объекты всех атомов.
  Для кодировки FOLIO — где унарное `P(a)` понижается в `is_a(a, p)` — пул поэтому
  смешивает **индивидов** (`rock`, `cocoGauff`) с **именами предикатов/классов**
  (`rabbit`, `femaletennis…`, объектов `is_a`). Заземление универсала только по голове
  по такому пулу инстанцирует его на именах классов, которые не являются элементами
  задуманного универсума первого порядка: лишние клаузы не являются следствиями
  исходного универсала и могут как сфабриковать доказательство, так и заблокировать
  законные опровержения (§4.3).

## 3. Объём и не-цели

**В объёме.**
- Правило с **переменной только по голове**: переменной, встречающейся в голове и ни в
  одном условии. Две формы, обрабатываются единообразно:
  - безусловный дизъюнктивный универсал `∀x (l₁(x) ∨ … ∨ lₙ(x))` (строки FOLIO);
  - безусловный Horn-универсал `∀x A(x)`, а также правило с телом и лишней переменной
    головы (`A(?x) → B(?y)`, то есть `∀x,y (A(x) → B(y))`).
- Заземление переменных только по голове по **области индивидов** (§4.1); честные
  `unsupported` / `budget`; парсер gold-fed не меняется.
- Синтетический гейт и routing-контроль.

**Вне объёма (без изменений, по-прежнему `out_of_fragment`).**
- Вложенные/многопеременные кванторы помимо переменных только по голове,
  функциональные термы.
- **Экзистенциальная посылка с вложенной дизъюнкцией** → **T2**; **неплоская цель** →
  **T4**.
- Изменение заземления переменных **тела**: `?c` в `is_a(?x, ?c)` обязан и дальше
  пробегать по именам классов, поэтому пул тела остаётся полным (§4.3). T5 трогает
  только переменные по голове.
- Без нового флага и новой настройки `.env`: capability — существующий `clausal`
  (`ANKYRA_LOGIC`, по умолчанию off); `head_only_rule` — производный
  `FragmentFeature`, а не процедура.
- Без NL-эвристик и подгонки под id (`docs/task.md` §3.8;
  `docs/coverage_ceiling.md` §8).

## 4. Конструкт и его решение

### 4.1 Прочтение — две области

`∀x (l₁(x) ∨ … ∨ lₙ(x))` читается классически над коммутируемой конечной областью.
Кодировка различает два вида термов:

- **Индивиды** — задуманный универсум рассуждения: любой терм в **субъектной** позиции
  либо в **объектной** позиции **не-`is_a`** атома. Это та же область, которой
  `folio_fol._object_names` уже пользуется для построения `Theory.objects`.
- **Имена классов** — **объекты `is_a`-атомов** (пониженные унарные предикаты),
  например `rabbit`, идентификаторы-предикаты вроде `femaletennis…`. Это артефакты
  кодировки, а не элементы универсума.

Определим **область индивидов**

```
D_ind = (ground-термы теории) \ {o : o встречается как объект is_a-атома}
```

(включая Skolem-константы и `extra_pool` из T3 — они индивиды и никогда не объекты
`is_a`). Имя класса, которое к тому же встречается как субъект, — документированная
граница (§10); коммутируемые коллекции её не проявляют.

### 4.2 Процедура решения (переиспользование ограниченного резолюционного вывода)

Новой процедуры нет: цель решают заземление и существующий ограниченный резолюционный
вывод. В `clausify` переменные правила только по голове инстанцируются по `D_ind`
(переменные тела остаются по полному пулу, §4.3). Заземление даёт для каждого индивида
`d` клаузу `¬body₁ ∨ … ∨ l₁(d) ∨ …`, и цель далее решается существующими путями L2 в
`verify` (`supported` / `refuted` / `contradiction` / `unknown` / `budget`). Переменная
только по голове, у которой **нет** индивида в `D_ind`, сохраняет честный отказ
`unsafe_rule`.

### 4.3 Почему это состоятельно и обще

- **Состоятельно.** `D_ind` — задуманный универсум; `∀x φ(x)` влечёт `φ(d)` для каждого
  `d ∈ D_ind`, поэтому ground-инстансы являются следствиями посылки. Инстанцирование
  на именах классов — нет: они не элементы области, поэтому такие клаузы не следуют и
  могут сделать набор клауз невыполнимым там, где теория выполнима, — сфабрикованное
  доказательство.
- **Полно для кодировки.** Каждый индивид встречается как субъект или как не-`is_a`
  аргумент, значит входит в `D_ind`; единственные исключённые термы — имена классов,
  которые не обозначает ни один индивидуальный запрос. Ни один нужный инстанс не
  теряется.
- **Наивная альтернатива несостоятельна и отвергнута.** Заземление переменных только по
  голове по полному пулу (индивиды **и** имена классов) — это ровно то, о чём
  предупреждает `docs/coverage_ceiling.md` §3: прототип на коммутируемых строках и
  несостоятелен в принципе, и эмпирически хуже (§9) — лишние классовые инстансы
  блокируют опровержения трёх строк `False`. Синтетический контроль доказывает истинный
  факт об имени класса, который заземление только по индивидам оставляет
  `unsupported` (§8, `head-only-03`).
- **Переменные тела намеренно не тронуты.** Переменная-класс (`?c` в `is_a(?x, ?c)`,
  тело правила над `is_a`) обязана пробегать по именам классов; её инстансы срабатывают
  только через выводимые атомы тела — это существующее, уже загейченное поведение. Её
  ограничение — отдельное, более широкое изменение, вне объёма T5.
- **Ограниченность.** `D_ind` конечна; существующий бюджет шагов ограничивает поиск, и
  исчерпание — честный `budget`.

## 5. Решения по устройству

- **T5-D1 — Область (разрешает T-D1).** (a) Заземлять переменные только по голове по
  `D_ind` (область индивидов); переменные тела без изменений. (b) Заземлять по полному
  пулу (наивно) — отвергнуто (инстансы-неследствия; хуже на коммутируемых строках).
  (c) Оставить строгий отказ — нет охвата. **DECIDED (a).**
- **T5-D2 — Определение области индивидов.** (a) `D_ind = ground-термы \ is_a-объекты`
  (строго; имя класса никогда не индивид). (b) `D_ind = ground-термы \ (is_a-объекты \
  термы, встречающиеся как субъект или не-`is_a` аргумент)` (мягко; имя, используемое
  и как класс, и как индивид, остаётся индивидом). Оба варианта дают идентичный
  результат на FOLIO (§9); (a) проще и корректно обрабатывает иерархии классов
  (`is_a(car, vehicle)`). **DECIDED (a)**; (b) зафиксирован как альтернатива.
- **T5-D3 — Именование фрагмента.** (a) Добавить производный `FragmentFeature`
  `head_only_rule` (правило с переменной только по голове), отображаемый в клаузальный
  фрагмент: аудируемое имя и место для routing-контроля, без нового capability/флага.
  (b) Переиспользовать `disjunction`. **DECIDED (a)** (зеркалит T1-D3/T3-D3). Заметка:
  строки FOLIO вместе с тем дают `disjunction`; Horn-универсал `∀x A(x)` даёт только
  `head_only_rule`.
- **T5-D4 — Объём.** (a) Любое правило с переменной только по голове (безусловный
  дизъюнктивный универсал, безусловный Horn-универсал, правило с телом и лишней
  переменной головы), заземляемое по `D_ind`. (b) Только безусловная дизъюнктивная
  форма. **DECIDED (a)** — одно единое правило заземления, без спецкейсов по форме.

## 10. Риски

- **Граница индивид/класс — soundness-чувствительная часть.** Ошибка, откатывающаяся к
  полному пулу при пустой `D_ind` или включающая `is_a`-объекты, допускает ложное `yes`.
  Синтетический контроль `head-only-03` — специальный негативный тест; gold-fed
  повторный замер требует **0 grounded false proofs**.
- **Имя класса, которое к тому же субъект.** По T5-D2(a) оно исключено из `D_ind`. Если
  задача действительно использует такое имя как индивида, его инстансы только по голове
  теряются (честный `unsupported`, никогда не несостоятельность). Документированная
  граница; коммутируемые коллекции её не проявляют.
- **Асимметрия тело/голова.** Переменные тела сохраняют полный пул, поэтому
  ground-инстансы тела на именах классов остаются возможны (предсуществующее,
  загейченное текущим результатом 0 ложных доказательств). T5 нельзя читать как
  исправивший это; выравнивание заземления тела на `D_ind` — отдельное, более широкое
  изменение.
- **Точность объяснения.** Правило только по голове рендерится как
  `IF TRUE => a(x) OR b(x)`; каждый шаг по-прежнему должен отображаться в реальное
  резолюционное ребро, без выдуманных шагов.
- **Стоимость.** Заземление добавляет одну клаузу на индивида на каждое правило только
  по голове; `D_ind` на FOLIO мала, а бюджет ограничивает поиск (исчерпание — честный
  `budget`).
- Никакого полного живого прогона FOLIO без отдельного бюджетного решения
  (`docs/reasoning_roadmap.md` §4).

## 11. Порядок работ (вехи)

1. Движок: `_individual_pool`, области в `_groundings`, проводка `clausify`;
   юнит-тесты. (Ничего живого не гейтит.)
2. Синтетические кейсы `head_only`; `evals.l2_synthetic` зелёный — soundness-гейт
   (`head-only-03`) предшествует всему остальному.
3. Фича фрагмента `head_only_rule` + routing-синтетический кейс.
4. LLM-free gold-fed повторный замер; зафиксировать дельту.
5. Документы: `coverage_ceiling.md` (T5 done + числа), `folio_gold_fed.md`,
   `l2_plan.md` (веха), `reasoning_roadmap.md`, `implementation_plan.md` пункт 26;
   зеркало `docs/t5_plan_ru.md`.

Каждая веха ложится отдельно ревьюируемой; soundness-гейт (шаг 2) предшествует
gold-fed повторному замеру (шаг 4).

## 12. Ограничители

- Конструкт входит как **именованный фрагмент** (`docs/fragment_routing.md`); за
  пределами коммутируемой формы остаётся честный `out_of_fragment`.
- **Никогда не понижать семантику, чтобы пройти строку** (`docs/coverage_ceiling.md`
  §8): не инстанцировать универсал на именах классов и не сворачивать
  `∀x(A(x)∨B(x))` в ground-факт.
- Без подгонки под id; LLM-free gold-fed граница — бесплатный гейт после пункта: охват
  вверх, **0 grounded false proofs**.

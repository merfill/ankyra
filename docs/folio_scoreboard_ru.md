# Скорборд FOLIO — единственный интегральный вид

Статус: **канонический итог оценки FOLIO** (только документация, без кода). Это
единственное место, где сведены все цифры FOLIO. Механика коллекции — в `docs/folio.md`,
метод gold-fed — в `docs/folio_gold_fed.md`, модель двух потолков — в
`docs/folio_ceilings.md`, план охвата — в `docs/coverage_ceiling.md`.

Канонический язык: английский; русское зеркало: `docs/folio_scoreboard_ru.md`.
Связанное: четыре заметки выше, `docs/reasoning_roadmap.md` (L2),
`docs/implementation_plan.md` §10 (гейтование композитного бенчмарка),
`docs/fragment_routing.md` (контракт объявленного фрагмента).

## 1. Почему единого числа у FOLIO нет

FOLIO не может иметь один headline-показатель без искажения того, что измерено:

1. **Это композитный бенчмарк по построению.** Его gold-FOL покрывает L0 (атомы,
   универсальные импликации), L1 (отрицание), L2 (`∨`, `∃`) и конструкции вне любой
   закоммиченной стадии (`⊕`, `↔`, равенство, функции, мультивары). Коллекция, чей
   gold смешивает формализмы, — гейт для нескольких стадий, а не один скорборд
   (`docs/implementation_plan.md` §10).
2. **Открытый мир.** 38.5% меток — `Unknown`; тривиальное «всегда `Unknown`» даёт
   38.5%, поэтому сырая accuracy доминируется мажоритарным классом.
3. **`out_of_fragment` — воздержание, а не ошибка.** Считать его ошибкой (или
   корректным `unknown`) — искажает число. Он стоит recall, но не корректности.
4. **Два независимых потолка.** *Охват* (какие формулы логика вообще может выразить) и
   *извлечение* (как часто LLM верно переводит покрытую строку) меняются независимо;
   один скаляр их смешивает.

Поэтому интегральный вид — маленький **дашборд**, воспроизводимый и LLM-free для
методной части.

## 2. Дашборд — четыре величины

| # | величина | определение | ось |
|---|---|---|---|
| 1 | **Охват (Coverage)** | строки во фрагменте / все строки | формализм |
| 2 | **Method bound** | gold-fed correct / covered (LLM-free) | формализм |
| 3 | **Извлечение (Extraction)** | text-fed correct / covered (live) | модель |
| 4 | **Корректность (Soundness)** | grounded false proofs (`= 0`, инвариант) | движок |

Никогда не сливать 2 и 3 в одно число: их разность *и есть* запас извлечения.

Талли конструкций (перекрываются внутри строки): отрицание 157, дизъюнкция 76,

Следствия:

- **Охват двух закоммиченных гейтов ≈ 106/204 ≈ 52%.** Дополнение — сознательная

  «accuracy FOLIO», молча использующая 45 или 58 строк, обязана это указывать.

Две разные причины дрейфа, обе безобидные:

- **Эволюция движка (без нового LLM-вызова).** Tier-1 (T1/T3/T5/T4/T2/T6) и поздние
  фиксы builder'а позволяют *текущему* движку решить больше на *той же сохранённой
  формализации*; text-fed replay растёт (25 → 29), а записанный live-скор остаётся на
  дате прогона.
- **Смена пути.** Neg-срез переоценён с Horn-пути (7/13) на клаузальный L2-путь
  (11/13), согласно `docs/implementation_plan.md` §8 item 29.

`text-fed` (сохранённый скор) и `text-fed (replay)` (текущий движок на сохранённой
формализации) сегодня совпадают; при изменении промпта/схемы извлечения обновить
сохранённый скор может только live-прогон.

## 6. Воспроизведение

LLM-free (из репозитория):

```
uv run python -m evals.recon_l2 --folio-only                       # талли конструкций
uv run python -m evals.analyze_folio --subset l2                    # gold-fed + replay
uv run python -m evals.analyze_folio --subset negation              # gold-fed + replay
uv run pytest tests/test_evals_folio_fol.py -q                      # гейт парсера/gold
```

Live (нужен платный экстрактор; бюджетное решение, `docs/reasoning_roadmap.md` §4):

```
uv run python -m evals.folio --subset {negation,l2} [--jobs 5]     # пишет evals/out/folio/
```

## 7. Не-цели и ограждения

- **Никакого headline по всей коллекции FOLIO.** Полный охват недостижим по дизайну:
  конструкции вроде равенства/функций лежат вне любой закоммиченной стадии, а полная
  FOL-выводимость лишь полуразрешима.
- **Никакого понижения семантики, чтобы пройти строку.** Схлопывание
  `∀x (P(x) → ¬Cat(x))` в ground `¬is_a(pet, cat)` доказывает корректный факт о *неверной*
  цели (`docs/folio_ceilings.md` §8).
- **Никакого tune по id.** Улучшения идут из общего контракта извлечения и именованных
  фрагментов по контракту объявленного фрагмента.
- **`out_of_fragment` — воздержание**, отчитывается явно и никогда не засчитывается как
  корректный `unknown`.

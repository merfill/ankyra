# ProntoQA — заметки о коллекции

Рабочие заметки по синтетическому бенчмарку дедукции, **гейт L1**
`docs/reasoning_roadmap_ru.md`. Английский оригинал: `docs/prontoqa.md`. Смежное:
`docs/reasoning_roadmap_ru.md`, `docs/l1_plan_ru.md` (план реализации L1),
`docs/proofwriter_ru.md`, `docs/task_ru.md` §3.8.

Источники: Saparov & He, *Language Models Are Greedy Reasoners: A Systematic
Formal Analysis of Chain-of-Thought* (ICLR 2023, arXiv:2210.01240) и *Testing the
General Deductive Reasoning Capacity of Large Language Models Using OOD Examples*
(NeurIPS 2023, arXiv:2305.15269). Генератор и данные:
`github.com/asaparov/prontoqa` (Apache-2.0); исходный релиз — ветка `v1`,
OOD-релиз — `main` + `generated_ood_data.zip`. Зеркала на HF:
`tasksource/prontoqa` (официальная ссылка), `smoorsmith/prontoqa` (формат
Logic-LLM), `renma/ProntoQA` (формат Logic-LM). Закоммиченной выборки пока нет.

## 1. Что это за бенчмарк

Синтетический бенчмарк вопросов-ответов с машинно-сгенерированными цепочками
рассуждений. Генератор строит **онтологию** — дерево или DAG вымышленных (или
реальных) концептов, у каждого есть родитель и, возможно, свойства и
отрицательные свойства, — затем утверждает тип одного индивида и задаёт вопрос о
его принадлежности. Каждый пример несёт формальное доказательство
(`chain_of_thought`).

Формы предложений (теории короткие и синтаксически простые):

- правила подведения: `Every X is a Y.` / `Each X is a Y.` / `X are Y.`;
- утверждение: `131071 is a Mersenne prime.` / `Wren is a numpus.`;
- отрицательные свойства (вариант с отрицанием): `Every real number is not
  imaginary.`;
- вопрос: `Is the following statement true or false? 131071 is not real.`

Есть два семейства вопросов:

- **membership / subsumption** — цепочка шагов `is_a` (классический 5-hop
  PrOntoQA; OOD-релиз добавляет 3/5/7-hop);
- **compositional** (PrOntoQA-OOD) — вложенные конъюнкция, дизъюнкция и отрицание,
  proof by cases и доказательство от противного.

Ручки генерации онтологии: `generate_negation`, `generate_properties`,
`require_properties`, `max_child_count`, `stop_probability` и дистракторы
`generate_distractor_parents` / `generate_distractor_branch` (множественное
наследование). Концепты-сиблинги делаются **дизъюнктными**
(`are_children_disjoint`) только при включённом отрицании, через
`¬∃x (Cᵢ(x) ∧ Cⱼ(x))`.

## 2. Поля записи

Сгенерированный JSON и HF-зеркала немного различаются. Формат Logic-LLM:

| Поле | Значение |
|---|---|
| `index` | индекс строки |
| `id` | id примера (`example1`, …) |
| `context` | теория: правила подведения и утверждение |
| `question` | `Is the following statement true or false? <statement>` |
| `options` | фиксированные `["A) True", "B) False"]` |
| `answer` | `A` или `B` (истинность утверждения) |
| `chain_of_thought` | доказательство, строки `Step N: <sentence>.` |

Официальный генератор пишет собственный JSON (шаги доказательства, а не
отрендеренный `chain_of_thought`): `run_experiment.py --model-name json` с
`--min-hops`, `--max-hops`, `--hops-skip`, `--ontology fictional|true|false`,
`--ordering postorder|preorder|random`, `--num-trials`, `--few-shot-examples`.

## 3. Оси

- **число шагов (hops)** — 1/3/5/7 шагов вывода;
- **отрицание** — отрицательные свойства и/или дизъюнктность сиблингов;
- **онтология** — вымышленные концепты vs реальная (биология, теория чисел);
- **compositional** — вложенность And/Or/Not, доказательство от противного;
- **порядок** — postorder / preorder / random;
- **дистракторы** — посторонние сущности, дистракторные родители (множественное
  наследование).

## 4. Формы доказательств

Генератор выдаёт доказательство по фиксированному словарю шагов; каждый
соответствует требуемой возможности движка:

| Шаг доказательства | Смысл | Этап Ankyra |
|---|---|---|
| `AXIOM` | утверждённый факт | L0 |
| `ModusPonens` (универсальная конкретизация) | `∀x(X→Y)`, `X(a)` ⊢ `Y(a)` | L0 |
| `AndIntro` / `AndElim` | конъюнкция определяющих свойств | L0, если извлечено как AND-тело правила |
| `OrIntro` / `OrElim` | дизъюнкция, разбор случаев | **L2** |
| `ProofByContra` | доказательство от противного | **L2** |
| дизъюнктность `¬∃ (Cᵢ ∧ Cⱼ)` | сиблинги не пересекаются | **L1** |
| отрицательное свойство `∀x(C → ¬P)` | явное отрицательное заключение | **L1** |

## 5. Связь с Ankyra

- **Положительный membership — это L0.** `Every X is a Y` превращается в
  `is_a(?x, X) => is_a(?x, Y)`; утверждённый тип и замыкание `is_a` отвечают на
  вопрос напрямую. Это ровно структура `Att` из ProofWriter, поэтому риск низкий.
- **Ответ «False» неоднозначен.** Часть ложных вопросов — это *отрицательные
  утверждения, опровергнутые положительной цепочкой* (напр. `131071 is not real`
  ложно, потому что выводится `is_a(131071, real)`) — L0 их берёт. Другие требуют
  **дизъюнктности** или явного отрицания, а это **L1** (стратифицированное
  отрицание / негативные ограничения). Именно поэтому ProntoQA — гейт L1.
- **Compositional-вопросы требуют L2** (дизъюнкция, разбор случаев, доказательство
  от противного) и по построению вне Horn-фрагмента.

Поскольку коллекция неоднородна, прогон Ankyra обязан быть **стратифицирован по
форме доказательства**: подмножество внутри фрагмента оценивается по гейту,
остальное отчитывается как `out_of_fragment` и не является провалом.

## 6. Как харнесс будет это использовать

- `problem_text` = `context` + вопрос, как в ProofWriter.
- Цель — утверждение как написано; адаптер polarity-aware (отрицательное
  утверждение может быть извлечено как положительный ask): `answer A (True)` →
  утверждение выводимо, `answer B (False)` → утверждение опровергнуто.
- По умолчанию строгая дедукция; для подмножества L1 объявленное допущение о мире
  (`ANKYRA_NEGATION_MODE`) выставляется **бенчмарком**, а не угадывается.
- Гейты и гигиена стоимости — как в `docs/proofwriter_ru.md` §6–7: маленькая
  закоммиченная выборка, `ANKYRA_EXTRACT_SAMPLES=1`, прогон один раз,
  перепрогон только при расхождении.

## 7. План тестирования

0. **Recon (без LLM).** Сгенерировать несколько сотен примеров официальным
   генератором (`--model-name json`) и посчитать распределение шагов
   доказательств, чтобы точно измерить подмножества L0 / L1 / L2.
1. **Билдер** `evals/build_prontoqa_sample.py` — детерминированный,
   стратифицированный, коммит `evals/data/prontoqa_tier_*.jsonl` (по образцу
   `evals.build_proofwriter_sample`).
2. **Адаптер** `evals/prontoqa.py` — `load_sample` / `problem_text` /
   `score_record` / `_to_problem`, `--tier/--ids/--limit`, трассы в
   `evals/out/prontoqa/`, тот же отчёт по гейту.
3. **Гейт L0:** 0 grounded false proofs, детерминированные все `proven`, kind
   accuracy ≥ 95% на подмножестве внутри фрагмента; `out_of_fragment` считается,
   но не валит гейт.
4. **Этап L1:** включить стратифицированное отрицание для подмножества
   дизъюнктности/отрицания, со своим гейтом и своей строкой отчёта.

## 8. Статус и результаты рекона

**Рекон выполнен (без LLM).** Сведены два источника:

- `smoorsmith/prontoqa` (зеркало ProntoQA v1 в формате Logic-LLM; по 500 строк в
  train/val/test, всего 1500);
- официальный генератор `asaparov/prontoqa` v1 (`run_experiment.py --model-name
  json`, seed 7, 180 строк) — как перекрёстная проверка.

Выводы:

- **Разбиение L0 / L1.** 760/1500 — позитивные цепочки подсуммирования
  `ModusPonens` (L0); 740/1500 завершаются через **явное правило с отрицаемым
  свойством** вида `Every X is not Y` (L1).
- **Нет дизъюнктности, нет композиции.** В поверхностном контексте **нет** ни одного
  предложения-дизъюнктности («No X is a Y»), и ни одно доказательство не использует
  дизъюнктность; `And`/`Or`/`ProofByContra` в этом релизе нет (это OOD-релиз
  `tasksource/prontoqa`, т.е. L2).
- Официальный генератор ведёт себя так же: отрицание всегда рендерится как явное
  правило с отрицаемым свойством. Формулы дизъюнктности существуют только в
  **формальной онтологии** генератора (`get_disjointness_formulas`) и никогда — в
  поверхностном контексте, т.е. из текста не извлекаются (это вопрос §6 плана;
  `docs/l1_plan_ru.md` D-L1-1(a) применим, если такие вопросы вообще попадут в
  выборку).
- **Существующий движок уже решает подмножество явного отрицания.** Правило с
  негативным консеквентом плюс позитивная цель дают `refuted` со strength `proven`
  (проверено офлайн: `is_a(real)->¬is_a(imaginary)` опровергает `imaginary(a)`);
  позитивная цепочка по-прежнему `supported`.

**Следствие.** ProntoQA v1 гейтит **L0 + явное отрицание (негативные консеквенты
правил), которое уже поддержано движком**; новая механика L1 (ограничения, NAF, CWA)
этой коллекцией **не задействуется**. Поэтому область — открытое решение
(`docs/l1_plan_ru.md` D-L1-5).

**Харнесс реализован.** `evals.build_prontoqa_sample` коммитит
`evals/data/prontoqa_tier_a.jsonl` (48) и `prontoqa_tier_b.jsonl` (160),
стратифицированные по форме доказательства × полярности утверждения;
`evals.prontoqa --tier a|b` — полярно-осознанный адаптер (зеркало харнесса
ProofWriter, выставляет `world_assumption="open"`). LLM-free первичный гейт L1 —
`evals.l1_synthetic`.

**Отчёт по гейту (строгая дедукция, `ANKYRA_EXTRACT_SAMPLES=1`).**

| Тир | Задач | Positive | Negation | Точность kind | Strength | Grounded false proofs |
|---|---|---|---|---|---|---|
| a | 48 | 24/24 | 24/24 | **48/48 (100%)** | все `proven` | 0 |
| b | 160 | 80/80 | 80/80 | **160/160 (100%)** | все `proven` | 0 |

Оба гейта пройдены: 0 grounded false proofs, каждый определённый ответ `proven`; все
208 задач решены на волне 0 (детерминированное замыкание, без гипотез/предложений).
Односторонняя 95% нижняя граница Клоппера–Пирсона по точности на задачу: 94.0%
(тир a, n=48) и **98.1%** (тир b, n=160), т.е. тир b статистически подтверждает
«≥95%». Оговорка: ProntoQA v1 везде 10 hops, поэтому выборка измеряет устойчивость
извлечения, а не глубину рассуждения (глубина покрыта перепрогоном ProofWriter
Tier D 297/300).
См. `docs/reasoning_roadmap_ru.md` L1 и `docs/l1_plan_ru.md`.

**Закрыто — прогоны ProntoQA больше не выполняются.** Коллекция считается
протестированной на L1: оба тира зелёные, подмножество явного отрицания уже
поддержано движком, измерять здесь больше нечего. ProntoQA v1 не запускается
повторно в рамках этапов; прогон возобновляется, только если он отдельно
понадобится на следующем этапе (например, compositional-срез ProntoQA-OOD для
L2), и тогда — отдельным решением по бюджету. Иначе коллекция остаётся закрытой,
чтобы не расходовать токены.

## 9. Recon ProntoQA-OOD (L2, LLM-free)

Источник: `tasksource/prontoqa`, OOD-релиз (Saparov & He, NeurIPS 2023). Это 58
JSON-файлов по 100 записей; оценивается запись `test_example`, итого **5800**
примеров. Воспроизводится командой
`uv run python -m evals.recon_l2 --prontoqa-only` (без LLM).

Каждый `test_example` классифицируется по требуемой возможности L2: `horn`
(одноатомная положительная/отрицательная цель без разбора случаев — уже L0/L1),
`l2_decomp` (конъюнктивная или дизъюнктивная **цель**, решается декомпозицией) и
`l2_reductio` (в доказательстве есть `Assume`: proof by cases / от противного).

| Класс | Примеры | Доля |
|---|---|---|
| `horn` (L0/L1) | 2534 | 43.7% |
| `l2_decomp` (∧/∨ цель) | 1993 | 34.4% |
| `l2_reductio` | 935 | 16.1% |
| `l2_reductio+decomp` | 338 | 5.8% |
| **L2 (любой не-horn)** | **3266** | **56.3%** |

По типам правил:

| Тип правила | Примеры | Форма | Возможность L2 |
|---|---|---|---|
| `AndElim` | 1200 | horn | — |
| `AndIntro` | 1400 | l2_decomp | конъюнктивная цель (декомпозиция) |
| `ProofsOnly` | 900 | horn | — |
| `ModusPonens` | 100 | horn | — |
| `OrElim` | 600 | l2_reductio | proof by cases над дизъюнктивным ground-фактом |
| `OrIntro` | 400 | l2_decomp | дизъюнктивная цель (доказать дизъюнкт) |
| `ProofByContra` | 300 | l2_reductio+decomp | reductio + конъюнктивная отрицательная цель |
| `Composed` | 900 | смешанные | 334 horn, 193 decomp, 335 reductio, 38 оба |

Surface-формы (число примеров): дизъюнктивный **ground-факт** 600 («Rex is a
shumpus or a jompus or a grimpus»), дизъюнктивный **антецедент правила** 1211
(«Everything that is A or B or C is D»), дизъюнктивная **цель** 587 («Prove: … is
A, B, or C»), **экзистенциал 0**.

Выводы:

- **Surface `or` — над атомами классовой принадлежности/свойства** (`is_a`), не над
  произвольными пропозициями и не над заполнителями объектов. Он встречается в
  антецедентах правил (Horn-расщепимо: `A∨B → D` ≡ `A→D ∧ B→D`), в
  **ground-фактах** (не-Horn) и в **целях**.
- **`OrElim` — proof by cases**: из дизъюнктивного ground-факта принимаем каждый
  дизъюнкт и доказываем цель; действительно не-Horn.
- **`OrIntro` — дизъюнктивная цель**, доказываемая доказательством дизъюнкта.
- **`ProofByContra` / `Composed` — reductio**: принять отрицание и вывести
  противоречие — контрапозиция, которой у Horn/L1 нет.
- **`AndIntro` — конъюнктивная цель** (`T ⊢ A ∧ B` тогда и только тогда, когда каждый
  конъюнкт); `AndElim`, `ProofsOnly`, `ModusPonens` (и 334 `Composed`) — Horn.
- **Экзистенциал не упражняется (0/5800).** Первопорядковый/`∃`-слой (milestone 8
  плана L2) поэтому **не** гейтится ProntoQA-OOD; его упражняет только FOLIO
  (`docs/folio_ru.md` §10).

Следствие. Первому гейту L2 нужны (a) декомпозиция конъюнктивных и дизъюнктивных
**целей**, (b) **дизъюнктивные ground-факты** с **разбором случаев** и (c)
**reductio/контрапозиция**. Кванторы и Skolem ему **не** нужны. Это уже, чем набросок
L2 в roadmap, и зафиксировано в `docs/l2_plan_ru.md` §6/§9.

**Harness L2 реализован (LLM-free); живой прогон ждёт бюджета.**
`evals.build_prontoqa_ood_sample` коммитит `evals/data/prontoqa_ood_tier_a.jsonl`
(44 задачи, стратифицировано по типу правила × классу L2: `horn`, `l2_decomp`,
`l2_reductio`, `l2_reductio+decomp`; тир b = 12 на бакет). `evals.prontoqa_ood` —
поляритет-осознанный адаптер (`--tier a|b`, `--ids`, `--limit`, `--no-write`,
`--jobs`), запускающий движок при `logic="ground"` (``ANKYRA_LOGIC``) и открытом
мире; отчитывается точностью по kind, бакетом `out_of_fragment` и статусами.
Offline-тесты: `tests/test_evals_prontoqa_ood.py`.

**Живой** прогон вызывает платный экстрактор и отложен до отдельного решения по
бюджету. Одна зависимость: составные кейсы (`ask_all`/`ask_any`) требуют поддержки
извлечения из milestone 9 плана L2, прежде чем их можно оценивать по kind; до этого
они сообщают отсутствие цели и считаются, а не проваливаются.

**Живой гейт (тир a, `--jobs 5`).** 42 оценки: **41/42 (97.6%)**, **0 grounded false
proofs**, все determinate-ответы `proven`. Две задачи без извлечённой цели (unknown);
один `Composed`-кейс дал противоречивую извлечённую теорию и был честно помечен
`contradiction`. Найден и исправлен дефект: `verify` больше не понижает
*доказанную* цель при таймауте её дополнения (детекция противоречия идёт под меньшим
лимитом), а адаптер оценивает составную цель по всему утверждению (а не по первому,
возможно отрицаемому, конъюнкту). Без этих фиксов тот же прогон давал 40%, т.е.
низкий результат был артефактом harness/приоритета, а не несостоятельностью.

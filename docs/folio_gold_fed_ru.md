# Gold-fed диагностика FOLIO — метод против извлечения

Статус: **реализовано и измерено** (FOLIO L2 tier a, без LLM). Заметка фиксирует
работу Phase 0, расширившую gold-FOL диагностику с L1-формы отрицания на L2
(`∨`/`∃`), и результат, определяющий приоритет по FOLIO.

Канонический язык: английский; английский оригинал: `docs/folio_gold_fed.md`.
Смежное: `docs/folio_ru.md` (§9–§10), `docs/folio_ceilings_ru.md` (§4, §7),
`docs/folio_extension_plan_ru.md` (§3, Phase 0), `docs/quality_findings_ru.md` §G,
`docs/l2_plan_ru.md`, `docs/implementation_plan_ru.md` §10,
`docs/reasoning_roadmap_ru.md`.

## 1. Вопрос

У FOLIO два независимых потолка (`docs/folio_ceilings_ru.md` §3): **охват**
(формализм — какие строки может выразить закоммиченная логика) и **извлечение**
(модель — как часто LLM правильно переводит охваченную строку). Живое число смешивает
оба и потому неоднозначно. Решающий контрфакт — **gold-fed** оценка: подать движку
аннотированные FOL-формулы вместо LLM-извлечения и измерить точность только метода.

- `gold-fed ≫ text-fed` → предел в **языке** (извлечении);
- `gold-fed ≈ text-fed`, оба низкие → предел в **методе** (охвате).

## 2. Метод (без LLM)

- **`evals/folio_fol.py`** — детерминированный парсер аннотированной FOL в модели
  L1/L2: рекурсивный спуск с приоритетом `→` > `∨` > `∧` > `¬` > атом, `∀`/`∃`,
  юникод-идентификаторы (напр. `Companies’Stocks`), нормальная форма отрицания и
  КНФ. Отображение:

  | gold-форма | представление |
  |---|---|
  | `A ∧ B → C`, `∀x (A(x) → B(x))` | `Rule(conditions, consequence)` |
  | `∀x (… → B(x) ∨ C(x))`, `A → ¬(B ∨ C)` | `Rule.alternatives` |
  | `A ∨ B → C` | два правила `A → C`, `B → C` |
  | `A ∨ B` (ground) | безусловное `Rule` с `alternatives` |
  | посылка `∀x (A(x) ∨ B(x))` (только по голове) | безусловное `Rule` с головной переменной (T5) |
  | `¬(A ∧ B)` / `¬(A ∨ B)` | Де Морган, до литералов |
  | посылка `∃x (φ ∧ …)` | `Theory.existentials` |
  | заключение ground / `∧` / `∨` / `∃x P(x)` | `Query.target` или `Query.goals` + `goal_mode` |
  | заключение `∀x (l₁ ∨ … ∨ lₙ)` (`∀x(A→B)`, `¬∃x φ`) | `Query.goals` + `goal_mode="forall"` (T3) |

  Формула вне закоммиченной формы поднимает `FolParseError` → честный
  `out_of_fragment`, без угадывания кодировки. Границы охвата: не-клаузальные/
  условные цели, экзистенциальная посылка с вложенной дизъюнкцией, вложенные
  кванторы, функции. Конъюнктивный экзистенциальный вывод с общим свидетелем
  (`∃x (A(x) ∧ B(x))`) добавлен во фрагмент пунктом Tier-1 **T1**
  (`docs/t1_plan_ru.md`): это совместная цель `all`, решаемая одним свидетелем для
  всех конъюнктов. Универсальный клаузальный вывод добавлен **T3**
  (`docs/t3_plan_ru.md`): это цель `goal_mode="forall"`, supported на свежей константе
  и refuted одним именованным свидетелем. Универсальная посылка только по голове
  (`∀x (A(x) ∨ B(x))`) добавлена **T5** (`docs/t5_plan_ru.md`): головная переменная
  заземляется по домену индивидов (пул минус `is_a`-объекты / имена классов).
- **`evals/analyze_folio.py`** — `--subset {negation,l2}`. L2 gold-прогон идёт под
  `setting_overrides(LOGIC="ground")` (клаузальная процедура L2); negation-прогон
  остаётся на Horn/L1-пути. Вердикт `out_of_fragment` — это абстенция, и он
  **никогда не засчитывается как верный `unknown`**.
- **Гейт:** `tests/test_evals_folio_fol.py` (парсер + gold-прогон на закоммиченных
  записях, без LLM).

Воспроизведение:

```
uv run python -m evals.analyze_folio --subset l2
uv run python -m evals.analyze_folio --subset negation
```

## 3. Результат

### L1 negation (13 in-fragment) — без изменений

| источник | верно |
|---|---|
| text-fed | 7/13 |
| gold-fed open | 7/13 |
| gold-fed closed | 8/13 |

Категории: ok 6, semantics 5, fragment 1, extraction 1 — coverage-bound (метки
`False` требуют reductio/CWA), как записано в `docs/folio_ru.md` §9.

### L2 tier a (45) — новое

| источник | верно |
|---|---|
| text-fed (LLM-извлечение) | 25/45 |
| gold-fed open (= closed) | 35/45 |
| gold `out_of_fragment` | 6/45 |

Покрытие (строки, которые закоммиченная процедура L2 может выразить и решить) —
**39/45**; пункт Tier-1 **T1** (`docs/t1_plan_ru.md`) добавил четыре строки с общим
свидетелем (`0033`, `0058`, `0059`, `0069`), **T3** (`docs/t3_plan_ru.md`) — строки
универсальной/`¬∃` цели (`0045`, `0107`), а **T5** (`docs/t5_plan_ru.md`) — двенадцать
строк универсала только по голове. На охваченных строках:

| метка | gold-fed | text-fed |
|---|---|---|
| True | 12/13 | 6/13 |
| False | 10/13 | 4/13 |
| Uncertain | 13/13 | 12/13 |
| **итого** | **35/39** | **22/39** |

Grounded false proof нет: каждый неверный gold-ответ — абстенция (`insufficient` из
бюджета резолюции — G4 — или `unsupported`); ошибочных детерминированных ответов
нет.

Оставшиеся 6 строк вне фрагмента:

- **6 парсер не может выразить:** составные/условные заключения (вложенные `∧`/`∨`
  или импликация как цель, T4: `0073`, `0020`), экзистенциальная посылка с вложенной
  дизъюнкцией (`∃x (A(x) ∧ (B(x) ∨ …))`, T2: `0006`, `0007`, `0008`) и одна битая
  аннотация (`0109`). Строк `unsafe_rule` не осталось.

## 4. Интерпретация и решение

Сырое gold-fed число (35/45) теперь ведёт text-fed (25/45); остаток — 6 честных
абстенций (цель T4, посылка T2, одна битая строка) и ошибки абстракции text-fed-пути.
В пересчёте на строки, которые закоммиченная процедура L2 покрывает, **gold-fed
(35/39) далеко опережает text-fed (22/39)**. Исходное измерение (17/45) и первые
числа — в истории `docs/t1_plan_ru.md` §13 и `docs/t3_plan_ru.md` §13.

Вывод: доминирующий потолок на L2-срезе остаётся **охватом (метод)**, а не языком, и
Tier-1 lowering закрыл его большую часть (T1/T3/T5: охват 27→39/45). Согласно
`docs/folio_ceilings_ru.md` §7 и `D-FE-1`/`D-FE-2`, оставшиеся пункты Tier-1 — T4
(неплоская цель) и T2 (экзистенциальная посылка с вложенной дизъюнкцией); извлечение
G1–G4 остаётся полезным на строках, которые метод уже покрывает. Разъяснение плана,
выход по пунктам и открытые решения — `docs/coverage_ceiling_ru.md`.

Оговорка: это **оценка метода, а не строгий верхний предел** — более сложная gold-
формализация может стоить дороже, чем абстракция LLM (это видно по бюджетным
промахам и согласию на `Uncertain`). Она отвечает на вопрос «метод или язык», а не
«что достижимо».

## 5. Ограничения-предохранители

- `out_of_fragment` — честная абстенция: снижает recall, но не звуковость, и
  никогда не засчитывается как верный `unknown`.
- Никогда не понижать семантику, чтобы пройти строку (`∀x (P(x) → ¬Cat(x))`,
  схлопнутое в ground `¬is_a(pet, cat)`, — это звуковый факт о неправильной цели;
  `docs/folio_ceilings_ru.md` §8).
- Никакой подгонки под конкретные id; улучшения — из общего контракта извлечения и
  именованных Tier-1 фрагментов по контракту объявленного фрагмента
  (`docs/fragment_routing_ru.md`).

# ProofWriter — заметки о коллекции

Рабочие заметки по внешнему бенчмарку eval-харнесса. Английский оригинал —
`docs/proofwriter.md`.

Источник: Tafjord, Mishra, Clark, *ProofWriter: Generating Implications, Proofs, and
Abductive Statements over Natural Language* (AI2, arXiv:2012.13048), зеркало
`tasksource/proofwriter` на Hugging Face Hub. Закоммиченная выборка —
`evals/data/proofwriter_tier_a.jsonl`; харнесс — `evals/proofwriter.py`.

## 1. Что это за бенчмарк

Синтетический бенчмарк логического вывода. Генератор строит **теорию** (короткий
текст фактов и правил) и **вопрос** (одно утверждение), и помечает элемент
`True`, `False` или `Unknown` вместе с одним или несколькими графами доказательства.

Словарь фиксирован генератором:

- **сущности** — Anne, Bob, Charlie, Dave, Erin, Fiona, Gary, Harry и
  `the cat / cow / dog / tiger / lion / bear / mouse / squirrel / rabbit / bald
  eagle`;
- **унарные свойства (атрибуты)** — nice, blue, round, rough, smart, young, big,
  cold, green, red, white, furry, quiet, kind, …;
- **бинарные отношения** — chases, eats, likes, needs, sees, visits.

Формы предложений:

- факты: `Anne is nice.` / `The cat chases the mouse.` / `Anne is not nice.`;
- правила: `All nice people are cold.` / `Rough things are white.` /
  `If someone is blue and round then they are young.` /
  `If the cat eats the cow then the cow is not nice.`

Метки:

- **True** — утверждение выводимо из теории;
- **False** — выводимо его отрицание;
- **Unknown** — не выводимо ни то, ни другое.

Есть два семантических режима: **CWA** (closed-world: недоказанное ложно) и
**OWA** (open-world: недоказанное — `Unknown`). Все id в `tasksource/proofwriter`
содержат `-OWA-`, то есть зеркало open-world. Ankyra работает в строгой дедукции,
это совпадающий режим: `Unknown` маппится в `unknown`, никогда в `no`.

## 2. Поля записи

Одна запись — это один вопрос к одной теории (одна и та же теория встречается во
многих записях, по одной на вопрос).

| Поле | Значение |
|---|---|
| `id` | `<Prefix>-OWA-D<N>-<k>`: семейство теста, глубина генерации, индекс |
| `config` | тег исходного среза (`depth-0..5`, `depth-3ext`, `NatLang`, `depth-3ext-NatLang`) |
| `theory` | текст посылок (факты + правила) |
| `question` | проверяемое утверждение |
| `answer` | `True` / `False` / `Unknown` |
| `maxD` | максимальная глубина доказательства в примере |
| `NFact`, `NRule` | число фактов / правил |
| `QDep` | глубина, на которой целевой факт сидит в графе доказательства (`0` = прямо заявлен) |
| `QLen` | длина доказательства в шагах; `null`, когда доказательства нет (как для `Unknown`) |
| `allProofs` | граф(ы) доказательства, напр. `@0: … [(triple1 OR ((triple6) -> rule6))]` |

## 3. Оси («области»)

**A. Тип вопроса — `Att` vs `Rel`.**
`Att*` спрашивает про унарный атрибут (`Harry is furry`), у Ankyra это `is_a`.
`Rel*` спрашивает про бинарное отношение (`The cat chases the mouse`) — бинарный
предикат.

**B. Отрицание в теории — `Neg` vs `Noneg`.** Измерено на validation-сплите:
теории `*Neg` содержат отрицание в 93–96% случаев (`Anne is not nice.`,
`If someone is smart and not round …`), а теории `*Noneg` свободны от отрицаний
(0%). Это свойство *теории*, а не вопроса: полярность вопроса — независимая ось,
примерно 50/50 внутри каждого семейства.

Вместе это даёт четыре семейства: `AttNoneg`, `AttNeg`, `RelNoneg`, `RelNeg`.

**C. Глубина доказательства.** `config = depth-N` — цель генерации; у
наблюдаемого `maxD` мода на `N` (напр. `depth-2` → `maxD = 2` у 8 944 из 10 094
записей; `depth-5` → `maxD = 5` у 9 200 из 10 190). `QDep ≥ 1` означает, что нужно
хотя бы одно применение правила; `depth-0` содержит и тривиальные `QDep = 0`.

**D. Язык / вариант.**
- **синтетическое ядро** (`depth-0..5`) — короткие шаблонные фразы;
- **`NatLang`** пересказывает те же задачи выдуманным естественным языком —
  `Bob has been blue because he's green with envy.`,
  `The round, rough, and green one was labeled Eric after all.` Это настоящий
  out-of-distribution вход для экстрактора (длинные составные предложения с
  отвлекающими придаточными);
- **`depth-3ext`** — расширенный depth-3 с бо́льшим числом фактов и правил (до
  16 фактов / 8 правил, `maxD` сконцентрирован на 3);
- **`depth-3ext-NatLang`** — комбинация расширенного depth-3 с формулировками
  NatLang.

## 4. Объёмы и сплиты

`tasksource/proofwriter`, subset `default`: train 585 552 / validation 85 468 /
test 174 476 записей. Харнесс использует сплит `validation`, закэшированный
локально в `evals/data/.cache/`.

Внутри validation:

- 6 368 уникальных id теорий, 54 848 уникальных пар `(id, question)`;
- число теорий по префиксу id: `AttNeg` 1 574, `AttNoneg` 1 695, `RelNeg` 1 426,
  `RelNoneg` 1 433, `AttNonegNatLang` 240;
- распределение меток: `True` 23 199, `False` 23 199, `Unknown` 39 070.

**Особенность зеркала.** Тег `config` — это исходный файл, из которого пришла
запись, и он не является чистым разбиением: `depth-3ext-NatLang` смешивает записи
core-префиксов (`AttNeg`/`AttNoneg`/`RelNeg`/`RelNoneg`) с `AttNonegNatLang`.
Надёжные оси — префикс `id` и содержимое `depth-N`/`NatLang`, а не строка
`config`.

## 5. Как это использует Ankyra

`evals/build_proofwriter_sample.py` выполняет детерминированный стратифицированный
отбор и коммитит его как JSONL, поэтому прогонам eval сеть не нужна. Текущая
закоммиченная выборка — **Tier A**: только синтетическое ядро (`config`,
совпадающий с `depth-\d+`), по три вопроса на
`(глубина ∈ {0,1,2,3,5}, метка ∈ {True,False,Unknown})`, с ротацией по четырём
семействам.

`evals/proofwriter.py` прогоняет каждую запись через весь пайплайн. Текст задачи —
это теория плюс `Is it true that <statement>?`. Семантика бенчмарка остаётся вне
движка: адаптер маппит

- `True → Answer.kind yes`,
- `False → Answer.kind no`,
- `Unknown → Answer.kind unknown`,

и инвертирует ожидаемую метку, когда экстрактор переписывает отрицательное
утверждение в положительный ask (это видно по каждому элементу как полярностный
флип). По умолчанию — строгая дедукция (`allow_hypotheses=False`); `--hypotheses`
включает абдуктивный режим, где детерминированные совпадения делятся на `proven`
и `proven_under`. Расхождения классифицируются по shape: `grounded_mismatch`
(строгое доказательство против метки — серьёзное), `hypothetical_decision`,
`question_begging`, `undecided_mismatch`.

**Политика сэмплирования.** Извлечение идёт с `ANKYRA_EXTRACT_SAMPLES=1`.
Best-of-N сэмплирование измеренно не улучшает результат (`quality_findings.md`,
C1): ранкер отбора — синтаксическая/grounding-метрика, дающая ничьи на логически
разных структурах. Провайдерская вариативность ловится перепрогоном, когда отчёт
не чистый, а не сэмплированием (см. поэтапный протокол в §6).

## 6. Статус и расширение

Строгая базовая линия на Tier A: 45/45 (30/30 детерминированных все `proven`,
15/15 `Unknown`, ложных строгих доказательств нет). Абдуктивный режим
отчитывается отдельно и не является гейтом.

### Поэтапное расширение

Этапы служат **и измерению качества, и отладке**. Они прогоняются итеративно:
прогон этапа → чтение отчёта по задачам и трасс → правки извлечения/формализации →
перепрогон. Размеры — это шаги набора уверенности; полная коллекция — финальный
прогон за гейтом.

**Протокол измерения.**
- `ANKYRA_EXTRACT_SAMPLES=1`; по умолчанию строгая дедукция; абдуктивный режим
  отчитывается отдельно и никогда не является гейтом.
- **Экономичные прогоны: этап один раз.** Перепрогон этапа — или только
  расходящейся задачи — лишь когда отчёт не чистый, чтобы отделить реальный сбой
  от провайдерской вариативности (C1). Этапы не повторяются фиксированное число
  раз; токены оплачиваются из своего кармана.
- Жёсткие инварианты на каждом прогоне: **0 grounded false proofs** (строгое
  доказательство против метки) и все детерминированные (`True`/`False`) ответы —
  `proven`. Расхождение разбирается: перепрогон для воспроизведения; если
  воспроизводится — это реальный сбой, который чиним, иначе фиксируется как
  провайдерская вариативность с частотой.

**Этапы.**

| Этап | Размер | Состав | Цель / гейт |
|---|---|---|---|
| A | 45 | core: 5 глубин × 3 метки × 3, ротация семейств | базовая линия (сделано) |
| B | 75 | A + 30 NatLang (10 теорий × 3 метки) | разведка и отладка на NatLang; гейт: 0 grounded false proofs, kind accuracy ≥ 90%, каждое падение разобрано |
| C | 150 | 75 core (5 × 3 метки × 5) + 75 NatLang (25 теорий × 3 метки) | масштабирование; гейт: 0 grounded false proofs, kind accuracy ≥ 95% |
| D | 300 | C + 150 `depth-3ext` (50 теорий × 3 метки) | вторая область; гейт: 0 grounded false proofs, kind accuracy ≥ 95%, отчёт по областям |
| E | полная | 6 368 теорий, по одному вопросу, все области (≈11 ч) | финальный прогон за гейтом; стоп на первом grounded false proof |

Этап E прогоняется один раз с таргетными перепрогонами падений. Набор всех
вопросов (54 848 элементов, ≈97 ч) — отдельное решение и по умолчанию вне объёма.

**Результаты.** Этап A: строгий 45/45 (§5). Этап B, первый прогон (`--tier b`,
`ANKYRA_EXTRACT_SAMPLES=1`): **74/75** kind accuracy — core 45/45, NatLang 29/30;
0 grounded false proofs; детерминированные 49/50 все `proven`; `Unknown` 25/25.
Единственное расхождение (`AttNonegNatLang-OWA-111`, ждали `False`, получили
`unknown`/`no_progress`) прошло на перепрогоне, то есть это провайдерская
вариативность (C1), а не воспроизводимый сбой; гейт пройден. Багов извлечения или
формализации на NatLang-области не выявлено.

Пороги и разбивки этапов C/D — это policy-ручки, а не архитектура; их можно
ужесточать по мере роста качества извлечения. Этапы B–D добавляются в
закоммиченную выборку расширением `evals/build_proofwriter_sample.py`
(спецификация отбора на этап), а итоговые гейты фиксируются в
`docs/implementation_plan.md`.

## 7. План тестирования

Объём: этапы B–E (этап A — закоммиченная базовая линия). План — это **цикл
отладки**, а не формальный скоринг: этап закрыт, только когда его отчёт зелёный
или каждое оставшееся падение категоризовано.

### 7.1 Что запускаем

Целевой CLI (требует правок билдера/харнесса из §6):

- сборка закоммиченной выборки этапа:
  `uv run --with pyarrow python -m evals.build_proofwriter_sample --tier b`
  → `evals/data/proofwriter_tier_b.jsonl` (детерминированно; `--tier c`, `--tier d`);
- прогон этапа (строгий, по умолчанию):
  `uv run python -m evals.proofwriter --tier b`
  — трассы по задачам в `evals/out/proofwriter/<id>.json`; `--hypotheses` включает
  абдуктивный режим (отчёт, но не гейт); `--limit N` для дымового прогона;
- точечный перепрогон после правки:
  `uv run python -m evals.proofwriter --tier b --ids <id1>,<id2>`;
- просмотр одной задачи: `evals.narrate` рендерит сохранённую трассу.
  **Пробел инструментов:** сейчас он читает только `evals/problems.jsonl` и
  `evals/out`, поэтому нужен `--traces-dir` (или аналог), чтобы рендерить
  ProofWriter-трассы из `evals/out/proofwriter`.

`ANKYRA_EXTRACT_SAMPLES=1` (он же по умолчанию). После появления кэша parquet сеть
не нужна.

### 7.2 Что смотрим

В отчёте прогона: общий `kind accuracy` по полярно-известным; `unknown polarity
(no target extracted)`; `polarity flips`; распределения `statuses` / `strengths` /
`shapes`; `determinate matches (proven vs proven_under)`; точность в разрезе
глубины, метки, префикса и полярности вопроса; и строка по задаче (id, config,
метка, фактический kind, статус, число волн, флип).

В трассе задачи (`evals/out/proofwriter/<id>.json`) для падения: `structure`,
`theory`, `symbolic` (проверка цитат/подстрок), `query`, `verdict` (гэпы,
связывания, неиспользованные посылки), `answer`, `explanation`, `waves`
(предложение + категория + причина), `hypotheses`, `llm_calls`.

### 7.3 Таксономия отказов и триаж

| Наблюдение | Смысл | Действие |
|---|---|---|
| `grounded_mismatch` (`proven`, неверная метка) | строгое доказательство против метки: баг формализации/движка или артефакт бенчмарка | **блок**; смотреть трассу; чинить или доказать артефакт |
| детерминированная метка, kind `unknown`, `unsupported`/`no_progress` | промах извлечения или формализации | чинить промпт / Фазу 0 |
| `unknown polarity (no target extracted)` | запрос не выразился в словаре теории | чинить извлечение вопроса / словарь |
| `polarity_flip` | экстрактор переписал отрицательное утверждение в положительный ask | проверить корректность; сам по себе не ошибка |
| `contradiction` | противоречие дошло до цели | смотреть; часто избыточное отрицание |
| `budget` | исчерпан `max_waves` | смотреть; может быть `insufficient`, а не багом |
| `hypothetical_decision` | только абдуктивный режим | информационно |
| `question_begging` | гипотеза переформулировала цель | должна была быть отклонена; если видно — баг |

Правило триажа (экономное): перепрогнать падающую задачу один раз. Если
воспроизводится — это реальный сбой, ему назначается корневая причина:
извлечение / билдер / движок / бенчмарк. Если не воспроизводится — фиксируется как
провайдерская вариативность (C1) с частотой.

### 7.4 Цикл правок и критерий выхода

На этап:

1. прогнать этап один раз;
2. прочитать отчёт, выписать падения с их shape, провести триаж;
3. перепрогнать каждое падение один раз, чтобы отделить реальные сбои от шума C1;
4. чинить реальные — минимальный диф, общие решения; без спецкейсов под
   формулировки бенчмарка (`docs/task.md` §3.8);
5. перепрогнать исправленные через `--ids`; когда накопился батч правок —
   прогнать этап целиком ещё раз;
6. проверить гейт.

**Зелёный** этап: 0 grounded false proofs; все детерминированные ответы `proven`;
kind accuracy ≥ порога этапа (B 90%, C/D 95%); каждое оставшееся падение
категоризовано (исправлено или задокументировано как артефакт бенчмарка /
провайдерская вариативность).

### 7.5 Гигиена стоимости

- этап прогоняется **один раз**; отдельные задачи — через `--ids`;
- трассы кэшируются в `evals/out/proofwriter` (gitignore) — перечитывать, не
  перезапускать;
- этап E прогоняется один раз с точечными перепрогонами падений;
- везде `SAMPLES=1`.

### 7.6 Результаты

После каждого этапа: обновить таблицу этапов в §6 измеренными числами; записать
находки в `docs/quality_findings.md` (раздел E); на каждую правку добавить или
расширить тесты; по любому незакрытому вопросу завести именованную находку в
`docs/implementation_plan.md`.
